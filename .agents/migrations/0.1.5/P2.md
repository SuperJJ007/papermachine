## P2.1 implementation entry points

The approved plan and research reports A §5.1 and B §3/§5 own scope. The imported implementations remain available at `7c1bc3df52`; upstream process ownership must be preserved when adapting them.

| Capability | Current target entry points | Required adaptation |
| --- | --- | --- |
| Target environment | subprocess/types.ts; subprocess-local/spawn.ts childEnv; subprocess-local/runner-launch.ts targetEnvironment; subprocess-e2b/process.ts prepareState | Restore explicit environmentBase across every target launch path. An empty target environment receives only explicit entries, including any deliberately supplied proxies. The scrubbed-parent path retains proxyEnvironmentForChild normalization. Provider control processes retain their own transport environment. |
| Cooperative interruption | subprocess/types.ts; subprocess-local/managed-owner.ts BoundProcessOwner; subprocess-local/spawn.ts bindManagedProcess; platform and E2B owners | Keep target identity private. Add cooperative signaling through the owner; preserve termination escalation and waitForExit quiescence. Do not map interrupt to terminate. |
| Execution world | subprocess Service Definition and local/E2B providers; Science runtime admission | Restore provider-declared host-local/remote identity and reject unsupported Science execution before filesystem observation. |
| Output validity | collected output implementations and Science interpreter observation | Restore incremental UTF-8 validity without treating decoding replacement characters as sufficient evidence. |
| Windows confinement | win32-process spawnInheritedJobProcess; sandbox-windows-acl | Verify the upstream primitive on Windows before choosing the console-initialization patch. No Windows verification has been performed in this phase. |

The ordinary local spawn calls childEnv directly, while managed runners materialize targetEnvironment separately. E2B serializes a remote ambient environment into a target environment file and separately builds controlEnvs. All three paths need the explicit target-base choice; changing only the ordinary spawn would leave managed runners or remote targets inheriting ambient values.

BoundProcessOwner.signal currently accepts only SIGTERM/SIGKILL. Cooperative interruption must account for platform owners and target-start timing, not just add a public handle closure.

## Required evidence

Focused provider tests must cover inherited versus empty environments with an active proxy, explicit overrides and tombstones, Windows case-insensitive names, and control/target separation. Interruption tests must prove continued execution after a handled interrupt and quiescent termination afterward. Windows primitive verification remains separate from POSIX tests. Full P2 acceptance also requires the plan's Science unit coverage, real Conda acceptance, and an artifact-producing science-headless run; none is claimed by this preparation checkpoint.
