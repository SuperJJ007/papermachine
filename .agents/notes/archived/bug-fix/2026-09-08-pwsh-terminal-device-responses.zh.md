# Agent Note: 发送设置命令前回答 PowerShell 终端设备查询

Status: implemented
Archived: 2026-09-10

[English](2026-09-08-pwsh-terminal-device-responses.md) | 中文

## Problem

PowerShell 交互宿主通过 `ESC[6n` 查询光标位置，并等待终端响应。丢弃该序列会使 shell 阻塞。在交换完成前发送提示符设置，也会把命令输入混入宿主等待的响应。搜索 `dsh> ` 子串进一步放大了问题：即使命令尚未执行，设置命令的回显也包含该文本。

## Decision

每个本地 PTY 会话拥有一个采用已配置尺寸、零滚动历史的 `@xterm/headless` 终端。原始输出推进这个持续维护的模拟器，其协议响应通过子进程终端写回。现有清理器和有界逐行缓冲区继续负责提示符标记及模型输出。终端拆卸前释放模拟器；响应写入失败走与其他写入相同的传输失败路径。

PowerShell 启动先等待初始 shell 就绪，再发送一次编码和提示符设置。后续等待要求完整的受控提示符行，并共用一个已配置的截止时间。回显的函数定义不能使启动完成。

## Alternatives considered

固定的光标位置响应虽能解除部分宿主的阻塞，却会在光标移动后报告错误坐标。把清理器扩展成光标模拟器会重复实现已有维护者的终端协议代码。延长静默时间或测试超时无法回答宿主正在等待的查询。

## Consequences

真实 PTY 和真实 Loader 组合覆盖 PowerShell 命令执行、持久状态及 UTF-8 输出。拆分的光标查询、光标移动、响应写入失败、设置命令回显和启动超时都有确定性覆盖。新增模拟器只保存有界屏幕，不会将逐行转录变成全屏终端 UI。
