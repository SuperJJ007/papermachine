# Agent Note: dsh-v0.1.1-rc.2 upstream merge

Status: implemented

English | [中文](2026-08-22-dsh-v0.1.1-rc.2-merge.zh.md)

## Problem

The Science fork's `main` had diverged from `deepseek-ai/deepseek-harness` by 129 commits while upstream shipped its own `dsh-v0.1.1-rc.2` release (129 commits: attachment-image normalization, a per-namespace settings describe-mirror, `session-projection` checkpoint/watermark support, a client bundle-purity build gate, several new `ui-*` client packages). Landing that release required resolving roughly 3,300 changed paths, of which ~120 carried real conflicts, and then re-expressing every Science capability the conflicting files carried on top of upstream's new shapes.

## Decision

`main` now contains `dsh-v0.1.1-rc.2` merged in (merge commit, upstream as second parent), followed by focused adaptation and doc-sync-fix commits. Conflict resolution followed one rule per file category: generated docs (`docs/module-graph.md`, `docs/config-catalog.md`, `docs/event-producer-consumer.md`, the `gen-cordis-catalog.ts` regions in `docs/subsystems/*`) took upstream's side and were regenerated afterward so Science re-enters them; `.i18n.yaml` pairing records were never hand-merged, only regenerated via `pnpm run verify-translation-pairing --write`; hand-written docs and READMEs merged both sides' prose, preserving Science content under upstream's structure; `packages/attachment/*` re-expressed Science's `saveText`/`readText`/`textLimits` capability on top of upstream's new normalization pipeline (`prepareImageFile`/`admitEncodedImages`/`RequestImageAttachment`) rather than reverting it.

Six upstream-API adaptations followed the merge, each tied to a shape upstream changed underneath a Science or shared registration:

- `packages/session/session-projection/src/index.ts`: `register()`'s erased-definition construction assigned `undefined` directly to `checkpointStateSchema`/`checkpointStateSeq`/`viewChanged`, three fields declared optional (`foo?: T`) rather than `foo: T | undefined`; under `exactOptionalPropertyTypes` this fails to typecheck. The fix omits the key via conditional object spread when the caller didn't supply one, and calls each through `definition.foo(...)` at the use site (never extracted to a bare local) with a function-type assertion narrowing the closure — extracting the method-shorthand property to a local trips oxlint's `unbound-method` rule, and a non-null assertion on the call trips `no-non-null-assertion`.
- `packages/host/apiproxy/src/api-proxy.ts`, `packages/science/science-session/src/index.ts`: two `sessionProjections.register()` calls (the host's `textLimits` projection, Science's own `science` projection) still used the pre-merge `ProjectionDefinition` shape — a top-level `schema`/`view` pair — instead of the merged `stateSchema` plus `wire: { viewSchema, view }`. Fixed to match the already-correct `imageLimits` registration beside `textLimits`.
- `packages/client/ui-conversation`: upstream's attachment-UI refactor (`refactor(client): make attachment UI a client plugin`) dropped `loadImage` from `ChatNodeOwnerProps`, orphaning `ui-tool`'s pre-existing `ToolCallOwnerProps.loadImage` wiring that Science's `annotate_artifact`/`run_python`/`run_r` toolview rows read images through. Added `loadImage` back to `ChatNodeOwnerProps` and threaded it through `ChatNodeSeat`/`ChatView`.
- `packages/client/ui-attachment`: the same refactor stopped exporting `MessageImage`/`ImageGallery`/`ImageLightbox`/`ImageLoader`/`MessageImageLabels` as package values (`src/index.ts` is now a Node-only stub; the browser components only exist through the `client/index.ts` plugin's own relative imports) — Science's `ArtifactContent`/`ScienceArtifactRow`/`ScienceDetailsView`/`ScienceOutcomeRow`/`science-attachment-loader.ts` render images outside the chat-message flow that plugin fills, so they need the components directly, not through `conversation.message.images`. Re-exported them from the `/client` subpath (browser-only, matching this repo's `/client`-subpath convention for other packages) and switched Science's imports there.
- `packages/client/ui-science/package.json`: the client bundle-purity build gate upstream added (`dsh-client-bundle-purity` in `packages/client/tsdown.client.ts`) forbids one client plugin's bundle from statically importing another's value exports; it names `dsh.client.external` as the declared escape hatch. Declared `@deepseek-ai/dsh-client-ui-attachment/client` there (plus `@deepseek-ai/dsh-client-ui-attachment` in `dsh.client.inject`, mirroring the package's other structural dependencies) so `pnpm run build` succeeds.
- `packages/core/agent-loop/README.md`/`.zh.md`, `packages/science/science-runtime/README.md`/`.zh.md`: neither heading upstream's or Science's new cross-reference points at (`Loop lifecycle (agent.ts)`, `Settings-bound entry`) carried the explicit `<a id="...">` anchor this repo's bilingual pairing rule requires — a cross-referenced fragment must stay byte-identical across the `.md`/`.zh.md` pair (`docs/i18n/README.md`), so a Chinese heading's own auto-slug can never be the target; only an explicit anchor using the English slug satisfies both files (the established pattern: `packages/core/agent/README.zh.md`'s `#initiating-agent-scope`). Added the missing anchors to both language sides of both files instead of translating the link fragments.

## Testing

`pnpm run typecheck`, `pnpm run lint`, and `pnpm run build` (client bundle-purity gate included) all pass clean. `pnpm exec vitest run packages/science packages/attachment --no-file-parallelism`: 525/526 pass, 1 skipped; the one failure (`annotate.spec.ts`'s "curates an exact named version in place, leaving every other version untouched") is byte-identical to the pre-merge fork tip in every file it touches (`harness.ts`, `capture.ts`, `fold-state.ts`, `transition.ts`, the test itself) — `harness.ts`'s shared `authorizeToolCall` hardcodes `turn: 1` for every call, so `scienceRunsShareTurn` always reports the same turn and `captureRunArtifacts` supersedes in place instead of opening a second version; a pre-existing fork bug, not a merge regression. `packages/session/session-projection/tests/registry.spec.ts` has two further pre-existing failures under the same byte-identical-to-pre-merge test: a checkpoint row admitted without `checkpointStateSchema` lets a malformed wire view throw out of `viewCheckpoint()`/`restore()` instead of being treated as unusable, and a host-only unit's `viewChanged` can never reach `onChanged` because host-only units never publish to the change feed at all (a design fact an earlier test in the same file already asserts) — neither is caused by this merge or its adaptations. `pnpm run test:snapshot` passes except 3 pre-existing failures in `examples/acp-agent/tests/{acp,goal}.snapshot.ts` (upstream's own tests, unrelated to Science): they assert empty `stderr` but this Node (v24.14) emits an `ExperimentalWarning: SQLite` line these particular spawns don't pass `--disable-warning=ExperimentalWarning` for, a pattern several other spawns in the same suite already carry.

`pnpm run doc-sync` passes except two accepted-debt gates: `verify-translation-pairing`'s corpus-wide check reports `docs/config-catalog.md`/`docs/module-graph.md` as structurally diverged from their `.zh.md` pair (new Science config entries only the English generator produces; neither generator has a Chinese counterpart) alongside a large pre-existing set of Science evidence-doc and Agent Note `.zh.md` pairs from before this merge with the same kind of drift, and `verify-agent-note-format` reports the untracked `2026-08-22-science-artifact-domain-and-image-edit.md` from an unrelated, in-progress workstream this merge did not touch.

## Alternatives considered

- **Hand-translate `docs/config-catalog.zh.md`/`docs/module-graph.zh.md` to close the pairing gate.** Rejected: both are generated files with no Chinese-producing generator; a hand translation would immediately go stale on the next regeneration and there is no mechanism to keep it current. The merge policy this note implements calls for reporting this debt, not hand-translating catalogs.
- **Leave `packages/attachment` on the fork's pre-merge admission path instead of upstream's normalization pipeline.** Rejected: upstream's architecture (content-addressed storage, pass-through when the source already satisfies the normalized format, sharp re-encoding otherwise) is the one this fork now inherits; reverting it would fork the storage layer permanently. Byte-exact admission for eligible sources (no metadata, no animation, already-normalized color depth/space, within size caps) is preserved through the pass-through path — the common case for Science's captured plots — and the auto-capture snapshot fixture whose fake PNG carries grayscale+alpha color (pass-through-ineligible) documents the one case where normalization changes stored bytes.
- **Route Science's image rendering through `ui-conversation`'s `conversation.message.images` slot instead of re-exporting `ui-attachment`'s components.** Rejected: that slot's owner contract is shaped for a chat message's image list; Science's artifact panel, details view, and transcript rows are not chat messages and need the presentational atoms (`MessageImage`, `ImageLightbox`) directly.

## Consequences

Science inherits upstream's attachment-normalization architecture, settings describe-mirror, and client bundle-purity gate going forward, at the cost of the documented pairing debt on two generated catalogs and the pre-existing bugs this merge surfaced (by finally running the tests that reach them) but did not introduce. `ui-attachment`'s `/client` subpath is now a second, deliberate public surface (components, not just the Cordis plugin `apply`) that any future refactor of that package must keep in mind.
