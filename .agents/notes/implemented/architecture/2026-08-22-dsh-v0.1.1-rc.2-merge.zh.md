# Agent Note: dsh-v0.1.1-rc.2 upstream merge

Status: implemented

[English](2026-08-22-dsh-v0.1.1-rc.2-merge.md) | 中文

## Problem

Science fork的 `main` 已相对 `deepseek-ai/deepseek-harness` 分叉出 129 个提交，同时上游发布了自己的 `dsh-v0.1.1-rc.2` 版本（129 个提交：附件图片归一化、按命名空间的 settings describe-mirror、`session-projection` 的 checkpoint/watermark 支持、client bundle-purity 构建门禁，以及若干新的 `ui-*` client 包）。合入该发布版本需要处理约 3,300 条变更路径，其中约 120 条存在真实冲突，随后还需在 upstream 新形状之上重新表达每一个冲突文件所携带的 Science 能力。

## Decision

`main` 现已合入 `dsh-v0.1.1-rc.2`（合并提交，upstream 作为第二父提交），随后是若干聚焦的适配提交与 doc-sync 修复提交。冲突解决按文件类别各遵循一条规则：生成式文档（`docs/module-graph.md`、`docs/config-catalog.md`、`docs/event-producer-consumer.md`、`docs/subsystems/*` 中 `gen-cordis-catalog.ts` 生成的区域）取 upstream 一侧，随后重新生成以便 Science 重新进入；`.i18n.yaml` 配对记录从不手工合并，只通过 `pnpm run verify-translation-pairing --write` 重新生成；手写文档与 README 合并两侧文字，在 upstream 结构之上保留 Science 内容；`packages/attachment/*` 在 upstream 新的归一化管线（`prepareImageFile`/`admitEncodedImages`/`RequestImageAttachment`）之上重新表达 Science 的 `saveText`/`readText`/`textLimits` 能力，而非回退它。

合并之后进行了六项 upstream API 适配，每一项都对应 upstream 在某个 Science 或共享注册点之下改变的形状：

- `packages/session/session-projection/src/index.ts`：`register()` 构造 erased definition 时直接把 `undefined` 赋给 `checkpointStateSchema`/`checkpointStateSeq`/`viewChanged` 三个字段，而这三者声明为可选（`foo?: T`）而非 `foo: T | undefined`；在 `exactOptionalPropertyTypes` 下无法通过类型检查。修复方式是：调用方未提供时通过条件对象展开省略该键；并在使用点通过 `definition.foo(...)` 调用（绝不提取为裸局部变量），配合函数类型断言来收窄闭包——把 method-shorthand 属性提取为局部变量会触发 oxlint 的 `unbound-method` 规则，在调用处使用非空断言则会触发 `no-non-null-assertion`。
- `packages/host/apiproxy/src/api-proxy.ts`、`packages/science/science-session/src/index.ts`：两处 `sessionProjections.register()` 调用（host 的 `textLimits` projection、Science 自身的 `science` projection）仍使用合并前的 `ProjectionDefinition` 形状——顶层 `schema`/`view` 字段对——而非合并后的 `stateSchema` 加 `wire: { viewSchema, view }`。已修复为与旁边已经正确的 `imageLimits` 注册一致。
- `packages/client/ui-conversation`：upstream 的附件 UI 重构（`refactor(client): make attachment UI a client plugin`）从 `ChatNodeOwnerProps` 中去掉了 `loadImage`，使 `ui-tool` 原有的 `ToolCallOwnerProps.loadImage` 接线失去来源——Science 的 `annotate_artifact`/`run_python`/`run_r` toolview 行正是通过它读取图片。已把 `loadImage` 加回 `ChatNodeOwnerProps`，并贯穿 `ChatNodeSeat`/`ChatView` 传递。
- `packages/client/ui-attachment`：同一次重构不再把 `MessageImage`/`ImageGallery`/`ImageLightbox`/`ImageLoader`/`MessageImageLabels` 作为包值导出（`src/index.ts` 现在只是一个 Node-only 空壳；浏览器组件只通过 `client/index.ts` 插件自身的相对导入存在）——Science 的 `ArtifactContent`/`ScienceArtifactRow`/`ScienceDetailsView`/`ScienceOutcomeRow`/`science-attachment-loader.ts` 在该插件覆盖的聊天消息流之外渲染图片，因此需要直接拿到这些组件，而不是经由 `conversation.message.images`。已把它们从 `/client` 子路径重新导出（浏览器专属，符合本仓库其他包的 `/client` 子路径约定），并把 Science 的导入切到该处。
- `packages/client/ui-science/package.json`：upstream 新增的 client bundle-purity 构建门禁（`packages/client/tsdown.client.ts` 中的 `dsh-client-bundle-purity`）禁止一个 client 插件的 bundle 静态导入另一个插件的值导出；它把 `dsh.client.external` 列为声明的逃生口。已在其中声明 `@deepseek-ai/dsh-client-ui-attachment/client`（并在 `dsh.client.inject` 中加入 `@deepseek-ai/dsh-client-ui-attachment`，与该包其余结构性依赖保持一致），使 `pnpm run build` 通过。
- `packages/core/agent-loop/README.md`/`.zh.md`、`packages/science/science-runtime/README.md`/`.zh.md`：upstream 与 Science 新增的两个跨文件引用所指向的标题（`Loop lifecycle (agent.ts)`、`Settings-bound entry`）都没有携带本仓库双语配对规则要求的显式 `<a id="...">` 锚点——被跨文件引用的 fragment 必须在 `.md`/`.zh.md` 配对之间保持逐字节一致（`docs/i18n/README.md`），因此中文标题自身的自动 slug 永远不能作为目标；只有使用英文 slug 的显式锚点才能同时满足两侧文件（已有先例：`packages/core/agent/README.zh.md` 的 `#initiating-agent-scope`）。已在两个文件的两种语言版本中都补上缺失的锚点，而不是去翻译链接 fragment。

## Testing

`pnpm run typecheck`、`pnpm run lint` 与 `pnpm run build`（含 client bundle-purity 门禁）均干净通过。`pnpm exec vitest run packages/science packages/attachment --no-file-parallelism`：525/526 通过、2 跳过；唯一失败（`annotate.spec.ts` 的 "curates an exact named version in place, leaving every other version untouched"）在其涉及的每个文件（`harness.ts`、`capture.ts`、`fold-state.ts`、`transition.ts`、测试文件本身）上都与合并前的 fork tip 逐字节一致——`harness.ts` 共享的 `authorizeToolCall` 对每次调用都硬编码 `turn: 1`，导致 `scienceRunsShareTurn` 始终判定同一 turn，`captureRunArtifacts` 因而原地替换而非开出第二个版本；这是一个先于本次合并存在的 fork bug，不是合并回归。`packages/session/session-projection/tests/registry.spec.ts` 还有另外两个先于合并存在的失败，同样出现在与合并前逐字节一致的测试上：未提供 `checkpointStateSchema` 的 checkpoint 行被接纳后，格式错误的 wire view 会从 `viewCheckpoint()`/`restore()` 中直接抛出，而不是被当作不可用的行处理；一个 host-only 单元的 `viewChanged` 永远无法触达 `onChanged`，因为 host-only 单元根本不会向变更流发布（同一文件中更早的一个测试已经断言了这一设计事实）——两者都不是本次合并造成的。`pnpm run test:snapshot` 通过，除了 `examples/acp-agent/tests/{acp,goal}.snapshot.ts` 中 3 个先于合并存在的失败（upstream 自己的测试，与 Science 无关）：它们断言 `stderr` 为空，但当前 Node（v24.14）会打印一行 `ExperimentalWarning: SQLite`，这几处 spawn 调用没有像同一测试套件里其他几处那样传 `--disable-warning=ExperimentalWarning`。

`pnpm run doc-sync` 通过，除两项已接受的欠账门禁：`verify-translation-pairing` 的全量检查报告 `docs/config-catalog.md`/`docs/module-graph.md` 与其 `.zh.md` 配对存在结构性偏离（只有英文生成器产出了新的 Science config 条目；两个生成器都没有中文对应物），并与本次合并之前就存在的一大批 Science evidence 文档与 Agent Note 的 `.zh.md` 配对（存在同类漂移）并列；以及 `verify-agent-note-format` 报告未跟踪的 `2026-08-22-science-artifact-domain-and-image-edit.md`——它属于本次合并未触及的另一条独立在途工作线。

## Alternatives considered

- **手工翻译 `docs/config-catalog.zh.md`/`docs/module-graph.zh.md` 以关闭配对门禁。** 否决：两者都是生成文件，没有产出中文版的生成器；手工翻译会在下次重新生成后立刻过期，也没有机制保持其时效。本 Note 所实现的合并策略要求上报这类欠账，而非手工翻译目录类文档。
- **让 `packages/attachment` 停留在 fork 合并前的准入路径上，而不是 upstream 的归一化管线。** 否决：upstream 的架构（content-addressed 存储、源数据已满足归一化格式时走 pass-through、否则由 sharp 重新编码）正是本 fork 现在继承的架构；回退它将永久分叉存储层。对符合条件的源（无元数据、非动图、色深/色彩空间已归一化、在体积上限内）而言，逐字节准入通过 pass-through 路径得以保留——这正是 Science 已捕获图表的常见情形；auto-capture 快照 fixture 中携带灰度+alpha 色彩（不符合 pass-through 条件）的伪造 PNG，恰好记录了归一化会改变已存字节数的那一种情形。
- **让 Science 的图片渲染改走 `ui-conversation` 的 `conversation.message.images` slot，而不是重新导出 `ui-attachment` 的组件。** 否决：该 slot 的 owner 契约是为聊天消息的图片列表设计的；Science 的 artifact 面板、详情视图与转录行都不是聊天消息，需要直接使用呈现原子组件（`MessageImage`、`ImageLightbox`）。

## Consequences

Science 从此继承 upstream 的附件归一化架构、settings describe-mirror 与 client bundle-purity 门禁，代价是两个生成目录上已记录的配对欠账，以及本次合并（通过终于运行到达它们的测试）揭示、但并非由它引入的若干先存 bug。`ui-attachment` 的 `/client` 子路径现在是第二个、有意为之的公开表面（组件，而不只是 Cordis 插件的 `apply`），未来对该包的任何重构都需要留意这一点。
