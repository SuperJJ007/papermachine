# Agent Note: Project artifact store — S2 runtime wiring

Status: implemented

English | [中文](2026-08-26-project-artifact-store-s2.zh.md)

## Problem

[S1](2026-08-26-project-artifact-store-s1.md) shipped `@deepseek-ai/dsh-science-artifact-store` as a standalone package with no consumer: `science-session`, `science-runtime`, and `tool-science` still embedded a complete attachment reference in `science/artifact-saved` and read/wrote bytes through the session-scoped attachment store. [S0](../../proposed/architecture/2026-08-25-project-artifact-store.md) specifies S2 as the slice that wires the store into the runtime — capture, curation, run inputs, artifact-viewer edits — and slims the durable event to store references. S0 stays `proposed` until S3 also ships.

## Decision

**Event slimming and fold rework.** `science/artifact-saved`'s base fields become `{artifactId, logicalName, version, title, caption?, projectId, versionId, sha256, mediaType, byteCount, environmentRevision, environmentFingerprint, createdAt}` plus the existing run/human-edit variant fields; `width`/`height`/attachment name are gone (the store does not record them). The old embedded-attachment value is rejected outright (pre-release stance, no shim). The strict fold (`transition.ts`) drops automatic same-turn content supersede: session `version` is now identical to the store's own per-artifact `ordinal`, so changed content always opens the next version. Only a model curation (`annotate_artifact`) may still supersede a version in place, and only as a metadata-only change — it must retain the superseded version's `versionId`/`sha256`/`mediaType`/`byteCount` verbatim, checked by the fold. One session's artifacts must share one `projectId` (`state.artifacts[0].projectId`), and a `versionId` cannot back two committed versions in one session. `SCIENCE_PROJECTION_STATE_VERSION` moved 9→10 for this shape change. `scienceRunsShareTurn` (the removed same-turn-supersede helper) is deleted from fold-state/fold/index exports.

**Project resolution.** `ScienceRuntime.sessionProject(session)` opens (and WeakMap-caches per live `Session`) the project at `session.header.cwd` via the store's `openProject`; a session with no `cwd` fails loud with a new `PROJECT_UNAVAILABLE` error code. Resolution happens eagerly in `bindEnvironment` and `startRun`, so a Science session without a workspace directory fails at the first Science operation, not silently later.

**Capture → store.** `capture.ts` hashes each eligible file locally, skips a byte-identical rerun (dedup by sha256, independent of turn), then calls `store.createArtifact`/`store.appendVersion` before appending the reference event — the store row commits first, so a vetoed event append leaves an orphaned but harmless store version (documented, not garbage-collected). `annotateVersion` runs before the superseding event for the same reason; the store cannot clear a caption (no explicit-null in `AnnotateVersionInput`), so the fold's retained value stays authority over a cleared caption. Run inputs (`prepareRunArtifacts`) read exact prior versions via `store.readBlob(projectId, sha256)` with byte caps on `byteCount`.

**Artifact-viewer edits.** `commitStyleEdit` appends a human-edit version directly through `store.appendVersion`. `ScienceEditService.submit` becomes async: a `normalized-region` target reads the target version's blob from the store and mints a session-message image via `attachments.saveImage` (model-visible ⟺ logged), keyed and deduped by `String(versionId)` so repeated region targets against one version share one minted image (a behavior change from one image per region target). The edit-service Cordis entry injects `['attachments', 'scienceArtifactStore']`.

**Presentation and client projection.** `ScienceArtifactPresentation` moves to `version: 2`: each item's `attachment` field becomes `content: {versionId, mediaType, byteCount}`. `get_science_state`'s model-visible state keeps `mediaType`/`bytes`, drops `width`/`height`, and never exposes `versionId`/`sha256`/`projectId` — those stay Host-internal, resolved only by whatever reads the durable event directly. The client projection's artifact entries carry `versionId`/`sha256`/`mediaType`/`byteCount` (no `projectId`; browser reads stay session-addressed) — `projection-schema.ts` validates the new shape.

**Attachment extractor removed.** `science-session` no longer registers a `ctx.sessionAttachments` extractor for `science/artifact-saved`; `session-attachment-index/src/policy.ts` reclassifies it `attachment-free`. Session export therefore no longer collects Science artifact bytes — deliberate, since the project store now owns them and outlives the session. Two suites that used `science/artifact-saved` as a stand-in "real extractor-required event type" (`dsh-host-apiproxy`'s `api-proxy-models.spec.ts` and `session-export.spec.ts`) now declare their own test-local `SessionEventMap`/`SessionAttachmentExtractorMap` augmentation instead, mirroring the pattern `session-attachment-index`'s own suite already used (no production domain registers an extractor today).

**Id reconciliation.** The store's `/ids` subpath (`@deepseek-ai/dsh-science-artifact-store/ids`, node-free) is the one id space: `science-session` re-exports `ProjectId`/`ArtifactId`/`VersionId` as `ScienceProjectId`/`ScienceArtifactId`/`ScienceVersionId`, deleting its own prior `ScienceArtifactId` brand.

**Compositions.** `@deepseek-ai/dsh-science-artifact-store` mounts wherever `@deepseek-ai/dsh-science-runtime` does — `packages/bundle/web-app/cordis.patch.yml` (before the `science-runtime` row) and `examples/headless-agent/science-tools.cordis.snapshot.yml` (beside `attachment-local`, still needed for edit-message image minting) — with `dshHome` left unconfigured in the Web bundle so it follows the same `$DSH_HOME` default `science-runtime`'s own row already relies on, and pinned to the snapshot's scratch root in the headless example, matching its sibling rows.

**presetId generalization (rider).** `ScienceModeRef.presetId` widens from the literal type `'science'` to `string`, and `codec.ts`'s schema from `z.literal('science')` to a bounded non-empty string — the field now records whichever preset actually bound Science mode rather than repeating a hardcoded literal in four places. `science-session/src/ids.ts` exports one named `SCIENCE_PRESET_ID` constant; `applicability.ts`'s admission check becomes self-consistent — the first `science/mode-bound` event must record `SCIENCE_PRESET_ID` and match the currently resolved preset (a shallow, untyped read of `event.data.mode.presetId`, mirroring how this package's invariant already reads `event.data.agentPreset` off a raw `agent-preset/selected` event before strict decode), and every later Science event must find the resolved preset still equal to `state.mode.presetId` — instead of repeating `preset !== 'science'`. `dsh-tool-science`'s `isScienceSession` and `ensureScienceBound` reference the same constant and record the actually-resolved preset id. Behavior is unchanged today (only `'science'` passes either check); the rider is a foundation, not a feature — recognizing a *different* preset id as Science-family (a genuinely distinct discipline preset, or a copy of this one) needs a preset-metadata mechanism this package does not yet consult, so `apps/cli/config/agent-presets/science/preset.yml` keeps `copyable: false` and `packages/preset/agent-presets/src/metadata.ts`'s `PresetMetadata.copyable` JSDoc now states that reason precisely.

## Alternatives considered

**Keep the fold's same-turn auto-supersede rule** and reconcile it against the store's per-artifact ordinal — rejected: the store has no concept of "turn," so preserving that rule would require session-side bookkeeping the store's own `ordinal` can't corroborate on replay from a second session (S3), where a different session's own turn numbering is meaningless. Session `version` ≡ store `ordinal` is strictly simpler and is what S3's cross-session append needs anyway.

**Full preset-metadata "family" recognition now** (a new `PresetMetadata` field an arbitrary discipline preset sets to opt into the Science domain) — rejected for this rider: it would make the strict fold depend on live, mutable preset configuration that can differ across deployments and versions, breaking the "replay is a pure function of the event log" invariant unless the decision is captured durably at bind time — which is a real design (a Host-side pre-commit lookup that stamps a durable "family" fact, matching the store-reference validation pattern already used for artifact events), not yet reviewed. Landing only the string-widening and self-consistency check keeps today's behavior identical while removing the scattered literal, without inventing unreviewed cross-package schema.

**Session export re-targeting the project store by checksum** (keep collecting Science artifact bytes into the exported ZIP) — rejected: it would need read access to whichever project store owns the bytes, entangling session export with a second store; the S0 note already scopes artifact export/import as a project-level S3/S4 decision.

## Consequences

Session export no longer includes Science artifact bytes; an export/import story for artifacts is a project-level decision deferred to S3/S4. `packages/client/ui-science` (`ArtifactContent.tsx`, `ScienceDetailsView.tsx`, `ScienceOutcomeRow.tsx`, `ScienceTurnArtifacts.tsx`) and its test suite still read the removed `attachment` field and `session.readAttachment` — they do not compile under `tsconfig.client.json`, and artifact viewing is functionally dark in the shipped Web UI until S4 adds a store-read RPC (a Typert `sessions.scienceArtifact({sessionId, versionId})`-shaped route was the S1/S2 handoffs' working suggestion, authorized by folding the session log, bytes via `store.readBlob(projectId-from-fold, sha256)`). `apps/web/tests/science-chart-outcome.e2e.ts` and `science-preset.snapshot.ts`'s UI-facing assertions are updated to the new event/presentation shapes but exercise that same dark path; they are not run as evidence of S2 (browser read wiring is S4's). `dsh-attachment-local` is now an unused devDependency of `science-runtime` (kept for now; drop when convenient, knip will flag it). `science-session`'s and `tool-science`'s package READMEs still carry some pre-S2 fold-mechanics prose (durable-vocabulary and strict-fold sections) written for the embedded-attachment model that this slice did not fully rewrite line-by-line; the composition, config-requirement, and mechanism-level paragraphs this slice touches directly (attachment extractor removal, `commitStyleEdit`/`submit` wiring, artifact-saved's field list) are current. Neither the TypeScript SDK (`examples/jsonrpc-agent/tests/snapshots/`) nor the Python SDK (`scripts/snapshots/python-sdk-single-exe/`) carries a Science scenario, so this slice's schema wave needed no SDK expected-output changes — confirmed by an executed keyless refresh of the TypeScript SDK snapshot (zero diff) and a static search of the Python SDK's own source, tests, and snapshot corpus (zero references); `python/sdk-runtime/package.json` gains the new `dsh-science-artifact-store` workspace dependency alongside its existing `dsh-science-runtime`/`dsh-science-session` entries for parity with its sibling `dsh-sandbox-local`/`dsh-subprocess-local` rows.
