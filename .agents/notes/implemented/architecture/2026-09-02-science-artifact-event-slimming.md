# Agent Note: `science/artifact-saved` event slimming and the store-is-authority fold

Status: implemented

English | [中文](2026-09-02-science-artifact-event-slimming.zh.md)

## Problem

[T1](2026-09-01-project-artifact-store-schema-v2.md) made the project artifact store's write transaction the sole authority for a version's provenance — content origin, producer, base version, and creation time all live only in the store now. `science/artifact-saved` still carried a full second copy of that provenance (`producerSessionId`, `runId`, `toolCallId`, `requestHeaderSeq`, `environmentRevision`, `environmentFingerprint`, `parent`, `origin`, `byteCount`, `mediaType`, `chart`, `createdAt`), and the strict fold (`transition.ts`) still re-derived and cross-checked all of it against the session's own run/tool-call/environment history — the exact two-homes-for-one-fact shape the audit that motivated T1 (D1–D14) diagnosed. This package needed to slim the event to what the design's authority rule actually leaves it: a store reference plus the presentation snapshot the model or user saw, and rewrite the fold to match.

## Decision

**The event keeps exactly `artifactId`, `versionId`, `version`, `logicalName`, `sha256`, `title`, `caption?`, `projectId`, and a new `seenAt`.** `sha256` stays as a content pin — proof of the exact bytes the model or user saw, independent of trusting the store — and `title`/`caption` are the presentation snapshot at commit time, not the store's current value (a later metadata edit can change the store's `version_annotations` without this event changing). `seenAt` replaces `createdAt`: this event's own commit time is when the model/user *saw* this presentation, not when the store committed the content, and the old name conflated the two. `logicalName` stays because it appears in model requests (tool receipts, `get_science_state`); nothing else does. `ScienceArtifactVersion` and `ScienceClientArtifactVersion` collapse from a `{run, human-edit}` discriminated union (keyed on the now-removed `origin` field) to one flat interface — there is nothing left to discriminate on, since content origin lives only in the store's `content_origin` column now. `ScienceClientArtifactVersion` additionally drops `projectId` (content reads are session-addressed; the Host resolves the owning project) and the event-derived `turn` join keyed by `toolCallId`. [Preserve Science trajectory ownership across cold pagination](../bug-fix/2026-09-02-science-cold-trajectory-ownership.md) later restores optional client `turn` and `step` coordinates from the private Science fold's active eligible call; the durable artifact event still contains no tool-call provenance.

**`applyArtifactSaved` keeps exactly four checks; everything else moved to the store write transaction that commits before this event does.**

| Kept check | Where |
|---|---|
| One session's artifacts share one `projectId` | `state.artifacts[0].projectId` compared against the incoming event |
| A `versionId` cannot back two committed versions | checked in the new-version branch before pushing |
| `version` must exceed this session's own locally-known maximum for that `artifactId`, or equal an already-recorded one | `known.at(-1)` vs. `artifact.version`, mirroring the pre-existing S3 cross-session-trust reasoning |
| `sha256` distinguishes a content event from a metadata-snapshot re-record | equal to the target's `sha256` (and `versionId`) → replace the array entry in place (title/caption advance, content pinned); different → rejected, since a genuine new version always uses a fresh ordinal |

| Deleted check | New home |
|---|---|
| `parent` lineage validation (self-reference, "does not identify a committed artifact version", "parent must be the current committed version", "must retain parent logical name", "a superseding save cannot rewrite its parent") | T1's `base_version_id`/`base_explicit` columns and FK; the human-edit-specific "must be current latest" policy is `commitStyleEdit`'s own precondition against a fresh store read (science-runtime, T2b) |
| Human-edit parent must be a PNG | `commitStyleEdit`'s call site reads the source version's media type from the store before allowing an edit (science-runtime, T2b) |
| Human-edit must copy parent `environmentRevision`/`environmentFingerprint` | `commitStyleEdit` assigns `environmentFingerprint` directly from the parent's own store-read value — an assignment, not a fold-checked equality (science-runtime, T2b) |
| `createdAt` interval checks (human-edit parent-to-commit, run finish-to-commit, "moves backwards in time") | `versions.created_at` is fixed once at the store's `INSERT` transaction time; temporal ordering is a property of that transaction, not something replay can independently verify without the field |
| Source run must exist and have reached a terminal status | the runtime only calls `store.appendVersion`/`store.annotateVersion` for a run it has itself observed complete — a call-site invariant in `capture.ts`/`index.ts` (science-runtime, T2b), not a replay-checkable fact once `runId` leaves the event |
| `origin`-gated authorization (`requireToolCall` for `annotate_artifact`, "only a model curation may supersede", auto-capture must carry its source run's own `toolCallId`/`requestHeaderSeq`) | `version_annotations.actor`/`sessionId`/`toolCallId`/`requestHeaderSeq` are recorded directly by the runtime's `annotateVersion` call (science-runtime, T2b); this fold no longer has an `origin` field to gate on, and any re-record retaining the target's `versionId`/`sha256` is now accepted as a metadata snapshot regardless of who is doing the recording — an intentional loosening the store's own actor column absorbs |
| A curation call's `toolCallId`/`requestHeaderSeq` consumed exactly once (`consumedToolCallSeqs`) | not relocated — `science/artifact-saved` no longer consumes a tool call at all, so the "no two Science facts share one authorizing call" invariant this shared with run/kernel/outcome facts no longer applies to curation. Nothing today prevents an `annotate_artifact` call's id from being cited twice through the store's own append path; this is a residual gap for T2b to close if it matters (the store records the actor's `toolCallId` per annotation row, but doesn't cross-check reuse against other Science fact kinds) |
| Reusing an `artifactId` under a different `logicalName` ("an artifactId cannot name two logical artifacts") | T1's `UNIQUE(owningProjectId, logicalName)` constraint makes this structurally impossible for a correctly-functioning store; the event's own `logicalName` is a per-event snapshot for model-request purposes, not a fold-verified invariant any more |
| `mediaType`/`byteCount` retained verbatim across a metadata-only re-record | dropped along with the fields themselves — the store's immutable version row is the only place these are recorded now |
| `chart` state on the artifact version, gated to `image/png` only | moved to the store's `figure_state` side table (T1's `kind`-keyed side-table design), written directly by the runtime alongside the version row (science-runtime, T2b) |

`science/outcome-published`'s chart-evidence branch loses one incidental capability as a direct consequence: it can no longer contribute an `environmentRevision` to `citedEnvironmentRevisions`, since an artifact version's environment provenance is no longer on the event. `ScienceOutcomePublication.environmentRevisions` now documents itself as "used by cited run evidence; chart evidence never contributes" rather than "run or chart evidence" — a chart-only outcome publishes with an empty `environmentRevisions` array.

**`SCIENCE_PROJECTION_STATE_VERSION` moved 16→17** for this change (fold semantics changed: the kept-check list, the metadata-snapshot dispatch, and the removed `chart`/environment-provenance fields on `ScienceArtifactVersion`/`ScienceClientArtifactVersion` all changed what a persisted projection checkpoint means). The linked cold-pagination fix subsequently advances it to 18 for the turn/call trace and derived artifact coordinates.

**`SESSION_FORMAT_VERSION` is not bumped; the codec tolerates and ignores the retired fields (decision (i) from the T2 task book).** `science/artifact-saved` is a domain event, not the header/envelope/surface mechanism [`SESSION_FORMAT_VERSION` gates](2026-08-10-session-log-version-mechanism.md) — per that note's own rule, an ordinary vocabulary/shape change inside one event's payload does not require a version bump unless an old runtime would misread a new log. The reverse direction is what matters here: a *new* runtime reading an *old* log must not refuse it just because the old event still carries fields this build no longer writes. `artifactSchema` in `codec.ts` is deliberately not `.strict()`: `z.object`'s default (non-strict) parsing silently strips any key the schema does not declare, which is exactly the tolerance a pre-release-no-longer-anything-goes reader needs. `seenAt` is `.optional()`; a legacy event with no `seenAt` at all falls back to reading the old `createdAt` field instead, with a `.transform()` that fails loud only when *neither* is present. This is a read-compatibility fallback only — this build never writes `createdAt`, and the two names are not semantically identical (`createdAt` was a content-commit time, `seenAt` is a display-time snapshot) — but it is the closest available fact for a log this build did not itself produce, and a missing `seenAt` on a build-produced event is not a case this codec needs to accept.

## Alternatives considered

**Bump `SESSION_FORMAT_VERSION` 0→1 and write the first real upgrader** (option (ii) in the task book) — rejected for this change: the near-identity conversion (drop the removed fields, rename `createdAt`→`seenAt`) is exactly the kind of "almost free" upgrader the versioning note says to write when unsure, but writing and testing the very first upgrader in this chain is a larger, separable piece of work than this slimming needs to ship correctly. The codec-tolerance path achieves the same read-compatibility outcome with a one-function change and is fully covered by a decode+fold round-trip test on a v1-shaped event. If a future structural change to the header/envelope/surface mechanism forces the first real bump anyway, this event's shape can fold into that upgrader's own field-dropping logic rather than needing a second, dedicated step.

**Keep `parent`/lineage validation in the fold, resolving base-version ancestry from the event alone** — rejected: this is exactly the D1–D3 shape T1's authority rule closes. `baseVersionId`/`baseExplicit` are declared facts the store's write transaction fixes once; re-deriving or cross-checking them from a session-log-only `parent` field reintroduces the two-homes-for-one-fact problem the whole T1/T2 effort exists to remove.

**Preserve `origin`-gated supersede authorization by keeping a slimmed `origin` field on the event** — rejected: `origin`/`content_origin` is exactly the fact T1's design assigns to the store's `versions.content_origin` column (immutable, set once at content-commit) and `version_annotations.actor` (who wrote a metadata edit) — keeping any form of it on the event re-opens a second, driftable copy of a fact the store now owns outright, for a check (`only a model curation may supersede`) whose real job — deciding whether a given actor is *allowed* to re-record a version's metadata — belongs at the store write transaction, not at fold-time replay of a session log that cannot see who called `annotateVersion`.

## Consequences

This is T2a: the scope was `packages/science/science-session` only. `packages/science/science-runtime`, `packages/science/tool-science`, `packages/extensions/tool-cordis` (its generated `api-catalog.ts`), and every consumer of the now-deleted `ScienceRunArtifactVersion`/`ScienceHumanEditArtifactVersion`/`ScienceClientRunArtifactVersion`/`ScienceClientHumanEditArtifactVersion` types fail to typecheck until a follow-up task (T2b) updates their write paths to match: `capture.ts` must write full `environmentFingerprint`/`producerTurn`/`figureState` to the store instead of the event, `commitStyleEdit` must resolve `parent.chart` from `store.getFigureState` instead of the session projection, `annotateArtifact` must stop rebuilding a whole version value and instead call the T1 store's `annotateVersion` plus append the slimmed event, and every model-visible receipt in `tool-science` must drop the fields this event no longer carries. `science-session`'s own test suite (108 tests across 13 files) is fully updated and green with 100% per-file coverage; several tests that existed solely to exercise now-deleted fold checks (human-edit ancestry, `origin`-gated supersede, auto-capture toolCallId/requestHeaderSeq matching, chart-on-artifact validation) are deleted rather than patched, per the "tests describe behavior, not correctness" rule — the behavior they described no longer exists in this package.
