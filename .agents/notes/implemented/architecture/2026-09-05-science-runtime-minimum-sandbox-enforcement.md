# Agent Note: `science-runtime` accepts partial sandbox enforcement only by explicit configuration, and records what it accepted

Status: implemented

English | [中文](2026-09-05-science-runtime-minimum-sandbox-enforcement.zh.md)

## Problem

`science-runtime`'s `confineWithFullEnforcement` required every sandbox confinement — persistent kernel spawn and interpreter probes alike — to report `enforcement: 'full'`, rejecting anything less with `CONFINEMENT_UNAVAILABLE`. `dsh-sandbox-windows-acl`, the win32 rung of `dsh-sandbox-local`, honestly reports `enforcement: 'partial'`: its write-restricted ACL token cannot close two verified gaps (Everyone-writable external objects stay reachable; NTFS hard links alias a workspace grant onto an external file object — see `packages/sandbox/sandbox-windows-acl/README.md`'s "Verified boundaries" section). A hardcoded `'full'` requirement makes every win32 deployment permanently unable to run Science, with no way to accept the weaker boundary even where a maintainer has explicitly decided the trade-off is acceptable ([issue #14](https://github.com/SuperJJ007/papermachine/issues/14)).

## Decision

**A validated `Config` field, not a constant, decides the accepted floor.** `minimumEnforcement?: 'full' | 'partial'` on `science-runtime`'s `Config` defaults to `'full'` and is validated at load (`assertMinimumEnforcement`) like every other field, per "no hardcoded tunables in plugins" — deployment-varying acceptance is an explicit config choice, not a silent relaxation baked into the confinement function.

**`confineWithFullEnforcement` is generalized to `confineWithEnforcement`, taking the configured minimum as a parameter.** `meetsMinimumEnforcement(reported, minimum)` returns true when `minimum === 'partial'` (either report satisfies it) or `reported === 'full'`; `minimum === 'full'` accepts only `'full'`. `CONFINEMENT_UNAVAILABLE` still covers everything below the minimum, and the thrown message now names both levels (`` `Science requires at least ${minimumEnforcement} sandbox enforcement; the sandbox reported ${confined.enforcement}` ``) instead of silently repeating "full" regardless of what was actually configured. The sandbox provider itself is untouched: `dsh-sandbox-windows-acl` keeps reporting `'partial'` honestly; the acceptance decision lives entirely on the Science side of the seam.

**Both confinement call sites read the configured minimum from `ScienceRuntime`'s resolved config.** `environment.ts`'s `confineProbe` (interpreter probes, reached through `bindEnvironment`) passes `services.minimumEnforcement`, itself threaded from `index.ts`'s `ResolvedConfig`. `execution.ts`'s `confineInterpreterArgv` (persistent kernel spawn) accepts a `minimumEnforcement` parameter but its sole caller, `kernel-process.ts`, is out of this change's scope (concurrent branch `feat/win32-kernel-transport` owns kernel spawn's win32 wiring), so the parameter defaults to `'full'` for that one caller — kernel spawn does not yet honor a configured `'partial'` minimum end to end. This is a real, documented gap (`science-runtime/README.md`'s Known Limitations), not a claim of full wiring: probes can run on win32 under an explicit `'partial'` configuration today; a persistent kernel spawn on win32 still cannot, independent of `minimumEnforcement`, because `environment.ts`'s `prepareObservation` and `index.ts`'s `startRun` both hard-reject `process.platform === 'win32'` before confinement is reached at all ([PR #17](https://github.com/SuperJJ007/papermachine/pull/17)'s `KERNEL_UNSUPPORTED_PLATFORM`) — a platform gate this change does not touch or relax. [The win32 scratch-privacy and probe-ordering Agent Note](../bug-fix/2026-09-06-win32-scratch-privacy-and-probe-ordering.md) closes the kernel-spawn `minimumEnforcement` gap this paragraph names: `KernelSetOptions`/`KernelProcessOptions` now forward the configured value into kernel-spawn confinement, the same way `confineProbe` already forwards it into probe confinement — that same change also made `confineInterpreterArgv`'s `minimumEnforcement` parameter required, with no default, since every production caller now has a real configured value to pass.

**The actual accepted enforcement level is recorded on every environment binding, durably.** `ScienceEnvironmentBinding` (`dsh-science-session`) gains `sandboxEnforcement?: 'full' | 'partial'`, mirroring `dsh-sandbox`'s `SandboxEnforcement` type as an inlined string literal rather than adding that package as a dependency of `dsh-science-session` (a domain-event package has no reason to depend on the sandbox seam's types for one mirrored literal). `index.ts`'s `environmentBinding()` builder sets it from whichever declared interpreter's probe actually ran (`observed.python?.enforcement ?? observed.r?.enforcement`) — both probes confine under the same provider and the same configured minimum, so either present value is the session's actual level; it is absent only when every declared interpreter failed static checks before confinement was attempted. The field flows through `dsh-science-session`'s client-safe projection (`ScienceClientEnvironmentBinding.sandboxEnforcement`) unredacted — it names no Host path or secret — so provenance shows what Science actually accepted, not only what it required. `packages/client/ui-science`'s `EnvironmentSection` already renders the whole client binding via `JSON.stringify`, so no UI code changes; the field appears automatically once present.

**The codec addition is a compatible domain-payload change, not a `SESSION_FORMAT_VERSION` bump.** [The session-log versioning Agent Note](2026-08-10-session-log-version-mechanism.md) reserves that integer for header/envelope/surface-mechanism changes and unrecognized *event types* (the `ignorable` marker); it does not gate an optional field added to an already-known event type's own payload schema. `dsh-science-session`'s `environmentSchema` (`.strict()`) adds `sandboxEnforcement: z.enum(['full', 'partial']).optional()` following the exact precedent already in `codec.ts` for `artifactSchema`'s `seenAt`/`createdAt`: absent on every log written before the field existed, and a `.strict()` schema is safe to extend additively pre-release. `SCIENCE_EVENT_VERSION` (the package's own single shared payload-version literal, never bumped since it was introduced) is also left unchanged for the same reason — bumping it would invalidate every existing Science event, not just `science/environment-bound`.

## Alternatives considered

**Build a full-enforcement Windows sandbox backend instead of accepting partial.** Rejected: `dsh-sandbox-windows-acl`'s two gaps are inherent to Windows restricted tokens, not implementation shortcuts — Everyone must stay in the restricting SID list for early DLL initialization and CNG to work at all, and NTFS hard links alias file *objects*, not paths, so a workspace ACE on a hard-linked pnpm-store file inevitably reaches the external alias. Closing either would require a fundamentally different confinement mechanism (a name-based rather than a token-based check), well beyond this change's scope and not something the maintainer asked for.

**Silently accept whatever enforcement level a supported platform's sandbox reports, with no configured floor.** Rejected: this is exactly the "no silent relaxation" the maintainer's issue #14 decision rules out — a deployment on a platform whose sandbox regresses to `'partial'` (a future backend, a misconfigured environment) would start accepting a weaker boundary with no record of why, and no way for an operator to have refused it. An explicit, validated `Config` field with a `'full'` default makes acceptance opt-in and named.

**Record `sandboxEnforcement` as a top-level field on the client projection instead of nested under `environment`.** Rejected: the enforcement level is a property of one profile binding's confinement outcome, not the session as a whole (a session can rebind its profile across revisions), so it belongs beside `python`/`r`/`status` on the same `ScienceEnvironmentBinding`/`ScienceClientEnvironmentBinding` value those already live on, not as a new sibling concept.

**Thread `minimumEnforcement` all the way into `kernel-process.ts`'s confinement call in this change.** Rejected: `kernel-process.ts`, the driver assets, and the win32 rejections in `startRun`/`prepareObservation` are `feat/win32-kernel-transport`'s territory; editing them here would create merge conflicts with concurrent work on the same lines. `confineInterpreterArgv`'s optional parameter (defaulting to `'full'`) keeps the one existing caller compiling unchanged while making the function ready for that branch to pass a real value through once it owns the wiring (the parameter has since become required, with no default — see this Note's own Decision section).

## Consequences

An interpreter probe (`bindEnvironment`, reached before any kernel spawn) now succeeds on a sandbox reporting `'partial'` when, and only when, a deployment sets `minimumEnforcement: 'partial'` in `science-runtime`'s config; the default (`'full'`) preserves today's behavior everywhere it is not explicitly overridden. `apps/desktop`'s `runtime-overlay.ts` sets `minimumEnforcement: partial` only for `platform: 'win32-x64'` in the generated `cordis.yml` overlay; every darwin target omits the field and keeps the `'full'` default. This overlay setting takes effect on a live win32 launch: `apps/desktop/src/main.ts`'s `openInitialSurface()` runs the same binding-and-onboarding path on every platform — see [the Windows-launch-block-removed Agent Note](../bug-fix/2026-09-06-windows-launch-block-removed.md).

Every environment binding Science writes now carries `sandboxEnforcement` whenever at least one declared interpreter's probe reached confinement, readable from the session log and from the client projection's `EnvironmentSection` (existing `JSON.stringify` rendering, no new UI). `packages/science/tool-science/README.md`/`README.zh.md` state that the accepted level is configured and recorded. `science-runtime/README.md`/`README.zh.md` document the new `Config` field, the recorded field, and link `dsh-sandbox-windows-acl`'s boundary list for what `'partial'` actually means; a Known Limitations bullet stated the kernel-spawn-confinement gap honestly rather than implying full end-to-end wiring until that gap closed (see this Note's own Decision section), at which point the bullet was removed rather than left describing a gap that no longer exists.

Coverage: `config.spec.ts`-equivalent cases in `environment.spec.ts` cover `minimumEnforcement`'s default, both valid values, and a failing-loud invalid value; `execution.spec.ts` adds a `confineWithEnforcement` matrix (full/full accepts, partial/full rejects naming both levels, partial/partial accepts, full/partial accepts, unavailable rejects regardless of minimum) and a `confineInterpreterArgv` pair (defaults to full, accepts a caller-passed minimum); `dsh-science-session`'s `projection.spec.ts` and `fold.spec.ts` cover the field's presence, absence, and decode round trip.
