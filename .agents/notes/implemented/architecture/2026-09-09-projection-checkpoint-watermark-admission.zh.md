# Agent Note: 投影 checkpoint 水位准入

Status: implemented

[English](2026-09-09-projection-checkpoint-watermark-admission.md) | 中文

## 问题

结构合法的检查点可能描述比其封套声明更早的事件前缀。

## Decision

类型合法的 checkpoint 仍可能在较新的外层序号下携带旧状态。按外层序号跳过事件会丢失持久化事实。投影定义可通过 checkpointStateSeq 公开状态水位。同一个解析器在缓存视图、回放种子或热恢复使用该行前，验证 stateSchema 以及水位与行序号相同。

## Consequences

即使投影键和状态版本匹配，schema 失败和内部水位不一致都会使缓存行不可用。无效行不发布缓存视图，并使 `restoreFloor` 返回零。`restore` 和 `hydrate` 拒绝不足的日志后缀，但会从完整日志重建状态，而非传播已丢弃缓存的 schema 错误。这项正确性检查不需要独立 checkpoint schema 或通知比较器。实时视图通知频率遵循上游引用比较行为。既有只读会话迁移准备记录处理日志格式转换，并未被此决定取代。

## 考虑过的替代方案

只在恢复时检查会让冷读取和水合接受不一致状态。另设检查点 schema 会重复验证。

补丁范围、行数和上游状态见[移栽补丁台账](../process/2026-09-09-replant-upstream-patch-ledger.zh.md)。

## 验证

投影注册表测试使用当前版本、外层游标合法的行，分别构造状态无效和内部水位不一致两种情况。测试检查缓存视图排除、完整重读选择、后缀拒绝、重放后检查点精确相等，以及在没有既存实时单元的独立 Session 上执行水合。领域测试保留负 token 数、重复轮次编号和标题输入不一致的夹具；损坏行不得用于初始化折叠，而有效检查点可以从同一后缀继续恢复。完整日志恢复必须同时重建预期视图和内部状态，因此仅断言恢复不抛错并不足够。

[已准备会话的缓存测试](../../../../packages/session/session-projection-cache/tests/cache.spec.ts)还覆盖可读取但不满足当前 wire 视图 schema 的缓存状态。直接注册表水合拒绝该行，而缓存水合用精确完整日志重试并安装预期的实时投影值。已准备的观察不改写存储行。仅测试无效状态不能证明这次重试：行解析会在水合抛错前丢弃无效状态。
