# Agent Note: Three Science product gaps: preset-switch identity, an unfriendly Runtime error, and a stale restart signal

Status: implemented

English | [中文](2026-08-18-science-mode-product-gaps.zh.md)

## Problem

Hands-on testing on 2026-08-18 recorded three Science-mode defects, none introduced by the artifacts/provenance work landing alongside this note.

**Tool-science's own guard read the frozen creation header, not the session's resolved preset.** `isScienceSession` (`packages/science/tool-science/src/context.ts`) checked `session.header.agentPreset === 'science'` directly. The header is a creation fact and stays exactly what it was; a session switched to the `science` preset while blank — the ordinary product flow, `AgentPresetSeat` in the conversation hero and the api-proxy `agentPreset.select` RPC behind it — records the switch only as a later `agent-preset/selected` event, never touching the header. Tool visibility already followed the switch correctly (`dsh-tools`' scope layers resolve from the live `dsh-agent-presets` mount, not the header), so a switched session advertised `run_python`/`run_r` normally; every call then rejected with "this tool requires a session bound to the science preset" — the exact symptom originally attributed to "tools advertised in non-Science sessions." Every other host-layer reader of a session's preset (`dsh-host-apiproxy`, `resolveSessionPreset` itself) already resolves this way; tool-science's own check was the one holdout.

A session created directly under the `science` preset (`agentPreset: 'science'` at creation, the CLI/ACP/headless entry-point path) never hits this gap — its header already says `science` from the start. `apps/cli/tests/web-agent-presets.e2e.ts`'s `keeps its narrow roster out of standard, and standard's roster out of it` already proves the literal original claim false for that path: `run_python`/`run_r` are absent from a `standard` session's tool list, scoped correctly by the R4 preset-mount architecture.

**The Science Runtime's unconfigured-profile error named an internal vocabulary, not the fix.** `ScienceRuntime.profile()` (`packages/science/science-runtime/src/index.ts`) rejected a profile id absent from its configured map with `unknown Science environment profile "science"` — accurate but silent about the fact a person can act on: no Conda prefix is named for it yet, and where to name one. The requested id is fixed preset policy (`profileId: 'science'` in the shipped preset's own `cordis.yml`), never model or user input, so every occurrence of this error means exactly one thing: the deployment has not configured that profile. The message reached both a human reading Runtime-thrown text directly and a model relaying it to one, and served neither.

**The settings card's restart-required signal was a client-local flag, not a host fact.** `ScienceSettingsCardController` tracked `restartRequired` as an instance field set `true` after a landed save and never otherwise cleared. A page reload constructs a fresh controller, so the flag reset to `false` regardless of whether the running Host had actually restarted — a person who saved a prefix, closed the tab, and reopened it without restarting the Host saw no signal that the change was still pending, and the card could not distinguish "the Host already restarted and picked this up" from "nothing has happened since the save."

## Decision

**`isScienceSession` resolves through `@deepseek-ai/dsh-agent-presets`'s `resolveSessionPreset`** (the session's creation header, overridden by the last `agent-preset/selected` event) instead of reading `session.header.agentPreset` directly. `tool-science` gained a peer/dev dependency on `dsh-agent-presets` for this pure function (no service, no `ctx` — `dsh-agent-presets` has no dependency back onto `dsh-science`, so this is not a cycle). `requireScienceSession` (`run.ts`) and the `system-prompt/assemble` first-use-binding waterfall both call `isScienceSession`, so both now agree with the tool-visibility scope layer on which sessions run under `science`.

This closes the gap for a session whose header and resolved preset already agree throughout its life (created under `science`, or created under something else and never switched) with no behavior change. For a session switched to `science` while blank, `dsh-science-session`'s own durable-stream applicability check now agrees too, closed in the same change (see the next paragraph and Consequences).

**`dsh-science-session`'s durable-stream applicability check now takes the session's resolved preset as a parameter instead of reading `header.agentPreset` itself.** `assertScienceSessionApplicability` (`applicability.ts`) signature changes from `(header, state, event)` to `(preset: string | undefined, state, event)`. Its one caller, the `science-session-invariant` companion (`invariant.ts`), tracks that resolved value incrementally alongside the existing `ScienceFoldState` cursor it already threads through `seed()` (Host-restart replay) and the `internal/dispatch`/`session/event` pre-commit pair (the live path) — advancing past each `agent-preset/selected` event exactly the way `resolveSessionPreset` does (newest selection wins), rather than calling `resolveSessionPreset` itself. `dsh-science-session` gains the `@deepseek-ai/dsh-agent-presets` peer/dev dependency for the `agent-preset/selected` `SessionEventMap` type augmentation the incremental walk narrows against — no runtime call, so this is not the layering inversion the alternative considered below worried about.

**`ScienceRuntime.profile()` rejects with a new `PROFILE_NOT_CONFIGURED` code** and a message naming the missing prefix and the Settings → Plugins → Science card, replacing the `INVALID_REQUEST` code that conflated "you configured nothing" with "you sent something invalid" — a distinction worth keeping now that the two need different messages. The check is the one choke point `bindEnvironment` and `startRun` both resolve a profile id through, so the message improves at every call site from a single edit, matching "enforce a decision in the operation that makes it."

**`SettingsProvider` (`dsh-settings`) captures the value a `restart`-applies namespace's owner actually read at registration** (`SettingsRegistration.effective`, frozen for the process lifetime) alongside the always-current `resolved` value, and exposes both from `describe()` as `value` (current document) and `effective` (what the running owner acts on) — equal for a `live`-applies namespace, which re-reads on every commit. This is a generic addition to the settings seam, not a Science-specific one: any `restart`-applies namespace's configuration UI can now tell "saved" from "in effect" from the wire alone. The field threads through `dsh-host-apiproxy`'s `SettingsNamespaceView` and `dsh-client-runtime`'s `SettingsScopeSnapshot<T>` the same way `applies` already does.

`ScienceSettingsCardController` replaces its `restartRequired` instance field with a pure `hostState()` projection (`'effective' | 'pendingRestart' | 'notConfigured'`) comparing `snapshot.effective` against `snapshot.value`'s `science` key presence — no bookkeeping, no client-local state, so a fresh controller after a page reload reports the same answer a live one would. `'pendingRestart'` covers both directions: a value just saved that the Host has not read yet, and a value just removed that the Host is still bound to. The card renders `'pendingRestart'`/`'notConfigured'` as the existing `role="status"` notice lines (reusing the existing `restartRequired`/`unconfiguredHint` locale keys, reworded to name "saved" explicitly); `'effective'` renders a new, plain (non-`status`) confirmation line — a static fact, not a transient update for assistive technology to announce, matching how a field's own hint renders.

## Alternatives considered

**Fix `isScienceSession` alone and call defect one closed.** Rejected as incomplete: the switch-while-blank scenario would still fail — tool visibility correct, execution still refusing — just with a different, deeper error surfacing from `dsh-science-session`'s own applicability guard instead of tool-science's message. Documenting the remaining gap (see Consequences) is more honest than a fix that only partly closes the symptom.

**Call `resolveSessionPreset(session)` directly at the invariant's pre-commit call site, instead of tracking the resolved preset incrementally.** Correct only for the live dispatch path, where `session.events` already reflects every previously committed event. `science-session-invariant` also re-seeds a session's complete history from scratch on Host restart (`seed()`), replaying `assertScienceSessionApplicability` once per historical event; calling `resolveSessionPreset(session)` there would resolve every one of those events against the session's CURRENT (full-log) preset, wrongly retrofitting a later `science` switch onto history that ran under `standard` when it was originally appended. `packages/science/science-session/tests/invariant.spec.ts`'s re-seed test exists specifically to catch this regression. The incremental cursor (advance-on-`agent-preset/selected`, carried the same way the existing `ScienceFoldState` cursor already is) gives the correct point-in-time answer for both the seed and the live path without this failure mode.

**Give the settings card its own Science-specific RPC for "the running Host's bound profiles."** Rejected in favor of the generic `dsh-settings` seam addition: `applies: 'restart'` already existed as a per-namespace declaration with no way to answer "restart to what effect," and any other `restart`-applies namespace has the identical gap. A dedicated Remote (the `pluginInventory` pattern) would have solved only Science's instance of a problem the seam itself was missing a field for.

**Always show an explicit "configured, effective" status banner.** Rejected: the card's own existing test suite established "zero status lines when nothing needs attention" as its convention (`shows a neutral "Configured" badge... ` asserted `queryAllByRole('status')).toHaveLength(0)`), and preserving it avoids a screen-reader announcement for a fact that did not just change. The confirmation still renders, as plain text alongside the field hints, satisfying "the card shows... configured, effective" without contradicting the existing convention.

**Rename the new `dsh-settings`/wire field away from `effective` to avoid the pre-existing informal use of "the effective value" (schema defaults → base → user resolution) elsewhere in this codebase's prose.** Considered late, after the field was already threaded through six files; the two senses are distinguishable by context (one is a document-resolution term used in prose, the other a named struct field), and one comment that specifically invited confusion was reworded (`provider-form.client.spec.tsx`) rather than renaming the shipped field.

## Consequences

Defect one and defect two ship as targeted, low-risk fixes verified by real-composition and unit coverage; defect three ships as a small, genuinely generic addition to the settings seam plus the Science card's consumption of it.

**The switch-while-blank Science session is fully supported, not just partly.** `isScienceSession` and `dsh-science-session`'s own durable applicability check now agree: both resolve the session's live preset (creation header, overridden by the last `agent-preset/selected` event), so first-use binding — `science/mode-bound` through the rest of a Science turn — succeeds for a session switched to `science` while blank, with no remaining "tool visible, execution refused" gap and no separate deeper failure shape to document. `apps/cli/tests/web-agent-presets.e2e.ts`'s `fails loudly before any provider request when the mounted Science Runtime has no profile configured` test asserts on the `PROFILE_NOT_CONFIGURED` message text now, replacing its prior placeholder assertion on the `INVALID_REQUEST`-era "unknown Science environment profile" wording.

**`ScienceRuntimeErrorCode` gained one member** (`PROFILE_NOT_CONFIGURED`); nothing in this repository switches on that closed union today (`.code` is read only as test/diagnostic metadata), so the addition has no exhaustiveness-switch fallout.

**`SettingsDescriptor`/`SettingsNamespaceView`/`SettingsScopeSnapshot<T>` gained a required `effective` field.** Every literal construction of these three shapes across the repository's tests and fixtures needed one more field (a mechanical, compiler-driven pass — no runtime behavior at those call sites changed beyond what the type made visible). A future settings-consuming card gets `effective` for free from the same wire path Science now uses.

## Testing

`packages/science/tool-science/tests/tool-science.spec.ts` adds a session created under `standard` then switched via an `agent-preset/selected` event, asserting `isScienceSession`/`requireScienceSession` resolve `true` from the log — the case the header-only check answered wrong. `apps/cli/tests/web-agent-presets.e2e.ts`'s existing `keeps its narrow roster out of standard, and standard's roster out of it` remains the real-composition evidence that the original "advertised in non-Science sessions" claim does not hold on the current architecture.

`packages/science/science-session/tests/applicability.spec.ts` updates every case to pass a resolved preset string (or `undefined`) instead of a header object. `packages/science/science-session/tests/invariant.spec.ts` adds two tests: a live-dispatch case (a session created under `standard`, `science/mode-bound` rejected before an `agent-preset/selected` switch and accepted immediately after) and a seed/replay case (a switched session's complete history re-seeded from scratch after a simulated Host restart does not retroactively fail).

`packages/science/science-runtime/tests/{environment,settings,loader-composition}.spec.ts` updated their unknown/unconfigured-profile assertions from `INVALID_REQUEST` to `PROFILE_NOT_CONFIGURED`, with one asserting the exact new message text.

`packages/settings/settings/tests/settings.spec.ts` adds three tests: `effective` frozen at registration for a `restart`-applies namespace across a later write, `effective` tracking every write for a `live`-applies one, and `effective` redacted independently of `value` once they diverge. `packages/client/ui-settings/tests/settings-scope.client.spec.ts` adds the wire-to-snapshot threading case. `packages/client/ui-science/tests/settings-card-controller.client.spec.ts` adds a dedicated `hostState` describe block (all three states, both mismatch directions) and updates every existing `restartRequired`-based assertion; `packages/client/ui-science/tests/ScienceSettingsCard.client.spec.tsx` updates the corresponding rendered-text assertions and adds the plain (non-`status`) `'effective'` confirmation case.
