# Agent Note: Chart adapters de-duplicate colliding element ids before hit-map extraction

Status: implemented

English | [中文](2026-08-28-chart-element-id-collision.zh.md)

## Problem

A real Science session drew a matplotlib grouped bar chart with twelve `ax.annotate` bar-value labels, alongside an R ggplot2 chart in the same session. R's edit panel appeared; Python's did not — the saved PNG's artifact carried no `chart` field at all. Running the model's exact source plus `CHART_EXTRACT` directly against the real kernel (mesa Python) showed the kernel itself extracted a valid 23-element chart (`runtime: 'matplotlib'`, `hitmapStatus: 'unavailable'` under `bbox_inches='tight'`) — the adapter and kernel protocol were not at fault.

The loss happened at host decode. `packages/science/science-runtime/src/index.ts`'s `extractChartsAfterFinish` calls `decodeScienceChartState` per extracted chart and, on a throw, logs a warn and omits that path from the returned chart map entirely — silently dropping the chart rather than failing the run. `science-session/src/codec.ts`'s chart `superRefine` throws when `elementIds.size !== chart.elements.length`, i.e. when two elements share an id. `chart_matplotlib.py`'s `extract_elements` built each annotation's id from the artist's own rendered text — `"annotation[text:%s]" % text.get_text()[:20]` — with no uniqueness guarantee across artists. Two of the twelve bar-value annotations rounded to the identical displayed string ("0.48"), so both got the id `annotation[text:0.48]`, `chart.elements` carried a duplicate, the codec rejected the whole chart, and the artifact lost `chart` — with no error surfaced anywhere the model or a maintainer would see it, since the drop is a warn-level log inside a private extraction helper. R's `chart_ggplot2.R` built annotation ids from `layer<N>:<GeomClass>`, which happened not to collide in this session, but carries the identical structural risk for two annotation layers producing the same geom class, or a series (`series[<label>]`) whose two legend labels are formatted identically by the plot's own scale.

The codec's uniqueness check is correct: the pixel-space hit map references elements by id, so a duplicate id makes the map ambiguous. The defect is that the adapters can emit a duplicate in the first place.

## Decision

`extract_elements` in both `chart_matplotlib.py` and `chart_ggplot2.R` runs a deterministic de-duplication pass over its built element list immediately before returning: the first element carrying a given id keeps it; every later element with the same id gets a stable `#N` suffix (`#2`, `#3`, …) in list order. `chartElementIdSchema` (`codec.ts`) only forbids empty ids, ids over `MAX_CHART_ELEMENT_ID_LENGTH`, and control characters — `#` is an ordinary legal character, so the suffixed id needs no further validation change. `compute_hitmap` (matplotlib) builds its result directly from the already-deduplicated `elements` list passed into it, so the hit map always references the post-dedup ids by construction; `compute_hitmap` (R) never reads `elements` at all — its handful of hit ids (`title`, `x_label`, `legend`, per-axes `grid`, …) are fixed strings distinct from the element catalog's `annotation`/`series` ids, so it carries no collision risk of its own. The codec's uniqueness and hit-reference checks are unchanged; they are correct and still the enforcement point.

## Alternatives considered

**Relax the codec's uniqueness requirement (allow the last element with a given id to win, or drop later duplicates).** Rejected: the codec's uniqueness invariant is what makes the hit map's id references unambiguous, and it is the only enforcement point that both adapters must satisfy; weakening it silently discards catalog entries (an annotation the user can see in the PNG but never was recoverable in `elements`) instead of preserving all of them under distinguishable ids.

**Make the id formula itself collision-resistant (hash the full rendered text, or include the artist's index unconditionally).** Rejected: existing ids (`series[GPT-4 (dv)]`, `annotation[text:0.48]`) are already meaningful, stable across identical re-runs, and used verbatim as edit targets in the model-visible `applyChartEdit` API surface (matched against `element["label"]` and `_artist_for`'s substring lookup); switching to a hash or an always-present index would change every existing id's shape for no benefit over appending a suffix only where a real collision occurs, and would not by itself guarantee uniqueness either (two artists can still hash identically or land at the same computed index) without a dedup pass regardless.

## Consequences

A matplotlib or ggplot2 chart whose extracted elements would have collided now keeps its full catalog under unique ids and gets an edit panel like any other chart, instead of `extractChartsAfterFinish` silently dropping the entire `chart` field with only a warn-level log line. The `#N`-suffixed id for a later duplicate is stable for a given figure (list order is deterministic per extraction) but is not guaranteed to point at the *same* physical artist as a differently-ordered extraction of a re-drawn figure; this only affects charts that already had colliding ids, which previously had no `chart` state to disambiguate at all. [Export geometry](2026-08-31-science-reference-authorship-and-geometry.md) resolves duplicate annotation ids to their own artist occurrence and records tight-cropped positions.

## Verification

`packages/science/science-runtime/tests/real-acceptance.ts`'s matplotlib `'tight'` case now draws a grouped bar chart whose bar-value annotations collide before dedup (`control[0]=0.483` and `treatment[0]=0.477` both format to `"0.48"`) and asserts the resulting artifact carries a `runtime: 'matplotlib'` chart with every element id unique and both `annotation[text:0.48]` and `annotation[text:0.48]#2` present — proving the real kernel's extraction, `decodeScienceChartState`, and the whole `extractChartsAfterFinish` host path accept it end to end. `packages/science/science-session/tests/chart-codec.spec.ts`'s existing `'rejects duplicate element ids, unordered hit bounds, and hits on an unavailable map'` test already locks the codec's own rejection of a chart with two same-id elements; it needed no change.
