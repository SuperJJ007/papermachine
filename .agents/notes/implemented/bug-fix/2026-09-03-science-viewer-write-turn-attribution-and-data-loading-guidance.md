# Agent Note: Viewer-write turn attribution and data-loading prompt guidance

Status: implemented

English | [中文](2026-09-03-science-viewer-write-turn-attribution-and-data-loading-guidance.zh.md)

## Problem

A save-as clicked during an idle gap between turns (Turn 9 settled, no Turn 10 sent yet) showed under Turn 9 in the trajectory until the user sent Turn 10, at which point the copy silently moved to Turn 10. `saveArtifactAs` and `performChartEdit`'s human-edit commit are viewer operations with no authorizing tool call, so the strict Science fold's turn/step assignment (open `run_python`/`run_r`/`annotate_artifact` call only) never applied to them, and `ScienceClientArtifactVersion.turn` stayed `undefined`. The client's `science-trace-model.ts` filled that gap with `lastTurn`, recomputed from the currently loaded conversation on every render — so a version created before the newest turn existed drifted onto it as soon as that turn appeared.

Separately, two prompt gaps surfaced on real devices. The Science persona told the model to read, search, and inspect the workspace with `read`/`glob`/`grep`, with no rule steering tabular data through the kernel instead; asked to read a CSV's columns, the model used `Glob`+`Read` and left no DataFrame behind, so a follow-up asking to compute on "the df just loaded" required re-reading the file. And `annotate_artifact`'s description presupposed the named artifact already existed ("an artifact your code already produced"); asked to caption a nonexistent `nothing.png`, the model never called the tool to find out and created a substitute file instead of reporting nothing named that existed.

## Decision

**`saveArtifactAs` and `performChartEdit`'s human-edit commit set `producerTurn` from the session's last started turn, read once when the method is called.** Both already hold a `ScienceProjection` from `assertSession`; `projection.trace.turns.at(-1)?.turn` is captured before any further `await` (kernel replay, store round trips) so a version created during an idle gap keeps the turn that was current at the moment of the call, never whichever turn is newest by the time the store write commits. The store already modeled `producerTurn` on `VersionRecord`/`VersionProducerInput` (capture.ts's run-auto path already set it from the authorizing run's own `tool/call` turn) — only the two viewer-write call sites were omitting it. It reaches `ScienceVersionSummary.producer.turn` on the browser through the existing `sessions.scienceVersions` read (`packages/host/apiproxy/src/api-proxy.ts`), with no new wire field.

**The client trace model prefers `producer.turn` over the timestamp fallback, and the timestamp fallback no longer guesses when no turn qualifies.** `buildScienceTraceModel` resolves an artifact version's turn as `artifact.turn ?? summary.producer.turn ?? artifactTurn(...)`, in that order: the projection owner coordinate (a run or annotation call), then the store's own `producerTurn` (a viewer write), then — only for a version with neither, a direct human edit or import predating this fix, or a legacy record — the last turn whose declared `startTime` is at or before the version's `createdAt`. A turn that starts after `createdAt` is never a candidate, closing the idle-gap drift the old `lastTurn` fallback caused. A version resolving none of these — its `createdAt` precedes every turn this view knows about — joins `unassigned.artifacts` (previously documented "always empty") alongside `unassigned.runs`; `ScienceTraceView`'s existing unassigned-history section and `trace.unassignedSummary` copy already render both without further UI change, so the copy no longer claims the missing coordinate is a producing call absent from the loaded conversation, only that the record has no turn in this trace. `contentOrigin` is untouched by this fix — a save-as copy stays whatever the source's content origin was; it is never reclassified as a human edit.

**The Science persona sends a data file through `run_python`/`run_r`, not `read`/`glob`/`grep`, even for a first look.** One added sentence in `apps/cli/config/agent-presets/science/agent.cordis.yml`'s persona names the tabular formats (csv, tsv, xlsx, parquet, sav, dta, rds, json data) and states the reason: loading through the kernel leaves a named variable other turns can reuse, where `read`/`glob`/`grep` cannot. `tool-science`'s `STATIC_GUIDANCE` carries the matching kernel-side half of the same fact — bind the loaded table to a named variable — next to the existing persistent-kernel bullet, without repeating the persona's read-vs-run rule (one home per fact: the persona is the product-level home for which tool to use, `STATIC_GUIDANCE` is the tool-level home for what to do once inside the kernel).

**`annotate_artifact`'s description tells the model to call it on a named-but-unknown artifact and relay the diagnostic, never fabricate a substitute.** The tool description and `logical_name`'s parameter description both add this instruction; `resolveAnnotateTarget`'s existing `ARTIFACT_NOT_FOUND` diagnostics (including the retained-but-uncaptured-raster recovery text) were already reachable and correct — the gap was purely that the model never called the tool for a name it had no record of, so those diagnostics never ran.

## Alternatives considered

**Recompute `producerTurn` at store-write time instead of at call entry, for `saveArtifactAs`/`performChartEdit`.** Rejected: the whole point is the turn *current when the user acted*, not whatever turn is current after kernel replay or a queued lease resolves — recomputing later would just move the drift window rather than close it.

**Give the session fold's `applyArtifactSaved` an `owner` lookup that also matches a viewer-write's synthetic marker, instead of writing `producerTurn` at the store.** Rejected: the fold's `owner` mechanism is specifically "the tool call open when this content was first committed" (`ScienceClientArtifactVersion.turn`'s own contract), and a viewer write has no such call by definition. Store-level `producerTurn` is the correct home — it already exists for exactly this kind of fact for run-auto captures.

**Keep the old `lastTurn` fallback and only add the store's `producerTurn`.** Rejected: `producerTurn` closes the gap only where the runtime write path was fixed; a legacy record, a direct human edit or import that never carried `producerTurn`, and any future coordinate-free version would still hit the same drifting fallback. Replacing `lastTurn` with "the last turn whose `startTime` precedes `createdAt`, else unassigned" fixes the mechanism, not just this one call site.

**Put both prompt sentences in `STATIC_GUIDANCE` alone, since it already reaches every Science model call.** Rejected for the data-loading rule: the persona is the product-level statement of which tool to reach for and is read once per session start alongside the other `read`/`glob`/`grep` guidance it is correcting; duplicating the same sentence in `STATIC_GUIDANCE` would violate one-home-per-fact for no benefit, since both sections are already composed into the same system prompt.

## Consequences

`packages/science/science-artifact-store` is untouched — `producerTurn` was already a modeled, optional column; only two callers changed what they pass. `packages/science/science-runtime/tests/save-as.spec.ts` and `chart-edit.spec.ts` each gained a case asserting `producerTurn` is recorded from the session's last started turn and is unaffected by a turn that starts after the call. `packages/client/ui-science/tests/science-trace.client.spec.tsx`'s prior pinned test describing the drifting fallback ("keeps legacy records without projection coordinates on the timestamp fallback") is replaced by three cases: the idle-gap timestamp fallback landing on the preceding turn, `producer.turn` winning over a timestamp that would resolve differently, and a pre-first-turn version landing in `unassigned.artifacts`. Two other existing client tests that relied on the removed `lastTurn` guess now declare an explicit turn-timing window instead, matching what a real Session always provides.

The keyless `science-tools` scenario (`examples/headless-agent/tests/snapshots/science-tools/`) is the end-to-end proof: `source-agreement.expected.json`'s two human-edit versions now carry `producer.turn`, and `model-view.expected.json` carries the two changed prompt strings verbatim — both refreshed with `DSH_SNAPSHOT=refresh` since the driver script and model responses are unchanged, only the runtime behavior and prompt text the snapshot observes. `docs/tool-catalog.md`/`.zh.md` are regenerated from the same source JSDoc/tool description.

The persona and `STATIC_GUIDANCE` additions are prompt text only; no schema, tool, or wire change. The child Science subagent's own narrower persona already tells it to "read or recompute any data you need yourself with `run_python`/`run_r`" and is left unchanged — it does not enumerate `read`/`glob`/`grep` as an alternative the way the parent persona does, so it carried no equivalent gap to close.
