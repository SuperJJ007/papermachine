# Agent Note: Science context churn and run-directory guidance

Status: implemented

English | [中文](2026-09-04-science-context-churn-and-run-directory-guidance.zh.md)

## Problem

An on-device 22-step Science session re-emitted the `science:environment` runtime-context snapshot 14 times, each carrying a `Latest run <runId> (<language>): <status>.` line that changed on every run. `dsh-agent-loop`'s `RuntimeContextProjection.project()` appends a fresh `user/message` copy of the full snapshot whenever the rendered text differs from the retained one, and never replaces an earlier snapshot — replacing one would invalidate the provider prompt cache for every message after it, the same cache-preservation design [the sandbox-policy context](../feature/2026-07-30-current-sandbox-policy-context.md) established for this mechanism. A per-run line inside a context designed to append-on-change therefore forced a fresh ~2.4 KB snapshot into history on every run, even though the run's own tool result and `get_science_state` already carry that status on demand.

Separately, the same session wrote an intermediate `boxplot_data.csv` under `SCIENCE_ARTIFACT_DIR` in one run, then tried `pd.read_csv` on that same relative path from the next run's `SCIENCE_ARTIFACT_DIR` and got a file-not-found: each run receives a fresh, private artifact directory, and `STATIC_GUIDANCE` did not state that a file written there does not survive to the next run. The model recovered by falling back to the kernel variable, but the run was wasted. A third on-device finding was a wasted step from indexing a pingouin result frame by a guessed column name instead of the one that version actually returns.

## Decision

**`renderScienceProjection` no longer renders `projection.runs`.** The `Latest run …` line is removed from `packages/science/tool-science/src/context.ts`; the context now changes only when `mode.modeRevision`, `environment`, or an interpreter binding changes, so an ordinary run turn renders byte-identical context and `RuntimeContextProjection` appends nothing. Run status remains model-visible through each run tool's own result and through `get_science_state`'s `runs` list, read on demand rather than resent on every turn. The append-vs-replace tradeoff itself is unchanged and undocumented here beyond the link above: this fix removes the source of per-run churn instead of touching how the snapshot is delivered.

**`STATIC_GUIDANCE`'s two `SCIENCE_STATE_DIR`/`SCIENCE_ARTIFACT_DIR` sentences are rewritten, not joined by a third.** The first now states that `SCIENCE_ARTIFACT_DIR` is a fresh directory each run, that a file written there is gone from the next run's directory, and that intermediate tables and working data belong in kernel variables or under `SCIENCE_STATE_DIR` only when they must survive a kernel restart — `SCIENCE_ARTIFACT_DIR` is for final deliverables only, since eligible files written there are captured as artifacts. The second keeps the private-scratch-current-directory fact and the `SCIENCE_WORKSPACE_DIR`/absolute-path access instruction, and now also states where `artifact_inputs` materialize (moved from the first sentence, which dropped a fact it no longer needed to carry). `packages/science/tool-science/README.md`/`.zh.md` quote `STATIC_GUIDANCE` verbatim and are updated in the same change, re-recorded through `verify-translation-pairing --write`.

**`apps/desktop/resources/skills/statistical-analysis/references/library_result_frames.md` adds one printed-columns rule plus verified names.** The rule: print `result.columns` (or `str(result)` in R) before indexing a result frame not yet used this session. The reference table below it names the exact result columns for pingouin's `ttest`/`mwu`/`wilcoxon`/`anova`/`pairwise_tests`/`corr`, scipy.stats result-object attributes (`ttest_ind`, `mannwhitneyu`, `wilcoxon`, `f_oneway`, `kruskal`, `shapiro`, `levene`, `pearsonr`, `spearmanr`, `chi2_contingency`), and statsmodels `summary2().tables`' three-table structure — every name read back by running the actual call against the shipped desktop environment (pingouin 0.6.1, scipy 1.16.3, statsmodels 0.14.6), not recalled from training data. `SKILL.md` gains one sentence pointing to the reference from the "Run the test" workflow step; the skill body stays at 7,424 characters, under the 8,000-character ceiling `apps/desktop/tests/bundled-skills.spec.ts` enforces.

## Alternatives considered

**Keep the run-status line but only append it as a separate, smaller context entry.** Rejected: `dsh-system-prompt` renders one ordered snapshot per registered context name, and the existing `science:environment` entry already covers mode/environment/interpreter facts that legitimately belong in one place; splitting the run status into its own entry would still append on every run, just with a smaller payload, not remove the churn.

**Add a third `SCIENCE_ARTIFACT_DIR` sentence stating the per-run freshness fact, leaving the other two untouched.** Rejected by the task itself: three overlapping sentences about the same two directories cost more fixed per-request tokens than rewriting the two that already exist, and the existing sentences already needed the "final deliverables only" framing to make the new fact actionable rather than just descriptive.

**Store the verified pingouin/scipy/statsmodels names from memory or general knowledge of the libraries.** Rejected: the skill's own existing "Compatibility traps" section already documents one pingouin column rename between versions, so guessed names in a new reference would repeat exactly the failure mode this fix closes. Every name in `library_result_frames.md` was read from `result.columns`/`dir(result)`/`repr(result)` against the exact installed versions.

## Consequences

A Science session with N runs and no environment or mode change now appends zero additional runtime-context snapshots after the first bind, instead of one per run; the keyless `science-tools` scenario's `stream-json.expected.jsonl` shrank from 13 to 8 `user/message` events (207 to 202 total JSONL lines) after refresh, and downstream `seq`/`lastScienceEventSeq` values shifted down to match the now-shorter event stream — expected, not a regression, since those are session-log sequence numbers. `model-view.expected.json` carries the rewritten `STATIC_GUIDANCE` and dynamic-context text verbatim. `packages/science/tool-science/tests/tool-science.spec.ts`'s prior "renders the latest run summary" case is replaced by one asserting the context is identical with and without run history, describing the new invariant rather than the removed rendering.

A model that writes an intermediate table under `SCIENCE_ARTIFACT_DIR` and expects to read it back from the next run's directory now has that failure mode named in the guidance it already receives every request; the guidance change is prompt text only, no schema or tool change. `docs/tool-catalog.md`/`.zh.md` are untouched because they regenerate from `run.ts`'s per-tool descriptions, which this fix does not touch — only the shared `STATIC_GUIDANCE` section changed.

`library_result_frames.md` is a static reference file, not enforced by any gate beyond the skill body's own character ceiling; a future pingouin/scipy/statsmodels upgrade that renames a documented column is a known drift this file does not detect automatically and a maintainer must re-verify against the shipped environment when those pins move.
