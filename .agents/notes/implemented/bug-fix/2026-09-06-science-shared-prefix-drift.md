# Agent Note: Per-run detection of a shared Conda prefix drifting under a Science session

Status: implemented

English | [中文](2026-09-06-science-shared-prefix-drift.zh.md)

## Problem

Two Science sessions bound to the same profile share one on-disk Conda prefix. `install_science_packages` in session A runs micromamba against that prefix and appends a fresh `science/environment-bound` revision to session A's own log — but session B's binding, and every other session sharing the prefix, never learns the prefix changed underneath it. `bindEnvironment` rejects rebinding a session once it has any run, so session B was permanently stuck reporting a stale `condaHistorySha256`/`packagesSha256`/`bindingFingerprint` for the rest of its life: `get_science_state` and every run result kept naming an environment that no longer matched what a `run_python`/`run_r` call actually executed against (GitHub issue #15).

## Decision

**A cheap, read-only digest of `<prefix>/conda-meta/history` is the drift signal, not a new event.** `prefixHistoryDigest(canonicalPrefix)` (`packages/science/science-runtime/src/environment.ts`) locates, `lstat`-validates (regular file, not a symlink), reads, and SHA-256-hashes that one append-only conda transaction log through the same private `readHistoryFile` helper `staticInterpreter` already used for its own history check — one function, shared by construction, so the two call sites can never drift into computing different digests for the same bytes. `prefixHistoryDigest` never throws: a missing file, a directory, a symlink, or any other read failure all collapse to `undefined`, and its JSDoc requires callers to treat `undefined` as drift rather than as "no signal." This is deliberately narrower than a new `science/prefix-observed` event or a filesystem watch: `conda-meta/history` is the one artifact every conda mutator (`micromamba install`, and a user's own manual `conda`/`micromamba` invocation against the same prefix) is guaranteed to append to, so comparing its digest catches drift regardless of which process caused it, at the cost of one `stat`+`readFile` per run instead of a full re-observation.

**`startRun` checks the digest before every run, cheaply, and only pays for a full re-observation on an actual mismatch.** `prefixDrifted(environment)` compares the live digest of each bound language's prefix against the `condaHistorySha256` recorded in the session's applied binding. A mismatch (including a digest that now resolves to `undefined`) routes through the same `reobserveAndMaybeRebind(session, profile, control, reason)` helper `installPackages` already used for its own re-observe-and-append step, now shared between the two call sites and parameterized only on `reason: 'install' | 'drift'`. On a match, `startRun` pays nothing beyond the one cheap digest read and proceeds exactly as before.

**A re-observation that comes back non-`applied` is never appended for a drift check.** `installPackages` unconditionally appends whatever `observeProfile` returns, including an `invalid` revision, because it is reporting the outcome of a mutation the caller asked for. A drift check triggered from inside `startRun` is not: the caller asked to run code, not to rebind. `bindEnvironment` refuses to rebind a session once it has any run (`index.ts`), so appending an `invalid` revision here would strand the session identically to the original bug it is fixing, permanently rather than transiently. `reobserveAndMaybeRebind(..., 'drift')` instead rejects the run itself with `ENVIRONMENT_NOT_READY` and leaves the session's last-applied revision untouched, so a later run against a prefix that becomes usable again (the mutating session finishes, or a broken manual edit is reverted) can still succeed.

**Scratch materialization happens before the re-observation, not after.** `startRun` materializes the session's scratch directory as soon as drift is detected and reuses that same `scratchPreparation` for the rest of the run, rather than re-observing first and materializing scratch only once a fresh environment comes back. Reordering it the other way would leave a probe or an install running with no scratch directory backing the run it is about to serve, and would duplicate the idempotent "create or verify" work `materializeSessionScratch` already does.

**Desktop's `applied.json` sync stays out of scope.** The desktop provisioning track mirrors an applied environment revision into `applied.json` on disk so a relaunch can skip re-observation; this change does not touch that path. A drift detected mid-session updates the session's in-memory/log-recorded binding but does not write `applied.json`, so a desktop relaunch after a cross-session drift still re-observes from scratch the way it always did before this change — no new staleness is introduced there, but no acceleration is added either. Whether `applied.json` should also learn about a rebind that happened without a fresh launch is a separate product question, tracked as a follow-up issue rather than folded into this fix, since it changes desktop's own on-disk contract rather than the Runtime's in-session behavior.

**Installing a package still needs no user approval.** `install_science_packages` (`packages/science/tool-science/src/install.ts`) registers through `defineTool` with only `requireDirectDispatch`; it carries no `tools/pre-execute` or `ctx.approval` gate, unlike the seam that exists for tools that need one (`packages/core/tools/README.md`). This was already true before this change and is unaffected by it: the drift fix makes the tool's cross-session side effect *visible* to every other session (each learns about the mutation on its own next run instead of silently going stale), which weakens rather than strengthens the case for adding an approval gate. The decision — no approval required — is recorded in `packages/science/tool-science/README.md` alongside this rationale.

## Alternatives considered

- **A new `science/prefix-observed` event every mutator appends, instead of a digest comparison.** Rejected: it requires every current and future writer of a shared prefix (micromamba, a user's own manual `conda`/`micromamba` invocation) to know about and append a DSH-specific event, which a manual invocation never will. Comparing `conda-meta/history`'s own digest needs no cooperation from the writer.
- **A filesystem watch on the prefix, checked once at session start.** Rejected on two counts: a watch established once at bind time misses a mutation that starts after the watch is set up but finishes before the affected run's own drift check would have caught it in a per-run design, and a long-lived watch handle held per session multiplies with the number of concurrently bound sessions for no benefit over a stat that already runs once per run.
- **Re-run the full `observeProfile` probe on every `startRun`, and skip the cheap digest step entirely.** Rejected: `observeProfile` spawns a real subprocess per bound language on every call, turning every run into two extra process spawns even when nothing changed — the digest check exists precisely to make the common no-drift case cost one `stat`+`readFile` instead.
- **Append the re-observed `invalid` revision for a drift check too, matching `installPackages`.** Rejected: `bindEnvironment` refuses to rebind once a session has any run, so this would convert a transient "the prefix is busy right now" into a permanent dead session — the exact failure mode the fix exists to close.
- **Re-observe first, then materialize scratch only for a confirmed rebind.** Rejected: it leaves the probe or install that re-observation runs with no scratch directory behind it, and defers `materializeSessionScratch`'s idempotent work to a point where it would need to run again regardless of whether scratch already existed from the pre-drift path.
- **Extend this change to also refresh desktop's `applied.json` on a mid-session drift.** Rejected for this PR: it changes desktop's own on-disk provisioning contract, a decision separate from the Runtime's in-session drift detection, and folding it in here would couple an unrelated surface to this fix's review and rollback unit.
- **Gate `install_science_packages` behind an approval prompt as part of this fix.** Rejected: the tool's approval status was already an open, undocumented question before this change; the drift fix makes the tool's side effect visible to other sessions rather than making it more dangerous, so it does not by itself justify adding a gate. The existing no-approval behavior is documented as-is, with its rationale, rather than changed.

## Consequences

Every `run_python`/`run_r` call now pays one extra `stat`+`readFile` against `conda-meta/history` for each bound language, before the pre-existing `assertIdleAppliedEnvironment` and scratch/profile work. A session whose shared prefix drifted mid-session sees its next run either succeed after an invisible re-bind (kernel restart, reason `environment-rebound`, exactly the wording `run_python`/`run_r` already use for every other restart cause) or fail loud with `ENVIRONMENT_NOT_READY` if the prefix is not currently usable — never a silent continuation against a stale binding. `conda-meta/history` only records conda/micromamba transactions: a manual `pip install` or `install.packages()` against the shared prefix, done outside the product, is not conda's own transaction log and is not detected by this mechanism; this gap is recorded in `packages/science/science-runtime/README.md`'s Known Limitations alongside the pre-existing per-run-not-per-import scope note it replaces.

## Testing

`packages/science/science-runtime/tests/environment.spec.ts` covers `prefixHistoryDigest`: a stable digest for unchanged content, a different digest after a content change, a missing history file, and history as a directory, alongside the existing `staticInterpreter` TOCTOU coverage the refactor preserved by splitting a `stat` mock and an `identityStat` fault slot into the shared fixture. `packages/science/science-runtime/tests/drift.spec.ts` (new) drives real `startRun` calls against `tests/harness.ts` fixtures and mutates `conda-meta/history` on disk between them: a Python-side drift that re-binds and restarts the kernel with a strictly higher epoch and an `environment-rebound` end reason; the same for an R-only profile, to pin that `selectBinding`'s language choice is exercised; no drift producing no re-bind and no restart (same epoch); a drift into an unusable prefix rejecting with `ENVIRONMENT_NOT_READY` while asserting no new `science/environment-bound` event was appended (the B8 regression lock); and history-as-a-directory routing through the same drift path as a missing file rather than surfacing an unclassified exception. `packages/science/tool-science/tests/tool-science.spec.ts` adds a real-prefix-mutation test proving `formatRunResult`'s `kernel restarted (environment re-bind)` line appears for a drift detected on someone else's install, not only for the pre-existing manually-appended-rebind case it already covered. The keyless `science-tools` headless snapshot (`examples/headless-agent`) is unaffected: its fixture writes `conda-meta/history` once and never mutates it again, so the digest it records at bind time and the digest `startRun` reads on every later call stay equal throughout that scenario, and the existing `environment re-bind` wording it already recorded from `installPackages`'s revision bump remains the only source of that line — the test was run and passed unchanged as evidence.
