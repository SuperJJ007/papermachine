# Agent Note：GUI ACL runner 持有后代进程共享的控制台

Status: implemented

[English](2026-09-09-gui-acl-runner-console.md) | 中文

## 问题

打包后的 Electron 可作为 Node 运行 ACL 包装进程，但自身没有控制台。此时在受限令牌下创建控制台子系统进程，会在 DLL 初始化时以 `0xC0000142` 失败。相同的 Python 和 R 可执行文件直接启动正常，Science 却将解释器探测判为 invalid。只从 CLI 启动的 runner 测试继承了控制台，无法发现这条桌面路径。

## 决策

runner 在创建受限子进程前建立控制台所有权。已有控制台或伪控制台保持不变。是否已关联控制台由 `GetConsoleCP` 判断，其中包括 `GetConsoleWindow` 返回 null 的无窗口控制台；仅凭窗口句柄不能判断是否可以分配控制台。没有控制台的 runner 用自身令牌分配控制台、隐藏窗口，并恢复继承的标准句柄。控制台由进程持有到退出。分配或句柄恢复失败时不创建子进程，沿用现有 runner 失败诊断。

子进程仍先以挂起状态创建，加入 job 后才执行。令牌限制、授权、环境选择、继承的管道字节和退出码转发保持不变。[受限令牌沙箱决策](../feature/2026-08-08-windows-acl-restricted-token-sandbox.zh.md) 继续拥有这些安全约束；本记录补充 GUI 启动的前置条件。

Science 探测失败会持久化。在首次 run 记录之前，加载失败绑定后的首次 prompt assembly 会用当前 Runtime 重新观测。Session 的 seed 边界与后续环境事件共同判断当前生命周期是否已重试，无需额外的重试缓存。已 applied 的绑定和已有 run 的 session 保持不变。修复后的桌面应用因此可以重新使用执行前探测失败的 session，而无需删除历史。

## 考虑过的替代方案

添加 `DETACHED_PROCESS` 可以让直接 Python 子进程启动，但 Conda R 启动器创建下一层控制台子系统进程时可能不传递该标志。runner 持有的控制台适用于完整后代链。增加令牌权限或关闭隔离会改变安全行为，却没有解决控制台所有者缺失。继承环境变量也不能修复控制台分配。

## 后果

托管子进程启动通过 Node 的 `windowsHide` 选项请求 `SW_HIDE`。没有控制台的 runner 会在自身生命周期内额外持有一个控制台。隐藏新分配的窗口维持后台执行界面；初始窗口可见性需要单独的桌面验证。已有 CLI 控制台的所有权和全部受限令牌规则保持不变。

## 验证

原生验收从没有控制台的 Electron 启动原版与修复版 runner，使用产品的空环境和管道输出。Python 与配置的 Conda R 启动器必须保留 Unicode 探测文本、报告包清单并执行绘图。单元检查保留已有控制台、在分配后恢复全部标准句柄，并拒绝分配、所有权或句柄恢复失败。打包验收包含执行后重开持久会话。
