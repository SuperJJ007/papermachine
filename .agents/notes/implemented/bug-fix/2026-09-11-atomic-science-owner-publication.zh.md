# Agent Note: Science scratch 所有者标记的原子发布

Status: implemented

[English](2026-09-11-atomic-science-owner-publication.md) | 中文

## Problem

同一精确 Session 的两次实体化可能竞争创建同一个 scratch 所有者标记。独占文件创建会先占用文件名，再写入内容。因此，获胜方仍在写入时，另一个操作可能读到空标记，并错误地拒绝正确的 Session 身份。

## Decision

scratch 所有者在标记目录中写入并同步一个唯一的 mode-0600 临时文件，再通过独占硬链接发布完整内容。只有成功发布的操作获得回滚所有权。竞争发布的操作将已有的完整标记与精确 Session 身份进行核对。发布后同步父目录，成功或失败时均移除临时文件名。

标记格式和保留的 scratch 布局不变。已有的不完整或不匹配标记仍然报错；此变更阻止新的不完整发布，不会把损坏的身份凭据视为可复用内容。

## Alternatives considered

**重试读取空标记。** 无法区分正在写入的进程和已经崩溃的进程，也会在身份边界引入时序假设。

**通过重命名覆盖标记。** 替换会覆盖并发所有者的凭据，无法保留独占所有权。

**在单个进程中串行执行。** 独立 Host 进程仍然共享文件系统命名空间。

## Consequences

读取方能看到完整的所有者字节，回滚仍保持独占。发布要求 Harness home 所在文件系统支持硬链接，不支持时拒绝操作。临时名称清理前发生崩溃可能留下私有临时文件，但该文件永远不会被视为所有者标记。

由屏障控制的回归测试在第一位写入者尚未写入内容时暂停它，确认正式标记不存在，让第二位写入者发布，再确认第一位写入者复用完整标记且没有获得回滚所有权。
