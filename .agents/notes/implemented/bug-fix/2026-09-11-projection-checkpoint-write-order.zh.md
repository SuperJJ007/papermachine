# Agent Note：跨日志刷盘保留检查点请求顺序

Status: implemented

[English](2026-09-11-projection-checkpoint-write-order.md) | 中文

## 问题

检查点在进入存储领域写入链前等待会话日志持久化。刷盘耗时不同会颠倒到达顺序：较早的创建检查点可能覆盖较新的轮次结束或释放检查点。领域串行化无法排列尚未到达的工作。

## 决策

缓存在同步阶段快照投影值，并预留每会话队列位置。日志刷盘可以重叠，但每次记录替换都等待自身的持久化屏障和前一次替换。失败的请求向调用方拒绝，同时释放队列供后续修复。冷读取写回使用同一队列。缓存释放先等待这些请求完成，再关闭领域。

## 考虑过的替代方案

**依赖存储领域队列。** 它在每次日志刷盘后才收到写入，无法保留检查点请求顺序。

**刷盘后才捕获取值。** 写入将描述更晚的事件切面，改变调用方请求的检查点，还可能超前于已刷盘日志。

## 影响

不同会话仍相互独立。日志保持权威，存储格式不变。受控延迟刷盘验证较早请求完成后，持久记录仍保留后来的检查点；已有恢复用例继续覆盖写入失败容忍和模式拒绝。
