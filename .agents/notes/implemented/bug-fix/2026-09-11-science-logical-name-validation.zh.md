# Agent Note: Science 逻辑名称与物化路径

Status: implemented

[English](2026-09-11-science-logical-name-validation.md) | 中文

## Problem

成果捕获可能发现持久化解码拒绝的文件系统名称。若在校验前保存该名称，Session 后续投影便无法重建自身成果。解释器执行与成果捕获也具有不同的失败结果。

## Decision

Artifact store 拥有纯逻辑名称校验，供捕获、store 创建/重建及 Science 解码共享。名称保留精确的 Unicode 与路径段。捕获在首次写入 store 或事件之前校验全部符合条件的候选。规范路径包含关系、普通文件检查、符号链接排除与字节上限仍是独立的文件系统检查。

逻辑身份与文件系统物化要求不同。历史设备名与末尾点仍可读取；只有新输入目标拒绝 Windows 设备名和末尾点/空格。身份也拒绝冒号与保留标点，防止盘符与备用数据流路径。编辑基线和光栅声明执行身份查找，不写文件。

捕获失败以安全分类进入普通持久化工具结果，永不改写解释器终态。无效名称拒绝不会保存任何候选；后续文件系统或事件失败可能发生在已有版本提交之后。日志保留内部诊断，模型输出提供对应分类的提示。

## Alternatives considered

**对所有历史名称使用最严格的文件系统语法。** 这会令先前接受的设备名或末尾点无法读取，制造新的恢复失败。

**规范化或重命名捕获文件。** 改写身份会破坏精确查找，还可能合并不同名称。整批拒绝保留原文件，避免校验顺序造成部分发布。

**报告 Python 运行失败或隐藏捕获错误。** 两者都会丢失有意义的结果。现有工具结果日志可以记录捕获诊断，无需增加 Session 格式或事件类型。

## Consequences

两个判断共享路径穿越和编码检查，但有意区别平台别名。[Project store 所有权决策](../architecture/2026-08-25-project-artifact-store.zh.md)仍负责版本身份。

验证覆盖历史解码、物化拒绝、写入前整批原子性、不变的持久化事件回放，以及先成功捕获 Unicode 名称、再拒绝捕获的可运行录制 Science 会话。POSIX 失败 fixture 创建 Windows 无法创建的 ADS 风格名称；Windows 改为执行纯校验和输入拒绝测试。私有历史恢复使用隔离副本和本地回复 provider，仅重定位副本 header 的工作目录，保留事件字节。
