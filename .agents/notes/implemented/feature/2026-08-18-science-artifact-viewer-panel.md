# Agent Note: Science artifact viewer panel

Status: implemented

English | [中文](2026-08-18-science-artifact-viewer-panel.zh.md)

## Problem

The Science Details entry rendered as a resident dashboard: an always-visible Environment strip, an ordered Runs list, an artifact gallery/detail toggle with a version rail, and a header-triggered lightbox — plus a separate wide `conversation.view` tab (`science.provenance`) for the four-part provenance bundle (code, execution log, conversation turn, environment). Opening Details meant scanning a status page before reaching any one chart; reaching provenance meant leaving the Details column for a full center-column tab, and getting back to a different chart meant returning through the gallery. Nothing in the panel modeled "the artifacts I have open right now," so working across two chart versions at once had no persistent home.

## Decision

The Science Details entry (`ui-science`'s `conversation.details.view` id `science`) is now an artifact viewer, not a dashboard. A top tab strip holds one tab per opened logical chart; clicking a transcript `save_chart` row opens or activates that chart's tab at the exact version the row names. The active tab's content view shows an in-panel toolbar (title, a `‹ vN ›` version stepper across that chart's durable versions, provenance/download/maximize/close-tab controls) above the dispatched content — today one image renderer, keyed by the chart's durable attachment media type, so a later non-image artifact phase adds a case without touching the tab strip or toolbar. With no open tabs the viewer shows its landing view: a gallery of every logical chart's latest version (opening one opens its tab) and the latest Outcome below it.

Provenance is an in-panel drill-in, not a separate registration: the toolbar's "Provenance" control switches the active tab's `view` to `'provenance'`, rendering a breadcrumb (`<chart title> › Provenance`) over four sub-tabs — Code, Execution log, Messages, Environment — that show one section at a time. `ScienceArtifactProvenance.tsx` carries the same resolution logic `ScienceProvenanceView.tsx` had (code from the run's tool-call args by `toolCallId`, execution log text plus the projection's durable byte counts/truncation, the environment revision as JSON with the superseded-revision fallback), renamed "Conversation" to "Messages" and kept it a summary-plus-jump, never a message replay. The former `conversation.view` registration (`science.provenance`, dynamically registered/disposed as the current session's `agentPreset` crossed the Science boundary) is deleted along with `ScienceProvenanceView.tsx`; there is no more session-gated dynamic registration in this package.

The former dashboard's Environment strip and Runs list are gone outright — not relocated as a resident section anywhere. Environment facts live only in the provenance drill-in's Environment sub-tab, scoped to one artifact's run, with the exact same JSON-plus-superseded-revision-fallback behavior the provenance view always had. There is no replacement session-wide "environment not applied" notice, because that notice belonged to the deleted strip specifically and a session with no artifact open has nothing to drill into; the two notices that predate the strip (missing projection support, unbound) are unrelated to it and are unchanged. The Outcome section moves to the landing view rather than gaining a pseudo-tab, since — unlike a chart — it carries no version history or provenance of its own to navigate.

The selection store (`selection-store.ts`) is now an open-tabs model: an ordered `openArtifacts` list (one entry per logical chart, each carrying the version that tab currently shows), `activeChartId`, one `view` (`'content' | 'provenance'`) and one `provenanceSubTab` (not per-tab — activating a different tab always returns to `'content'`; the sub-tab choice is a sticky preference), and `lightboxOpen`. A tab's shown version is never a second field: it is always read off the matching `openArtifacts` entry. Every action (`openTab`, `activateTab`, `closeTab`, `setTabVersion`, `setView`, `setProvenanceSubTab`, `setLightboxOpen`) maintains one invariant — `activeChartId` is `null` iff `openArtifacts` is empty, otherwise it names an entry in `openArtifacts` — proven directly in `selection-store.client.spec.ts` and relied on (via a non-null assertion with a comment citing that proof) to keep the viewer's own render code free of a dead defensive branch. The store is not `localStorage`-persisted (unchanged from before this redesign): open tabs and the active view survive a Details-column close/reopen or a session switch-and-back within one page load, through the framework's own per-(handle, session) store cache, independent of `ui-layout`'s force-close-on-session-switch behavior — not across a page reload.

`ScienceArtifactHeaderActions.tsx` and the keyed `conversation.details.header.actions` registration for key `science` are deleted: both former controls (provenance, expand) now live inside the entry's own toolbar, which is the entry's own body content, not the shell's shared header row. `DetailsPanel`'s own header keeps showing only the entry-level chrome (title, close); the toolbar's per-artifact chrome is a level lower, inside the panel body.

One ui-conversation change was required: the Messages sub-tab's jump-to-transcript action needs the same one-shot inspect-and-reveal handoff `ConvViewOwnerProps.inspectCall` gives `conversation.view` entries, but `DetailsViewOwnerProps` (the owner share for `conversation.details.view` entries) carried nothing. `DetailsViewOwnerProps` gains a required `inspectCall: (callId: CallId) => void`; `DetailsPanel.tsx` supplies it to the routed entry from the same `store: chatStore` share it already holds for its header-actions dispatch, with the identical write (`actions.setInspect({ callId }); actions.setView('trajectory')`) `ConversationSession.tsx` gives `conversation.view` entries — two owners supplying the same write pattern to their respective slot kind, not one importing the other. Because the field is required (not optional — an always-supplied capability should not carry a hypothetical undefined case into the component that consumes it), every existing hand-built `conversation.details.view` props object needed it too: `ToolDetailsView`'s own test fixtures in `ui-conversation` and every card spec in `ui-tool` that renders `ToolDetailsView` directly (`diff-card`, `read-card`, `search-card`, `terminal-card`, `web-card`) gained a no-op `inspectCall`.

## Alternatives considered

**Keep provenance as a separate `conversation.view` tab.** Rejected: the redesign's brief was an in-panel drill-in reachable from the toolbar, matching a tabbed artifact viewer rather than a second wide surface; the session-gated dynamic registration it required (present only for a Science session, since a tab's list membership is a framework-unfiltered static ledger) added machinery a same-entry drill-in does not need at all.

**Make `DetailsViewOwnerProps.inspectCall` optional to avoid the `ui-tool` test ripple.** Rejected: the capability is unconditionally supplied by the one real owner (`DetailsPanel`) for every entry, so an optional type would push a defensive undefined-check into `ScienceArtifactProvenance` for a case that cannot occur in production — the "trust the interface at a typed same-process boundary" rule cuts the other way here. The ripple was seven test files gaining a one-line no-op prop, not a design cost.

**Keep a resident session-wide Environment strip alongside the drill-in.** Rejected: it was the surface the redesign's brief named for removal, and duplicating the same facts in two places (a resident strip plus a per-artifact drill-in) would create two things to keep in sync for one fact.

**Give the Outcome section its own pseudo-tab in the tab strip.** Rejected: the tab strip's one job is "open artifacts, one per logical chart, each independently closeable and steppable through versions" — Outcome has no version history and no provenance to navigate, so it does not fit that model, and a pseudo-tab would need special-casing everywhere the real code assumes a tab names a chart. A landing-view section costs no extra chrome and the transcript's own `publish_outcome` row remains the primary way to reach a specific revision.

**Let a stepper button's `onClick` guard against firing while `prev`/`next` is undefined.** Rejected once `disabled` already blocks activation: a runtime guard inside the handler is an unreachable branch the coverage gate correctly flags — the fix is not disabling the guard's `disabled` state, it is omitting the handler entirely (`onClick={prev === undefined ? undefined : () => {...}}`) so every remaining branch is a real click.

**Prove the toolbar's download control with a real Chromium download event in the web e2e scenario.** Rejected for this change: headless download handling adds sandbox/CI fragility disproportionate to what it would prove beyond the jsdom unit coverage (anchor `href`/`download`/`click`, both filename branches, the swallowed-rejection path) already exercises exactly. The e2e scenario clicks the control and asserts no page error instead.

## Consequences

The panel is smaller to reason about per screen (one artifact's toolbar and content, or one drill-in section, never everything at once) at the cost of Environment/Runs no longer being visible without opening a chart's provenance — acceptable because neither fact was actionable without an artifact to relate it to. The tab strip and per-tab version stepper are new persistent state a user can lose track of (multiple chart tabs open across a long session); there is no "close all tabs" affordance yet, matching how a real browser tab strip works but unlike the old single-selection model, which could never accumulate the same way. The content dispatch's media-type `switch` is the one seam the redesign was asked to leave open for non-PNG artifacts; nothing else about the tab strip, toolbar, or store needs to change when that phase lands. `DetailsViewOwnerProps.inspectCall` is now part of every `conversation.details.view` entry's contract, not only Science's; a future entry gets the same jump-to-transcript capability for free.

This note's Decision section supersedes the "The artifact panel — Details column" and "The provenance view — conversation view tab" sections of [Science artifacts — versioned figures carrying their provenance](2026-08-18-science-artifacts.md), an implemented note in the same feature line whose own text for those two sections now states this redesign's outcome directly (version rail, header-actions provenance/expand controls, the session-gated `conversation.view` tab — the original design those sections proposed and this redesign replaces). That note's Host-side projection-linkage and package-inventory decisions are unaffected and remain current.
