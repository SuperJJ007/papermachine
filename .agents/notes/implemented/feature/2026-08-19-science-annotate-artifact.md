# Agent Note: retire `save_chart`, add metadata-only `annotate_artifact`

Status: implemented

English | [中文](2026-08-19-science-annotate-artifact.zh.md)

## Problem

Auto-capture ([Science Runtime auto-capture of run-written files](2026-08-19-science-auto-capture.md)) durably saves every eligible run-written file before the model's next turn. `save_chart`'s "import a PNG from a successful run's artifact directory" contract became dishonest the moment that shipped: the Runtime had already captured the file, so asking the model to also name a `run_id`/`artifact_path` and re-import it duplicated work the Runtime already did, added a step the model could get wrong, and only ever accepted PNG. The model still needs a way to mark curation — "this is the file that best demonstrates my result" — but that is a metadata operation, not a byte-moving one. `get_science_state`'s `charts` field and `run_python`/`run_r`'s result text also stayed PNG-only and receipt-free respectively, both flagged as pending follow-up work in the auto-capture note.

## Decision

**`ScienceRuntime.annotateArtifact`** (`science-runtime/src/index.ts`) replaces `commitChart`. It resolves the named logical artifact's exact `version` (or its latest) against the live projection and re-commits the **same** content-addressed `attachment` as the next contiguous version, carrying the supplied `title`/`caption` and `origin: 'model'` — never touching the filesystem or `ctx.attachments`. Its only failure beyond the shared pre-publication ones is `ARTIFACT_NOT_FOUND` (`logicalName` or its named `version` does not exist). `CommitScienceChartRequest`, and the `SOURCE_RUN_NOT_SUCCESSFUL`/`INHERITED_RUN`/`IMAGE_TYPE_NOT_ALLOWED` error codes that existed solely to serve the byte-import path, are deleted rather than kept as unreachable code — pre-release, no shim.

**Fully synchronous, still `Promise`-returning.** `annotateArtifact` has no `await` (metadata-only), which the `require-await` lint rule flags on an `async` function. Removing `async` outright breaks the calling convention every other `ScienceRuntimeService` operation relies on: a caller doing `await scienceRuntime.annotateArtifact(...)` outside its own `async` wrapper needs every failure — including `assertSession`'s own, which ran before any lease existed — to be a Promise rejection, not a synchronous throw. The method keeps a nested `try`/`catch` and returns `Promise.resolve(artifact)`/`Promise.reject(...)` by hand instead of relying on `async`'s automatic wrapping.

**`chart.ts` → `artifact-file.ts`.** `resolveArtifactFile`, `validateArtifactPathSyntax`, `listArtifactEntries`, and the diagnostic-listing helpers existed only to serve `commitChart`'s "resolve one named file inside a run's artifact directory" need; annotate_artifact never resolves a file, so they are deleted with it. Only `walkArtifactFiles`/`readBoundedFile` (capture's own dependencies) remain, in a renamed file whose docstring no longer describes chart-specific behavior. The two now-dead Config fields, `artifactDiagnosticMaxEntries`/`artifactDiagnosticMaxBytes`, are removed from `config.ts`, its schema, `resolveConfig`, and the Runtime's private fields.

**`science-session/src/transition.ts`'s curated-origin tool-name allowlist** (`requireToolCall(..., ['save_chart'])`) becomes `['annotate_artifact']` — the one durable-model line that had to change alongside the tool rename, since a `science/artifact-saved` event with `origin: 'model'` is only valid when it names the current curation tool.

**Tool surface** (`tool-science`): `save-chart.ts`/`chart-schema.ts` are replaced by `annotate-artifact.ts`/`artifact-schema.ts`. `scienceArtifactSchemaProperties` renames `chartId` to `artifactId`, adds `origin`, and widens to the full set of fields both value builders share (`mediaType`/`bytes`/`width`/`height`/`createdAt`), matching the durable field names. `artifact-schema.ts` also exports `scienceArtifactValueFields`, the shared identity/curation/source/media flattening both value builders draw from: `artifactReceiptFromArtifact` (`annotate-artifact.ts`) spreads it and appends its own trailing fields (`attachmentId`/`attachmentName`); `stateArtifact` (`state.ts`) destructures it and reconstructs the key order instead, since its pinned schema interleaves `environmentRevision`/`environmentFingerprintPreview` between `runId` and `mediaType` — a position a trailing spread cannot reach. `get_science_state`'s `stateChartSchema`/`charts` become `stateArtifactSchema`/`artifacts`; `width`/`height` are optional (present only for an image attachment); the `hasImageAttachment` filter this tool used to narrow to image-only is gone — every captured/curated artifact is now listed regardless of media type. `history.chartVersionsOmitted` renames to `artifactVersionsOmitted`.

**Run-result capture receipt.** `runOutputSchema` gains `capturedArtifacts` (artifactId/logicalName/version/mediaType/bytes/optional width+height), `captureSkippedOversizedCount`, `captureTruncatedPerRun`, `captureTruncatedPerSession` — present only when `ScienceRunResult.capture` is defined (the synchronous/quiescent settlement path). `formatRunResult` derives a trailing `` Captured N artifacts: `name` vV (mediaType[, WxH], size), ... `` line, plus one line per nonzero skip/truncation flag, purely from these schema fields — never from a live re-read of the session — so the receipt text cannot drift from the `science/artifact-saved` events it describes.

**`annotate_artifact`'s presentation stays image-only for now.** `presentation.ts`'s `scienceArtifactPresentation` (renamed from `scienceChartPresentation`) still projects only `ScienceChartPresentation` — the pre-existing, image-required Client card shape — when the curated attachment has `width`/`height`; curating a non-image artifact returns `null`, which `ScienceChartRow.tsx`'s existing `parsePresentation` already treats as "no card, fall back to plain text row." This is a deliberate interim choice: `null` is the graceful degradation already built for an unrecognized presentation value, not a new failure mode. `ScienceChartPresentation`'s own docstring now says this explicitly. [per-media-type artifact viewer rendering (csv/json/md/png)](2026-08-19-science-viewer-file-types.md) generalizes `ui-science`'s per-type rendering and renames `ScienceChartPresentation` to `ScienceArtifactPresentation`.

## Alternatives considered

**Keep `commitChart`'s error codes/diagnostic machinery as unreachable code, in case a future change needs file-resolution again.** Rejected: nothing currently calls it, and the pre-release stance prefers deleting dead code over speculative retention — a future change can reintroduce a file-resolution helper against the actual need it has then.

**Generalize `ScienceChartPresentation` to `ScienceArtifactPresentation` here.** Rejected: `ui-science` is a separate package this decision does not touch; [per-media-type artifact viewer rendering (csv/json/md/png)](2026-08-19-science-viewer-file-types.md) owns the presentation rename and per-type dispatch. Returning `null` for a non-image curation is a correct, working interim state — not a half-finished type.

**Route the `annotate_artifact` receipt-listing count through a live re-derivation from the session log inside `render()`.** Rejected: `render()` only receives the tool's own already-persisted `value`, and re-deriving from `session.events` there would require plumbing the session into a pure projection function. Schema-carried fields (already the pattern `chartReceiptSchema`/`stateChartSchema` used) keep `render` a pure function of `value`.

## Consequences

**Real Conda acceptance** (`science-runtime/tests/real-acceptance.ts`) no longer calls `commitChart` to produce its PNG artifact: the run itself already writes `real-chart.png` under `SCIENCE_ARTIFACT_DIR`, so auto-capture produces version 1, and the acceptance script calls `annotateArtifact` to curate it into version 2 before the existing attachment-readback and Outcome-citation checks.

**`apps/web/tests/science-preset.snapshot.ts`** now drives the same csv/json/md/png-writing `FakeSubprocess` pattern the keyless snapshot uses, asserts the run result's `capturedArtifacts`, and calls `annotate_artifact` in place of the two `save_chart` calls (contiguous versioning is proven by two curation calls on the same auto-captured artifact instead of two imports). Its `get_science_state` assertion also fixes a latent `chartCount`/`chartVersionCount` naming bug — the durable `ScienceProjectionMetrics` fields have been `artifactCount`/`artifactVersionCount` since [`science/artifact-saved` replaces `science/chart-saved`](2026-08-18-science-artifact-saved-event.md), so the old assertion's field names never matched the tool's actual JSON output.

**Keyless snapshot** (`examples/headless-agent/science-tools.cordis.snapshot.yml` and its drivers): `science-runtime-fixture.ts`'s `FakeSubprocess` now writes `summary.csv`/`meta.json`/`notes.md`/`plot.png` per run (one file per allowlisted auto-capture media type); `science-mock-llm.ts` drives `get_science_state` → `run_python` → `annotate_artifact` → `publish_outcome` → `get_science_state`, asserting five `science/artifact-saved` events (four auto, one curated, four distinct artifact identities) instead of the prior two `save_chart` calls on one identity. `model-view.expected.json`/`stream-json.expected.jsonl` were regenerated with `DSH_SNAPSHOT=refresh` (keyless — no API key needed, since this scenario's model is a scripted deterministic adapter) and reverified stable under a plain replay.

**Test coverage.** `science-runtime/tests/annotate.spec.ts` (new file): curates the latest version reusing attachment/provenance, a non-image artifact, an exact named (non-latest) version, a curation chain, an unknown `logical_name`, and an unknown `version` with the available versions in the diagnostic. `science-runtime/tests/artifact-file.spec.ts` (renamed from `chart.spec.ts`, gutted to the two surviving exports): walk ordering, symlink exclusion, the hard walk cap, and bounded-read behavior including the exact-boundary case. `tool-science/tests/tool-science.spec.ts`'s `save_chart` describe block becomes `annotate_artifact`, seeding auto-captured artifacts directly (through a real `ctx.attachments.saveImage`/`saveText` call plus a hand-built `origin: 'auto'` event, since the local `FakeSubprocess` fixture never writes real files) rather than through `writeArtifact`+`save_chart`. Every touched `src/` file holds per-file 100% coverage.

**Deferred to, and closed by, [per-media-type artifact viewer rendering (csv/json/md/png)](2026-08-19-science-viewer-file-types.md)**: `ui-science`'s `hasImageAttachment` filters in `ScienceDetailsView.tsx`/`ScienceOutcomeRow.tsx`, its `ScienceChartRow.tsx` toolview key (`save_chart`, unreachable since no tool by that name existed — dead but compiling, not user-visible since no `save_chart` tool call could occur), and `ScienceChartPresentation` → `ScienceArtifactPresentation` all remained exactly as [Science Runtime auto-capture of run-written files](2026-08-19-science-auto-capture.md) left them until that note generalized the viewer to every captured media type and re-keyed the transcript rows to `run_python`/`run_r`/`annotate_artifact`.
