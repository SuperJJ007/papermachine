# Agent Note: Science Runtime auto-capture of run-written files

Status: implemented

English | [中文](2026-08-19-science-auto-capture.zh.md)

## Problem

Before this change, a run's output became a durable Science artifact only if the model separately called `save_chart` on a PNG. Every other file a `run_python`/`run_r` call wrote under `SCIENCE_ARTIFACT_DIR` — a CSV table, a JSON summary, a Markdown report, a plain-text log — was invisible to the session log unless the model happened to import it by exact path, and `save_chart`'s `SOURCE_RUN_NOT_SUCCESSFUL` gate meant a failed run's partial output was never capturable at all.

## Decision

The Runtime itself walks each run's artifact directory and durably saves every eligible file as a versioned artifact, with no model step required.

**Capture hook.** `ScienceRuntime.settlePublishedRun` (`science-runtime/src/index.ts`) gained a private `captureAfterFinish` method, called immediately after each of its two `science/run-finished` append sites (the synchronous/quiescent return path, and the non-quiescent branch's `.then()` continuation) and before the lease releases. It fires for every terminal `status` — `success`, `failed`, `timed-out`, `cancelled` — never for a replay-only `interrupted` run, since those have no real settlement event to hook.

**Walk and filters.** A new `science-runtime/src/capture.ts` module exports `captureRunArtifacts`, reusing `walkArtifactFiles` (now exported from `chart.ts`) and `readBoundedFile`. It adds a fixed extension allowlist (`.csv`, `.json`, `.md`, `.png`, `.txt`, mapped to their declared media type) and a dotfile/dot-directory segment exclusion, neither of which is Config — they mirror the existing precedent that `ImageAttachmentLimits.mediaTypes` is a frozen constant, not a Loader-exposed knob.

**Versioning and dedup.** `logicalName` is the file's path relative to `runScratch.artifacts`, forward-slash form (`plots/loss.png`); a file reappearing at the same relative path in a later run is the next version of the same logical artifact. Dedup does not hash the candidate file itself: it always calls `saveImage`/`saveText` (idempotent, content-addressed) and compares the *returned* opaque `attachmentId` against the latest existing version's — an equality check between two values of the same branded type, never inspecting either string's internal structure, unlike locally hashing the candidate file and comparing to `attachment.attachmentId`, which would license exactly the format-peeking `packages/AGENTS.md` forbids ("opaque cross-boundary ids are branded, never bare string"); comparing two fresh, same-type references sidesteps that without adding a redundant local hash pass.

**Fold cost.** The walk replays the session's Science fold once (`foldScience(session.events)`) rather than once per eligible file: each successful `session.append('science/artifact-saved', …)` advances that same accumulator in place (`applyScienceEvent`), and `projectScienceFold` derives the public projection on demand from it — the incremental composition `@deepseek-ai/dsh-science-session`'s `replayScience` itself runs in one shot, now exposed from that package's root for this exact cross-package caller.

**Three new Config fields** on `dsh-science-runtime`, following the existing `artifactDiagnosticMax*`/`packagesMax*` pattern exactly (`DEFAULT_*`/`MIN_*`/`MAX_*` constants, a `.step(1).min().max().default()` schema entry, a matching manual `resolveConfig` check, `assertKnownKeys` covering the new names): `captureMaxFileBytes` (default 5 MiB, 1–50 MiB), `captureMaxFilesPerRun` (default 50, 1–1,000), `captureMaxArtifactVersionsPerSession` (default 500, 1–10,000). An oversized file is skipped and counted (`skippedOversizedCount`); a per-run/per-session cap truncates the remaining eligible files and sets a flag (`truncatedPerRun`/`truncatedPerSession`) — never a run failure, and never a thrown error even when the deployment's own `imageLimits`/`textLimits` byte cap is narrower than `captureMaxFileBytes` (an `AttachmentError` from `saveImage`/`saveText` is caught and counted as oversized).

`ScienceRunResult` gained an optional `capture?: CaptureRunArtifactsResult` field, populated only on the synchronous/quiescent path (the non-quiescent branch's own capture result has no caller reading it synchronously, symmetric to that branch's terminal fact already being invisible to the model's current turn); [retire `save_chart`, add metadata-only `annotate_artifact`](2026-08-19-science-annotate-artifact.md) turns this into `run_python`/`run_r`'s appended receipt text. `CaptureRunArtifactsResult.appendFailed` flags a `session.append` rejection that stopped the walk early; `captureAfterFinish` logs every capture failure rather than absorbing it silently — `warn` for an environmental fault (the artifact directory disappeared, a permission or disk error), `error` for anything else, since that residual class is a defect in the Runtime's own capture logic. Neither class fails the run.

## Durable-model prerequisites the union widening completed

[`science/artifact-saved` replaces `science/chart-saved`](2026-08-18-science-artifact-saved-event.md) and [A parallel Text attachment family beside the image family](2026-08-18-attachment-text-family.md) delivered the `science/artifact-saved` event, `origin`/`title`/`caption` fields, and the parallel attachment Text family end to end — but not the union widening or the fold-level relaxations auto-capture needs; both notes flagged these as deferred. Three gaps had to close before capture could compile or pass its own fold-level invariant:

1. **`ScienceArtifactVersion.attachment: ImageAttachmentRef | TextAttachmentRef`** (`science-session/src/types.ts`), with the matching `codec.ts` schema split (`imageAttachmentSchema`/`textAttachmentSchema`/`artifactAttachmentSchema` union) and `projection-schema.ts` (`validImageAttachment`/`validTextAttachment`).
2. **`applyArtifactSaved`'s source-run gate widened from `status !== 'success'` to `status === 'running' || status === 'interrupted'`** (`transition.ts`) — a failed/timed-out/cancelled run's captured file must fold successfully, since capture fires on every terminal status.
3. **Origin-based provenance, not one `requireToolCall` path for every artifact.** The existing `requireToolCall` marks a referenced tool call "consumed" (`state.consumedToolCallSeqs`) so it cannot back a second Science fact — correct for a curated save (each `save_chart` call authorizes exactly one commit) but wrong for capture: the run's own `run_python`/`run_r` toolCallId is *already* consumed by `applyRunStarted`, and one run can produce many captured files. `applyArtifactSaved` now branches on `artifact.origin`: `'auto'` requires `artifact.toolCallId === source.toolCallId && artifact.requestHeaderSeq === source.requestHeaderSeq` (inherited, already-proven identity, no fresh lookup, no consumption — many files share one run's call); `'model'` still calls `requireToolCall(..., ['save_chart'])` exactly as before, consuming a fresh call once.
4. **`logicalName`'s decoder grammar widened from a single `SAFE_ID` segment to `SAFE_LOGICAL_NAME`** — forward-slash path segments, each the existing safe-id grammar — since a captured file's logical name is a real relative path (`plots/loss.png`), not a flat name.

These durable-model changes complete the union widening [`science/artifact-saved` replaces `science/chart-saved`](2026-08-18-science-artifact-saved-event.md) deferred, landing here because auto-capture is the first caller that needs them. `save_chart`'s existing model-curated path is unaffected: its default fixture and behavior (`origin: 'model'`, a fresh `save_chart` tool call) hit the unchanged `else` branch.

**Compile ripple from the union, resolved by [retire `save_chart`, add metadata-only `annotate_artifact`](2026-08-19-science-annotate-artifact.md).** Here, `tool-science/src/save-chart.ts` and `state.ts` still assumed `ScienceArtifactVersion.attachment` was always image-shaped, and `state.ts`'s `charts` field filtered `projection.artifacts` to image-attachment versions only pending that later change; `ui-science`'s Details entry and Outcome row carried the matching narrowing one level up. That note retired `save_chart`/`commitChart` in favor of metadata-only `annotate_artifact` and generalized `get_science_state`'s field to `artifacts` (every media type, `origin`, optional `width`/`height`); `ui-science`'s per-type rendering is a further, separately sequenced change (see [per-media-type artifact viewer rendering (csv/json/md/png)](2026-08-19-science-viewer-file-types.md)).

## Async-capture has no separate model-visible notification

The non-quiescent settlement branch injects no model-visible completion fact beyond the durable `science/run-finished` event itself — no system message, no side-channel notification. The durable `science/artifact-saved` events plus the model's next `get_science_state` call are accepted as sufficient for v1; recorded under this package's README "Known Limitations and Deferred Work".

## Alternatives considered

**Hash the candidate file locally for dedup.** Rejected in favor of comparing two opaque `saveImage`/`saveText`-returned references — see above.

**A per-file byte pre-check via `lstat().size` before every read.** Rejected: `readBoundedFile` already bounds memory to `captureMaxFileBytes + 1` regardless of the file's real size, matching `commitChart`'s own precedent (no separate stat-based pre-check there either). Keeping both a stat-based pre-check and a post-read length check would produce one genuinely untestable duplicate branch (the pre-check can never differ from the post-check outcome except via an unreproducible race) for no memory-safety benefit `readBoundedFile` doesn't already provide.

**Replay the complete Session event log fresh on every eligible file inside the walk.** Rejected: quadratic in the session's total event count for no benefit — `foldScience` once plus `applyScienceEvent` per appended event reaches the identical projection incrementally.

**Give `captureAfterFinish` no independent liveness check, relying solely on `captureRunArtifacts`'s own internal `session.append` failure handling.** Kept the outer check anyway (`v8 ignore`d, since it cannot be deterministically raced in a test) as defense-in-depth consistent with every other call site in this file re-verifying `this.ctx.sessions.get(session.id) !== session` before touching a Session.

## Consequences

**Test regression, not caused by capture logic itself.** `run.spec.ts`'s existing "publishes an eventual terminal after the only terminate verb throws but a later observation proves exit" test assumed the lease released synchronously once `science/run-finished` became observable. Auto-capture now runs (async: at least one `readdir`) between that append and lease release in the non-quiescent branch, so the test's immediate retry started throwing `RUNTIME_BUSY`. Fixed by polling the retry's `startRun` call with `vi.waitFor` instead of a bare `await`, with a comment explaining why — the retry's own authorization tool call is computed once, outside the polled closure, so retries do not duplicate session facts.

**Fixture updates for the union widening**, unrelated to capture behavior itself: `tool-science/tests/tool-science.spec.ts`'s chart-history-cap fixture gained `bytes`/`width`/`height` (previously omitted since that test only cared about ordering/omission counts, now filtered out entirely by `state.ts`'s image-only guard without them); two `fold.spec.ts`/`fold-transitions.spec.ts` error-message assertions updated for the renamed rejection text ("must reference a successful prior run" → "must reference a run that reached a terminal status").

**Test coverage.** `science-runtime/tests/capture.spec.ts` (new file, changed file, identical rerun skipped, oversized skipped+counted, per-run/per-session caps, dotfile/extension exclusion, capture on a failed run, deployment admission rejection treated as oversized, a non-filesystem capture failure logged at `error`, a filesystem-coded capture failure logged at `warn`, a `science/artifact-saved` append refusal flagged on the result and logged, none of these failing the run); `science-runtime/tests/environment.spec.ts`'s configuration suite (the three new Config fields' bounds); `science-session/tests/fold.spec.ts`/`fold-transitions.spec.ts` (auto-origin acceptance with inherited provenance, both `||`-operand rejection cases for a toolCallId/requestHeaderSeq mismatch, a text-attachment fold round-trip); `science-session/tests/projection-schema.spec.ts` (a valid text-attachment wire value). Every touched `src/` file in `science-runtime` and `science-session` holds per-file 100% statement/branch/function/line coverage; three narrow `v8 ignore`s mark TOCTOU-style races (a walked file removed or replaced between the walk and its canonical-path re-check; a Session detaching in the exact synchronous window between a re-verified append and the capture call that follows it) that are real but not deterministically reproducible in a test, each with an inline justification.

**Scope note.** This change does not touch `save_chart`'s tool schema, add `annotate_artifact`, or change `run_python`/`run_r`'s result text — [retire `save_chart`, add metadata-only `annotate_artifact`](2026-08-19-science-annotate-artifact.md) covers the tool-surface change and the receipt text. It does not touch any per-media-type viewer rendering either — [per-media-type artifact viewer rendering (csv/json/md/png)](2026-08-19-science-viewer-file-types.md) covers that.
