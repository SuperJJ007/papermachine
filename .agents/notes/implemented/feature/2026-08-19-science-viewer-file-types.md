# Agent Note: per-media-type artifact viewer rendering (csv/json/md/png)

Status: implemented

English | [中文](2026-08-19-science-viewer-file-types.zh.md)

## Problem

Auto-capture (`2026-08-19-science-auto-capture.md`) durably saves every eligible csv/json/md/png file `run_python`/`run_r` writes, and `annotate_artifact` (`2026-08-19-science-annotate-artifact.md`) can curate any of them — but `ui-science`'s artifact viewer, its transcript rows, and the Client-safe presentation type all stayed image-only, filtering every non-image version out of the gallery, the Details entry's content dispatch, and the Outcome row's evidence tile. A captured csv/json/md file was durably logged but invisible everywhere a person would look for it.

## Decision

**Presentation generalizes from one chart to a list of artifacts.** `tool-science/src/types.ts`'s `ScienceChartPresentation` (one image, `kind: 'science/chart'`) is replaced by `ScienceArtifactPresentation` (`kind: 'science/artifact'`, `artifacts: ScienceArtifactPresentationItem[]`) — an item carries `artifactId`/`logicalName`/`version`/`title`/`attachment` (width/height present only for an image), deliberately omitting `caption`/`runId`/`createdAt`: the Client row never read those from the old shape either, and full provenance is one click away through the live `science` projection. `presentation.ts`'s `scienceArtifactPresentation(items)` returns `null` for an empty list, one tagged value otherwise — shared by `annotate_artifact` (always exactly one item) and, newly, `run_python`/`run_r` (one item per file that call's capture walk produced, built from `run.ts`'s `capturedArtifactSchema`, which gained `title`/`attachmentId`/`attachmentName` fields carried for this purpose and never rendered into the model-visible receipt text).

**Two dedicated rows replace the one dead `save_chart` row.** `ScienceChartRow.tsx` is renamed `ScienceArtifactRow.tsx`, generalized to any media type (an image thumbnail via `MessageImage`, or `ArtifactFileTile` — a static icon-plus-extension tile, no fetch — for text), and re-keyed from `save_chart` (a tool that no longer exists; the row was dead code) to `annotate_artifact`. `run_python`/`run_r` get a new `ScienceRunRow.tsx`: since a run's primary content is its rendered text (status/stdout/stderr/capture receipt), this row always renders through the same plain-text fallback card every dedicated row shares (`ScienceToolFallbackRow`, which gained an `after` slot for this), appending one clickable reference chip per captured file when the presentation names any — a compact icon/name/version pill, not a thumbnail, since a run can capture up to `captureMaxFilesPerRun` files at once.

**Content dispatch (`ArtifactContent.tsx`, new).** Extracted out of `ScienceDetailsView.tsx`: an image renders through the existing `MessageImage` "single" variant; a text attachment fetches its decoded bytes through a new `loadText` loader (`science-attachment-loader.ts`'s `createScienceTextLoader`, mirroring `createScienceImageLoader` over `ISession.readTextAttachment` — already-decoded UTF-8, no base64 step) and dispatches again: `text/csv` through a new `ArtifactTable.tsx`, `application/json` through `ui-primitives`' existing `JsonTree` (falling back to preformatted raw text for content that parses to a non-object/array, or fails to parse at all), `text/markdown` through the existing `MarkdownText`, `text/plain` as preformatted text. Every `ScienceDetailsView.tsx` entry point (gallery, tab strip, toolbar) now reads `science.artifacts` directly — the `hasImageAttachment`/`ScienceImageArtifactVersion` filters are gone. The toolbar's maximize control (raster-only) and the toolbar-triggered lightbox render only for an image; download builds a `data:` URI from either loader and names the file from the attachment's own display name, or the logical name (already the captured file's real path, extension included) with the version inserted before that extension.

**`ArtifactTable.tsx`/`csv.ts` are package-local, not `ui-primitives` exports.** A repo-wide grep found no table component anywhere in `packages/client` and no second consumer; `csv.ts`'s parser is hand-rolled (RFC4180-style: quoted fields, embedded commas/newlines, doubled-quote escaping) rather than a dependency, since this is a read-only preview over auto-captured or model-annotated files, never arbitrary untrusted upload — "configurability does not justify an unsupported... public operation set" (`packages/AGENTS.md`) applies the same way to a speculative shared primitive as to a speculative format. A real second consumer is the trigger to promote both into `ui-primitives`, not this one.

**`ScienceOutcomeRow.tsx`'s evidence tile** now distinguishes three cases instead of two: an unresolved citation (`chart === undefined`) still reports "unavailable"; a resolved non-image citation renders `ArtifactFileTile`; a resolved image citation renders its thumbnail exactly as before.

**Locale namespace generalizes from `chart.*` to `artifact.*`/`run.*`/`table.*`.** Pre-release, renamed freely rather than kept alongside a new namespace: `chart.title`/`.open`/`.loading`/etc. become `artifact.*` (used by every media type, not only images); new `run.titlePython`/`run.titleR`/`run.running`/`run.failed`/`run.stopped`/`run.artifacts` serve the Run row; new `table.empty`/`table.sortBy` serve `ArtifactTable`. `details.charts.title`/`.empty` become `details.artifacts.title`/`.empty`; `details.artifact.select` drops the word "chart" ("Open {title}, version {version}", not "Open chart {title}..."). An extension label ("CSV", "JSON", "MD", "TXT") is not localized, the same register as an unlocalized file extension.

**Rendered rows and characters are capped, not the full document.** `format.ts`'s `capForDisplay`/`capTextForDisplay` bound what actually reaches the DOM: `ArtifactTable.tsx` renders at most `MAX_ARTIFACT_TABLE_ROWS` (500) of the sorted rows; `ArtifactContent.tsx`'s JSON tree and `<pre>` text panes cap at `MAX_ARTIFACT_TEXT_CHARACTERS` (100,000) characters — both fixed presentation bounds, not `Config` fields, following the display-cap precedent `ui-trajectory`'s `trajectory-preview.ts` already sets. Each cap that trims content shows a "showing first N of M" notice (`table.truncated`/`artifact.textTruncated`) rather than truncating silently; content past the cap is not otherwise reachable from this viewer (README's Known Limitations).

**One `artifactImageLabels(t)` builder, not three inline copies.** `ArtifactContent.tsx` exports it; `ScienceArtifactRow.tsx`'s row thumbnail and `ScienceDetailsView.tsx`'s gallery tile both import it instead of each independently constructing the same `MessageImageLabels` object.

**An auto-captured file's toolbar shows its name once, not twice.** `capture.ts` sets an auto-captured artifact's `title` to its logical name's basename; when the logical name carries no directory component the two are identical, so `ArtifactToolbar` renders the logical-name line only when it differs from the title.

## Alternatives considered

**Give `annotate_artifact`'s row a list-rendering path too, for symmetry with the Run row.** Rejected: `annotate_artifact`'s presentation always names exactly one item (the tool curates one artifact per call), so a list path would have zero real callers; the asymmetry is explained, not accidental (recorded under Known Limitations).

**Fetch a thumbnail for each Run row reference chip.** Rejected: a run can capture up to `captureMaxFilesPerRun` (default 50) files in one call; a grid of eagerly-loaded thumbnails would be both visually heavy and a burst of loader calls for content the model itself is unlikely to want previewed inline. A compact icon-plus-text chip, opened on click into the full viewer, matches the existing "row is a pointer, viewer is the destination" pattern every dedicated row already uses.

**Add a shared `ArtifactThumbnail` component dispatching image-vs-tile.** Rejected: once non-image thumbnails need no loader call at all (a static tile), the dispatch collapses to a one-line ternary at each of the three call sites (`ScienceArtifactRow`, `ScienceDetailsView`'s gallery, `ScienceOutcomeRow`'s evidence tile); a wrapping component would add a layer for no shared behavior beyond that ternary.

## Consequences

**Model-visible text is unchanged**; only `tool/result.meta` (never sent to the provider) gained fields. The keyless snapshot (`examples/headless-agent/science-tools.cordis.snapshot.yml`) still needed a `DSH_SNAPSHOT=refresh`, because the snapshot's stream-json/model-view goldens capture the full durable event stream, including `tool/result.meta` — reverified stable under a plain replay afterward.

**`apps/web/tests/science-preset.snapshot.ts`** updates its two `annotate_artifact` result-meta assertions from the old `{kind:'science/chart', chartVersion}` shape to `{kind:'science/artifact', artifacts:[{version}]}`.

**`apps/web/tests/science-chart-outcome.e2e.ts`** (pre-existing, real-Chromium): its fixture seeded a `save_chart` tool call and `science/chart` presentation meta directly (bypassing the real tool, so it stayed passing across the tool's rename and eventual removal) — updated here to `annotate_artifact`/`science/artifact` and the "Open {title}..." wording; every redaction assertion (no absolute Host path, no full fingerprint) is untouched. A new sibling scenario, `apps/web/tests/science-artifact-types.e2e.ts`, seeds one `run_python` call whose auto-capture produced one file per csv/json/md/png, drives Chromium through each reference chip, and asserts the sortable table (including a sort click), the JSON tree, rendered Markdown, and the image path, closing with a fresh ARIA golden (`snapshots/science-artifact-types/panel.expected.md`).

**`packages/client/connection/src/client/fixture.ts`'s empty `texts` map is intentionally left unseeded.** Its only consumer (`fixture-commands.client.spec.ts`) never touches attachments, and no dev-server or other test currently exercises `sessions.textAttachment` through this particular fixture world; seeding it now would have no owner or need (`packages/AGENTS.md`). Revisit if a future GUI-journey test starts exercising a text attachment through this fixture specifically.

**Test coverage.** New: `csv.client.spec.ts`, `ArtifactTable.client.spec.ts` (including a direct `compareCells` unit describe for branch coverage independent of `Array.prototype.sort`'s comparator-call pattern, and the row-truncation notice), `ArtifactFileTile.client.spec.ts`, `science-run-row.client.spec.tsx`. Rewritten: `science-chart-row.client.spec.tsx` → `science-artifact-row.client.spec.tsx` (any media type, not only image), `ScienceDetailsView.client.spec.tsx` (per-type content dispatch, non-image gallery/download/no-maximize cases, unmount-during-load races for both the resolve and reject path, the CSV row cap, the oversized-JSON/oversized-plain-text character cap, and the toolbar's title/logicalName collapse), `science-outcome-row.client.spec.tsx` (the new non-image-but-resolved tile case), `real-composition.client.spec.tsx` and `browser-plugin.client.spec.ts` (the four toolview keys, `loadText` in the Details inject face). `tool-science/tests/tool-science.spec.ts` gained a `scienceArtifactPresentation` describe block and `run_python` presentationMeta unit tests (retrieved directly via `ctx.tools.get('run_python')?.output.presentationMeta` to cover the `capturedArtifacts` absent/present and multi-item branches without needing a real non-quiescent settlement). `apps/web/tests/science-artifact-types.e2e.ts` asserts the full `condaHistorySha256` never reaches the rendered panel, mirroring `science-chart-outcome.e2e.ts`'s existing assertion for the same field. Every touched `src/` file holds per-file 100% coverage.
