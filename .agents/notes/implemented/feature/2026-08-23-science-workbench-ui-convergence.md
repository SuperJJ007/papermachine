# Agent Note: Science workbench UI convergence

Status: implemented

English | [中文](2026-08-23-science-workbench-ui-convergence.zh.md)

## Problem

Science artifacts were reachable through a session Details action, but the surrounding product still treated conversation as the primary workspace. Project files and Outcomes lacked stable destinations, model-assisted edits used a second instruction composer inside the artifact viewer, and the engineering Trajectory view was the only event-level account available from the conversation view ring. These splits duplicated navigation and made selected chart elements disappear from the user's main request context.

The artifact-view modes and session-wide Trace placement described below are superseded by [Artifact object state and turn-local causality](2026-08-25-artifact-object-state-and-turn-local-causality.md). The Files/Outcomes destinations, composer ownership, shell palette, toggle placement, and direct-edit decisions remain current.

## Decision

The Web shell presents Science Files and Outcomes as distinct destinations above the session browser only while a Science Session is current. Settings remains fixed at the sidebar foot. Files opens the artifact stage; Outcomes opens a separate Outcome-only route. The complete three-column Science workbench uses the light document palette even when the application preference is dark: `AppFrame.module.css`'s `.frame[data-science-session]` rule resets every alias/specific token whose light and dark values differ in `design-platform.css`, and a coverage test parses both stylesheets and fails the moment a new differing token has no light reset here. Non-Science Sessions receive none of the Science destinations, Trace tab, composer accessory, kernel dock, or the `session`-mode welcome-page Files action — that action reads the current (possibly still-blank) Session's own `agentPreset`, the same signal every other Science surface gates on, rather than showing for any preset once no Session has started.

The desktop app forces Science as the product default (its overlay sets `agent-presets`' default and disables `ui-agent-preset`), so the generic Web session-gated placement above has nothing to distinguish there: a person opens the desktop app straight onto the workspace-selection screen, before any workspace is picked and before any Session exists, and the Files toggle must already be visible at the far top-right — the same corner ui-conversation's `conversation.page.utilities` slot already occupies unconditionally, since `ConversationRoot` (this slot's owner) mounts session-maybe and renders that slot regardless of Session state. `ui-science`'s Host half validates a `toggleScope` Config field (`session`, the default kept unchanged for the generic Web deployment, or `global`) and publishes the resolved value as a `globalThis` boot value ahead of every plugin bundle (`webserver/index-inject`, mirroring `dsh-client-ui-theme`'s own boot-value injection — the only established mechanism carrying a validated Host Config value across the Host/browser process boundary, since the client-modules boot graph (`window.__DSH_BOOT__`) carries no per-plugin config). The browser half reads that boot value once, synchronously, at its own `apply()`: `global` registers exactly one unconditional `conversation.page.utilities` action (`ScienceGlobalToggle`) and skips the session-header registration entirely, so the toggle has exactly one owner and stays visible through every later Session state too; `session` keeps the hand-off described above unchanged. The desktop app's overlay (`apps/desktop/src/runtime-overlay.ts`) sets `toggleScope: global` on the `ui-science` row.

The Science Details entry remains the authoritative artifact stage described by [Science artifact viewer panel](2026-08-18-science-artifact-viewer-panel.md). Files projects one latest-version card per artifact identity and does not duplicate Outcome, which keeps its independent Details destination. Open artifacts use one horizontally scrolling tab strip. The active viewer separates title and download/maximize/close controls from a second row containing Preview/Diff/Provenance and the exact-version stepper; selecting an older version shows its position in history and returns the body to Preview. Diff compares the selected version with the exact `parent` reference, supports text attachments through the session-scoped loader and shared `DiffBlock`, and reports missing, unsupported, unchanged, and failed states without substituting latest. Provenance contains Code, Execution log, Messages, Review, and Environment; Review remains an explicit empty state until `science-session` projects a structured record. In `session` mode, the page-level Files toggle sits in the session header's right-aligned utility group after Session Log and exposes its active state; in `global` mode the toggle instead sits at the far top-right of every screen and carries no active-state indicator. A Vega-Lite element row separates human style selection from model selection: clicking the name or chart opens the style panel, while the row's `+` control stages the exact path and optional element comment in the main composer. A raster's normalized drag surface stages through the identical comment-plus-`+`/`−` control once a region is drawn. Every selection and comment draft remains scoped to the exact artifact id and version; tab or version changes remount Preview, and Host admission validates the complete ordered target set before enqueueing one durable `science-edit` user message.

Direct Vega-Lite style controls remain in the stage and commit a human-edit version without a model request. The embedded artifact instruction field and send action are absent, so model-assisted artifact changes have one composer and one visible request path.

The Science-only conversation ring includes a user-facing Trace view projected from loaded real Session nodes and the client-safe Science projection. Each turn is one intent group summarizing run attempts, failures, elapsed run time, artifact deltas, delegation, and miscellaneous tools; structured run and artifact fields alone choose the title. A group presents at most one agent conclusion, chosen from the last non-empty assistant text event in that turn; its collapsed card contains the group title, status, artifact-delta chips, and one truncated conclusion line, while intermediate assistant narration is omitted from Trace. User messages, structured selections, and direct human edits occupy the user side of the center timeline, while agent groups occupy the opposite side, and the scrollable Trace reserves clearance from the live composer height. Artifact provenance preserves the generating turn's complete whitespace-normalized user request and complete agent conclusion; explicit `call:` and `turn:` buttons open Trajectory and semantic Trace, while `artifact:` actions open the exact artifact stage. Persistent-kernel language, epoch, and lifecycle state also appear in one fixed readout below the main composer.

The conversation service owns a per-view Session-visibility registry and mounted view opener. A registered `ViewVisibilitySource` carries its own invalidation (`subscribe`) alongside its per-Session `visible` predicate, and the conversation service's view ring subscribes to every registered source in addition to its own slot ledger — so a visibility answer that changes for a reason the ledger never sees (a Session list update, a projection resolving) still re-lists the tabs. Science registers Trace visibility this way, re-subscribing to the sessions list and every listed Session's `science` projection whenever that list changes, so ordinary conversations have no Science tab, the tab appears the moment a Session's preset or projection qualifies, while provenance can still open Trace at an exact `turn:` anchor. Target chips read from the Science locale rather than embedding English and render each target's raw comment text (never JSON-escaped). Download always resolves the selected durable source version; deterministic PNG/PDF export remains outside this decision and has no placeholder control.

## Alternatives considered

**Keep a second composer in the artifact stage.** Rejected because two send paths divide one request between artifact-local state and conversation history, and they cannot express one instruction over targets from several artifacts.

**Send one message per selected target.** Rejected because the user's instruction applies to the selection as a set; independent admissions permit partial acceptance and remove the requirement that the model coordinate the edits.

**Expose the engineering Trajectory ledger as the only trace.** Rejected because its raw event inspection and timing controls serve debugging. A compact semantic projection supports the user's causal reading while retaining a direct path to the ledger.

**Duplicate kernel status in the artifact stage.** Rejected because lifecycle state is session-wide rather than artifact-specific, and two copies would violate the single-authority placement rule.

**Give a raster region its own staging path instead of the shared comment-plus-add control.** Rejected: a region and a spec path are both exact-version targets the same Host admission validates the same way, so a second UI pattern would buy nothing but a second set of tests and a second way for the two to drift.

**Poll the sessions list and per-Session projections for Trace visibility instead of a `ViewVisibilitySource` subscription.** Rejected because polling either wastes cycles on an interval short enough to feel live or reads stale on one long enough not to; the registered source's own `subscribe` costs nothing while idle and fires exactly when its answer could change.

**Hand-pick which alias tokens the Science light override resets, instead of computing the differing set from `design-platform.css`.** Rejected because a hand-picked list is exactly the mechanism that produced the original gap: a token added to the palette later has no reason to also land in a manually maintained override, while the computed coverage test fails immediately when one does.

**Detect the desktop composition in the browser (a build target, a bundled flag, or a runtime probe such as `navigator.userAgent` or a window global not sourced from validated Host Config).** Rejected as environment sniffing: the same built client bundle serves every composition, so the placement must come from an explicit, validated Config field the composing overlay sets, not from the browser inferring which app it is running inside.

**Route `toggleScope` through the `science-runtime` settings namespace (`ctx.settingsScope`) `ui-science` already binds for its settings card.** Rejected: that namespace is a runtime-binding concern (Conda prefixes) with async, reactive, potentially user-editable semantics — the wrong contract for a fixed deployment-composition fact needed synchronously at plugin apply-time, and folding an unrelated UI-placement field into it would blur the namespace's one job.

**Add `config` to the client-modules boot wire (`WebBootEntry`/`window.__DSH_BOOT__`) so every browser plugin's `apply(ctx, config)` could receive validated Host config directly.** Rejected as disproportionate: no package needs this generically today, and the change would touch the shared wire schema, the Host scanner, and every browser plugin's apply signature for one package's one boolean-shaped need. The `webserver/index-inject` boot-global — already used by `dsh-client-ui-theme` for exactly this kind of one-shot Host-to-browser value — solves it without touching shared machinery.

## Consequences

Files and Outcomes resolve to different Details destinations with no duplicated Outcome section in Files. `AppFrame` remains the only owner of the Details column and collapses it when the column solver cannot preserve the center minimum; the Artifact implementation adds no Drawer or overlay system. Cross-artifact selections survive while the user composes one instruction but remain browser-local and clear only after accepted admission. Multi-target messages enlarge the durable `science-edit` source and model-visible text, while exact-version admission and `edit_of` ancestry remain unchanged per target. Trace is intentionally a linear semantic projection: DAG and kernel-epoch separators stay in engineering inspection, while delegation is one folded intent-group row rather than a separate lane.

The focused backend tests pin ordered commented targets and all-or-nothing validation. Client composition tests pin Science-only destinations, accessory, kernel, and Trace visibility plus bidirectional element and region staging, cross-artifact/version comment isolation, and post-stage comment edits reaching the store; the keyless Science scenario pins the assembled multi-target message through a real runnable profile. `ui-layout`'s own coverage test scans `design-platform.css` and `AppFrame.module.css` for the light-token reset, and an orchestration test in `ui-conversation` pins a `ViewVisibilitySource` invalidating independently of the slot ledger.

`ui-science`'s own tests pin both `toggleScope` compositions: its Host half publishing the resolved boot-global value (default and `global`) and disposing it with its fiber, its browser half's boot-global reader falling back to `session` for an absent or malformed value, and the plugin registering exactly the `global`-mode's one `conversation.page.utilities` owner (no session-header entry) or the unchanged `session`-mode pair. `apps/desktop`'s runtime-overlay test pins the `ui-science` row's `toggleScope: global` config among the rendered patch ids. This is a pure client-composition and Host-config change with no model- or transcript-visible output, so no keyless snapshot moved.
