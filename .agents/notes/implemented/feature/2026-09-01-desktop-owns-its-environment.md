# Agent Note: PaperMachine owns its environment outright

Status: implemented

English | [中文](2026-09-01-desktop-owns-its-environment.zh.md)

> Supersedes the bind-an-existing-environment route documented in [desktop onboarding reaches its install path](2026-09-01-desktop-general-environment.md); that note's environment-declaration, custom-environment, and DMG mechanics remain current except where this note says a field renamed.

## Problem

Onboarding offered two routes: bind a conda-family Python/R environment already on the user's machine, or install the shipped `general` environment. Binding an existing environment meant PaperMachine ran against whatever packages, versions, and channel configuration that install happened to have — a different reproducible code path per user, no way to add or upgrade a package into that prefix without risking the user's own Anaconda setup, and a first run that assumed the user already had a working conda-family install to point at. Claude Science ships and manages its own environment for the same reasons; PaperMachine's bind route was the one place it diverged.

Separately, the shipped environment's only download source was `https://conda.anaconda.org/conda-forge`. That host is unreliable from mainland China, where a meaningful share of the product's target researchers work, turning first install into a stall with no alternative.

## Decision

Onboarding has exactly one route: install. Bind-an-existing-environment is removed entirely — `src/detection.ts`, the `desktop:detect`/`desktop:bind` IPC handlers, and the preload bridge's `detect`/`bind` methods are gone, along with the `#detected` section, its two interpreter groups, and the bind/re-detect buttons in `resources/onboarding.html`. The one piece of `detection.ts` provisioning still needs — `qualifyingInterpreters`, which re-validates a prefix's interpreter presence right before a binding is written — moved to its own module, `src/interpreter-presence.ts`, so the validation survives without keeping the whole filesystem scanner alive for one caller (`bindProvisionedPrefix` in `main.ts`).

`resolveEnvironmentBindingStatus` (`src/environment-binding.ts`) now checks not only that a bound prefix still exists but that it sits inside this application's own provisioned environments root, `<dshHome>/desktop-environments/environments/` (exported as `desktopEnvironmentsRoot`/`provisionedEnvironmentsDirectory` from `provisioning.ts`, shared by both modules so the definition of "ours" lives in one place). A binding naming a prefix outside that root — from a build predating this change, or any other foreign conda-family install — is reported `invalid` with a reason stating the environment must be reinstalled, routing back to onboarding rather than silently continuing to run against a path this application no longer promises to keep working. The application menu's "Rebind Environment…" action is renamed "Change Environment…", matching what it now does: reopen onboarding to install a different (or repaired) environment, never to point at one already on disk.

The shipped `general` declaration's single `channels` field is replaced with an ordered `sources` array (`EnvironmentSource`: `id`, `name`, `channels`). `general.json` ships three, tried as whole, independent `micromamba create` attempts in order — never merged into one channel list, which would let a single solve mix packages from different mirrors into one inconsistent environment:

1. `tuna` — `https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud/conda-forge`
2. `ustc` — `https://mirrors.ustc.edu.cn/anaconda/cloud/conda-forge`
3. `official` — `https://conda.anaconda.org/conda-forge`

`DesktopEnvironmentProvisioner.provision` (`provisioning.ts`) runs `orderSourcesFrom(declaration.sources, preferredSourceId)` to decide attempt order, then loops: clear the prefix, run `create` against that source's channel(s) alone, and on any failure move to the next source with a freshly cleared prefix, reporting each attempt through the existing `ProvisioningProgress` channel (`"Retrying via <source name> (source N of M)"`). No attempt is classified network-vs-solve before retrying — a bad package spec fails fast during solve, so retrying it across sources costs seconds, and that uniformity is simpler and equally honest. Cancellation during an attempt propagates immediately rather than trying the next source. micromamba's package cache is shared via one `MAMBA_ROOT_PREFIX` across every attempt, so packages a failed attempt already downloaded are not re-fetched by the next one. The last source's error is what a total failure surfaces.

`resources/environments/general.json`'s channel URLs are now parsed by `parseEnvironmentDeclaration` (`environment-declaration.ts`) against a strict allowlist (`https://` plus `[A-Za-z0-9._~/-]`) rather than the old bare-channel-name pattern, since a channel URL reaches `micromamba`'s argv unescaped and this is that value's parser boundary — no whitespace, control character, or shell metacharacter is accepted at any position.

A new module, `src/source-selection.ts`, decides the confirmation panel's default source deterministically from system locale settings — `Intl.DateTimeFormat().resolvedOptions().timeZone` and `app.getPreferredSystemLanguages()`, both read in `main.ts` and passed in as plain data so the decision function itself stays pure and unit-testable without Electron. `resolveDefaultSourceId` returns the `tuna` mirror when the timezone is `Asia/Shanghai` or any preferred language starts with `zh`, otherwise the `official` channel; it never probes reachability or measures speed. The confirmation panel (`onboarding.ts`/`onboarding.html`) renders every offered source as a radio choice, preselected to this default, and still states the download size and disk requirement before anything downloads. The user's choice becomes the first attempt in the ordered fallback described above; the remaining sources still follow if it fails.

`buildCustomDeclaration` (`custom-environment.ts`) takes the shipped declaration's `sources` unchanged rather than letting the user pick per-package sources — a custom package set does not get to choose where packages come from, only which packages. Its revision digest is deliberately computed from `packages` alone, excluding `sources`: a source describes where packages are downloaded from, not what ends up installed, so trying a different mirror (whether by user choice or the ordered fallback moving on) for the same package list must not mint a new revision and force a redundant re-provision of what would be an identical environment.

## Alternatives considered

- **Keep the bind route as an opt-in "advanced" setting.** Rejected for this change: it would still leave two on-disk formats (a bound foreign prefix and an owned provisioned one) and two validation paths to maintain for a route the product decision says should not exist at all. If a "use my own environment" setting is ever wanted, it is recoverable from git history rather than kept dormant with no entry point — the exact defect the immediately preceding change on this branch had fixed (an implemented, tested route with no way to reach it) must not be reintroduced in the other direction.
- **Merge all three sources into one `channels` list micromamba searches across.** Rejected: a conda channel list means "search all of these for the best match," so a single solve could resolve `numpy` from TUNA's mirror and `pandas` from the official channel in one install, mixing build provenance in ways that are prohibitively hard to reason about or reproduce. A whole-attempt retry keeps every provisioned environment traceable to exactly one source.
- **Classify each fallback failure as network-vs-solve and only retry network failures.** Rejected: distinguishing them reliably from micromamba's output is not worth the complexity, and a genuinely bad package spec fails during solve, before any download — retrying it across three sources costs seconds, so retrying everything uniformly is simpler and no less honest.
- **Probe mirror reachability or latency to pick the default source.** Rejected: the task constraint is explicit — the default must be deterministic from system settings (timezone, language) alone. A network probe adds a slow, flaky first-run step and defeats the purpose of a fast, obvious default the user can still override.
- **Include `sources` in the custom declaration's revision digest.** Rejected: sources are metadata about where packages come from, not what the resulting environment contains; hashing them would mint a spurious new revision — and trigger a redundant re-provision — every time a custom install's ordered fallback moved past its first source.

## Consequences

Every PaperMachine environment is now provisioned by this application into a prefix it owns, at a path only it writes to; a pre-existing Anaconda/Miniconda/Miniforge/Mambaforge/Micromamba install on a user's machine is invisible to the product and untouched by it. A binding written by a build before this change (naming an arbitrary bound prefix) stops working on upgrade and routes back to onboarding with a stated reason, requiring a fresh install; this is an accepted, honest breaking change under this repository's pre-release, no-compatibility-promise stance. A user in mainland China gets a working default mirror without configuration, and a failed mirror no longer means a stalled first run — the ordered fallback tries the next source automatically, at the cost of up to two extra failed-attempt delays (bounded by each source's own `create` timeout) before the install either succeeds or a total failure is reported. Detection's best-effort `--version` probing of found interpreters, and its guidance copy for a machine with nothing detected, are both gone along with the route they served; `qualifyingInterpreters`' TOCTOU re-check of a freshly provisioned prefix is the only surviving piece of that module.

## Verification

`tests/environment-declaration.spec.ts` covers the `sources` array's parsing: three shipped sources in fallback order, a rejected non-`https` URL, rejected shell-metacharacter and whitespace payloads (a parser-boundary check, since a channel URL reaches `micromamba`'s argv unescaped), a rejected empty `sources` array, a rejected duplicate source id, and the three real shipped mirror URLs accepted individually. `tests/provisioning.spec.ts` covers `orderSourcesFrom`'s reordering and the provisioner's ordered-fallback loop end to end: falling back to the next source as a whole retried `create` attempt (never a merged channel list), trying every source and surfacing the last error when all fail, one shared `MAMBA_ROOT_PREFIX` across every attempt, no further source tried once cancellation interrupts an attempt, and starting from a caller-supplied preferred source. `tests/source-selection.spec.ts` covers the geo default in both directions (timezone, language, and their absence) and its fallback when a declaration's sources omit the preferred id. `tests/environment-binding.spec.ts` covers a bound prefix inside the provisioned root passing, one outside it (existing on disk) being rejected with a reinstall-stating reason, and the root path itself not qualifying as "inside" it. `tests/onboarding.spec.ts` covers the confirmation panel's source picker (default preselection, overriding it, and the chosen id reaching both the standard and custom provisioning calls) and asserts the bridge exposes no `detect`/`bind` methods and the page renders no `#detected`/`#bind`/`#redetect` elements. `tests/custom-environment.spec.ts` covers the digest staying stable when only `sources` changes.
