# Agent Note: Persist the Details panel across reloads; localize workspace-file open errors

Status: implemented

English | [中文](2026-09-01-details-panel-persistence-and-workspace-error-i18n.zh.md)

## Problem

Real-machine acceptance of the Science workbench surfaced two independent gaps.

`createLayoutStore()` (`packages/client/ui-layout/src/client/stores.ts`) declared no `persist`, so every field — sidebar width, Details width and open/closed state, and the narrow-viewport pair — reset on reload. A user who opened the Details column onto an artifact tab or a project file lost that column on the next reload: the panel holding open work state behaved as if it held none.

`WorkspaceFilePreview` (`packages/client/ui-science/src/client/ScienceDetailsView.tsx`) rendered the host's raw English `error.message` onto a Chinese-locale screen — "Workspace file exceeds the 2 MiB preview limit." The host already carries a closed-enum reason for exactly this purpose: `workspaceFile` throws `WorkspaceReadError` (`NO_WORKSPACE` | `PATH_OUTSIDE_WORKSPACE` | `FILE_TOO_LARGE`, `packages/host/apiproxy/src/api-proxy.ts`) and sends it as `science-artifact-error`'s `details.reason`. The same file's `loadLibrary` and `loadWorkspaceFiles` handlers (`ProjectLibrary`, same component) rendered the same host's raw `error.message` for the artifact library and the project-file listing, the two remaining `setError(result.error.message)` call sites that reach the same structured api-proxy path as `workspaceFile`.

## Decision

The layout store persists under the versioned key `dsh.layout.panels.v1` and declares `sidebar`, `narrow`, and `narrowExpanded` as `transient`, so only `details` round-trips through `localStorage`. Persistence is deliberately asymmetric between the two panel-width fields, against this repository's usual preference for symmetric parallel values: Details is the workspace surface for documents a user opened on purpose, and the product owner asked for it to survive a reload; the sidebar is navigation chrome whose reload-reset `apps/web/tests/smoke-real.e2e.ts` pins as intended ("sidebar drag widens the column and resets across reload"); `narrow`/`narrowExpanded` are live derivations of the viewport breakpoint that `AppFrame` feeds through `setNarrow`, so persisting them would leak a narrow-viewport state into the next load at a wide one. `stores.ts`'s JSDoc carries the same reasoning at the declaration.

`scienceArtifactErrorReason(error)` extracts `details.reason` for a `science-artifact-error` failure (`undefined` for every other code), and three functions switch on it for their own surface. `workspaceFileErrorText(error, t)` maps the three `WorkspaceReadError` reasons to `library.fileNoWorkspace`, `library.filePathOutside`, and `library.fileTooLarge`; a missing or unrecognized reason and every other error code fall back to `library.fileOpenFailed`. `libraryErrorText(error, t)` maps only `NO_WORKSPACE` (`library.libraryNoWorkspace`) — `scienceLibrary` (`api-proxy.ts`) also forwards a `ProjectArtifactStoreErrorCode` (`SCHEMA_VERSION_MISMATCH` | `INVALID_MARKER` | `ARTIFACT_NOT_FOUND` | `VERSION_NOT_FOUND` | `BLOB_NOT_FOUND` | `BLOB_CORRUPT`, `packages/science/science-artifact-store/src/errors.ts`) as the same reason, but none of those store codes are user-actionable, so they and `internal` and any unrecognized reason fall back to `library.libraryLoadFailed`. `projectFilesErrorText(error, t)` maps `NO_WORKSPACE` and `PATH_OUTSIDE_WORKSPACE` (`workspaceFiles` shares `resolveWorkspacePath` with `workspaceFile`, so it can carry either — never `FILE_TOO_LARGE`, which only `workspaceFile`'s is-a-file check throws) to `library.filesNoWorkspace`/`library.filesPathOutside`, and everything else to `library.filesListFailed`. All eight keys exist in `zh` and `en` (`locales.ts`); the file-preview keys say 文件 (a single project file), while the library and listing keys say 成果库 / 项目文件列表 to match `library.home`/`library.files`' existing vocabulary. The host's error text is unchanged in all three: it remains the log-facing and non-localized-caller-facing string.

The remaining four call sites — `addArtifactNote`, `removeArtifactNote`, `applyChartOps`, `previewChartOps` — stay unmapped. They reach `ctx.remote.scienceEdits.*`, a Typert Remote (`packages/client/ui-science/src/client/index.ts`), not the api-proxy path above. `ScienceEditService` (`packages/science/tool-science/src/edit-message.ts`) throws `ScienceEditError(message, code)` on a business rejection (`CHART_STALE`, `CHART_NOT_ADDRESSABLE`, `CHART_OP_INVALID`, `SCIENCE_EDIT_TARGET_MISMATCH`, `SCIENCE_EDIT_TARGET_NOT_FOUND`, `SCIENCE_EDIT_INVALID_REQUEST`) — a plain `Error` subclass, not a `TypertLookupFailure`. The Gateway's `rpcFailure()` (`packages/api/gateway/src/index.ts`) converts every error that is neither `RemoteInvocationCancelled` nor `TypertLookupFailure` to `{ code: 'internal', message: error.message, details: {} }`, so `ScienceEditError`'s `code` never crosses the wire — the client sees only `internal` and the English `message`, confirmed by the existing `gateway.client.spec.ts` coverage of the identical collapse for another business rejection. `ScienceDetailsInjected`'s `{ readonly message: string }` failure type (`ScienceDetailsView.tsx`) is accurate, not merely under-widened: there is no structured field a client-side mapping function could switch on today. Mapping this group requires a Remote- or Host-side change (see Alternatives), not a Details-view change, and is deferred pending a product decision on which.

## Alternatives considered

**Persist the whole layout store, sidebar included.** Rejected: it contradicts the sidebar-reset assertion that smoke-real already pins as product behavior, and the sidebar is navigation chrome rather than saved work state.

**Localize by rewriting the host's error text.** Rejected: the host string serves logs and callers that carry no locale. The structured `details.reason` is what a localized surface consumes.

**Map the four Typert Remote call sites (`addArtifactNote`, `removeArtifactNote`, `applyChartOps`, `previewChartOps`) alongside the api-proxy three.** Deferred, not rejected: confirmed by reading `rpcFailure()` (see Decision) that no `ScienceEditErrorCode` reaches the client today, so there is nothing to switch on without a separate change first. Two ways to give the client that signal: (a) let a business rejection's `code` cross the Remote wire (widen `rpcFailure()`'s conversion, or add a `TypertLookupFailure`-like carrier for business codes) so `ScienceEditErrorCode` survives to `ScienceDetailsInjected`; (b) keep the Remote's `internal` collapse and instead have the Host attach a structured field elsewhere (e.g. widen `ScienceEditError`'s message to a stable, parseable prefix, or add a second, api-proxy-style channel for edit failures). Both put a specific reason (stale version, non-addressable chart, invalid operation) back in front of the user instead of a blanket "operation failed", which trades away exactly the information a failed edit needs to convey; picking between them is a product/Remote-design decision, not a Details-view one.

**Clamp defensively against the reported bad first-open width.** Rejected: acceptance reported the Details column first rendering near 120–200px, below its own 300px `DETAILS_MIN`, self-correcting after a manual drag. Every path that writes `details` (`openDetails`, `setDetails`, and `columns.ts`'s concession chain) clamps to `[DETAILS_MIN, DETAILS_MAX]` or `0`, so no data path produces that width. `AppFrame.module.css`'s `transition: grid-template-columns 0.3s ease-in-out` animates the track from `0` through every intermediate value on open, which an observation taken mid-transition sees and which settles on its own — consistent with the symptom being irreproducible on demand. Insurance code without a found mechanism buys nothing.

## Consequences

Enabling persistence on a previously transient store changes test isolation: any test file that seats `createLayoutStore()` (or `AppFrame`, which seats it) more than once per process must clear `localStorage` between mounts. `packages/client/ui-layout/tests/app-frame.client.spec.tsx` needed exactly that, and its resize and collapse assertions failed until it got it.

Each error mapping's `default` branch discards a host reason (or an entire error code, for `libraryErrorText`'s `ProjectArtifactStoreErrorCode` family) this build does not map in favour of a generic notice, so a maintainer adding a new `WorkspaceReadError` or `ProjectArtifactStoreErrorCode` value on the host adds the matching client case or accepts the generic fallback; none of the three mappings is exhaustive by construction. The four Typert Remote call sites still render the host's English `internal` message verbatim: they are the remaining known case of untranslated host text on a localized screen, and they stay that way until the deferred Remote/Host change above lands. Replacing that text with a generic localized notice today would cost the user the one thing a failed edit must convey — stale version, non-addressable chart, invalid operation — so the English text is the lesser harm until a reason crosses the wire. A maintainer touching `ScienceEditService` should not assume its `ScienceEditErrorCode` is visible to the user today.

## Testing

`layout-store.client.spec.ts` covers Details surviving a second `create()` while sidebar and the narrow pair reset, the narrow pair never being written, a stored payload carrying them being ignored on read, and a legacy payload missing every declared field rehydrating without throwing. `ScienceDetailsView.client.spec.tsx` covers: each of the three `WorkspaceReadError` reasons, an unrecognized reason, and a missing reason for the file preview; `NO_WORKSPACE` and a `ProjectArtifactStoreErrorCode` (`BLOB_CORRUPT`) and an unrecognized reason for the library; `NO_WORKSPACE` and `PATH_OUTSIDE_WORKSPACE` and an unrecognized reason for the file listing; and an `internal`-code failure falling back to the generic notice for both the library and the listing — all in both locales, all asserting the host's raw text never reaches the screen.
