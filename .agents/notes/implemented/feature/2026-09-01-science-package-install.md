# Agent Note: Science package installs through ordered micromamba channels

Status: implemented

English | [中文](2026-09-01-science-package-install.zh.md)

## Problem

A Science session could run code against its bound Conda prefix but could not add a package to it. The only route open to the model was an in-kernel `pip install` or `install.packages()`, whose effect lives in the running kernel's memory and disappears at the next kernel restart — an idle expiry, a crash, an interrupt escalation, or the end of the session — with nothing in the durable environment record saying the package was ever there. A researcher who asked for a library therefore got one that worked until it silently did not.

`ScienceRuntime` already carried an optional `micromambaPath` and an `installPackages` operation, but that operation pinned every install to the literal channel name `conda-forge`, which resolves to `https://conda.anaconda.org`. [PaperMachine provisions its own environment](2026-09-01-desktop-owns-its-environment.md) through an ordered list of mirrors precisely because that host is unreliable from mainland China. A desktop user whose environment was created through the TUNA or USTC mirror would have had every later install stall or fail against a host their machine cannot reach.

## Decision

**Installs go through micromamba only.** `installPackages` never falls back to `pip`/`install.packages()`, and `INSTALLER_NOT_CONFIGURED` is a loud rejection rather than a silent degradation to an in-kernel install. A package that reaches the durable environment record is one micromamba resolved into the prefix.

**`installChannels` is an ordered list retried whole, not a channel set.** `Config.installChannels` (`packages/science/science-runtime/src/config.ts`) is an ordered, non-empty list of `https://` conda channel URLs. `installPackages` runs one complete, independent `micromamba install --yes --no-rc --prefix <prefix> --override-channels --channel <one URL> <packages>` per entry, in order, stopping at the first success. `installArgv` takes exactly one `channelUrl` and can express nothing else. Only a `'failed'` attempt tries the next URL: `'cancelled'` and `'timed-out'` stop immediately, because every attempt shares the one `OperationControl` this call holds, so a retry would observe the same deadline and the same abort signal. Each attempt creates and removes its own install scratch directory. This is the whole-attempt shape the desktop provisioning track already uses for `micromamba create`.

**`micromambaPath` and `installChannels` are co-required.** `resolveConfig` throws `science-runtime: micromambaPath and installChannels must be configured together, or neither` when exactly one is set, so a half-configured deployment fails at load rather than at the first install. Every channel URL is validated at config resolution against `CHANNEL_URL` — `https://` plus a fixed allowlist of letters, digits, and `._~/-`, the byte-identical regex `apps/desktop/src/https-url.ts` uses — because the value reaches `micromamba` argv unescaped, and against `MAX_INSTALL_CHANNELS` (16). schemastery normalizes an omitted optional array to `[]`, so an empty `installChannels` reads as unconfigured. `ScienceRuntime` narrows the two independently-optional resolved fields into one `installer: { micromambaPath, channels } | undefined` at construction, so no call site re-checks the pairing.

**A successful install restarts the kernel lazily, through the existing `environment-rebound` path.** `installPackages` re-observes the profile and appends one fresh whole-value `science/environment-bound` revision; it kills no kernel and starts none. `ScienceKernelSet.acquire` already ends a live kernel whose `environmentRevision` no longer matches the applied revision, with end reason `environment-rebound`, and spawns a fresh epoch. The next `run_python`/`run_r` for that language therefore restarts, and the run result already names that reason. No new event, end reason, or restart path exists for installs. The tool result states the consequence in the same turn as the install: `environment revision <n> applied — this takes effect on the next run_python/run_r call for this language, not now: that call restarts the kernel (an environment re-bind) and every variable, import, and definition it currently holds in memory is lost then`.

**One tool, `install_science_packages`, takes `language` and `packages`.** It is the Consumer half of the capability, dispatched through `requireDirectDispatch` like the other Science mutators; unlike `run_python`/`run_r`/`annotate_artifact` it carries no `toolCallId`/`requestHeaderSeq` provenance, matching `bindEnvironment`'s own whole-value append. Its render intent is `generic` with no editor locations, matching every other Science tool: an install has no file to show, and a presenter is a pure function of `args`, which hold no Host path to render.

## Alternatives considered

- **Pass every configured channel to one `micromamba install` as a `--channel` list.** Rejected: a conda channel list means "search all of these for the best match," not "fall back." One solve could resolve one package from a mirror and another from the official host, mixing build provenance in one prefix, and a reachable-but-stale mirror would silently win entries over the official channel instead of being skipped. The whole-attempt retry keeps every installed set traceable to exactly one channel. Same rejection, same reason, as the desktop provisioning track's own.
- **Retry the next channel on any non-success outcome.** Rejected: `'cancelled'` and `'timed-out'` are properties of this call, not of the channel. Every attempt shares one `OperationControl`, so the retry would abort immediately and only add a misleading second attempt to the record.
- **Classify a failure as network-vs-solve and retry only network failures.** Rejected for the same reason the provisioning track rejected it: micromamba's output does not distinguish them reliably, and a genuinely bad package spec fails during solve before any download, so retrying it across the list costs seconds.
- **Restart the affected kernel immediately on a successful install.** Rejected: it would destroy in-memory state the model may still be using, at a moment the model did not ask to lose it, and it would need a second restart path beside `environment-rebound` that produces the same durable facts. Deferring to the next run leaves the choice of when to pay the restart with the caller and reuses one mechanism.
- **Split the capability into `install`/`uninstall`/`list` tools.** Rejected: `get_science_state` already reports each language's full package inventory, so `list` would duplicate a model-visible surface; uninstall has no product requirement and would let the model remove a package the environment declaration promises. Three tools would grow the Science roster by three instead of one for one capability.
- **One tool per language (`install_python_packages`/`install_r_packages`).** Rejected: `run_python`/`run_r` are two tools because their `code` arguments are two different languages a model writes; a conda package spec has one grammar, so the language is an argument, not a tool.
- **`terminal` render intent, showing the micromamba invocation.** Rejected: the invocation names the Host's micromamba path and channel URLs, and a presenter may read only `args`, which hold neither. The model result already carries the bounded stdout/stderr tails for inspection.
- **Make the install channel a `run_python`/`run_r` argument or a per-call tool argument.** Rejected: which mirrors a deployment may reach is Host policy, not a model decision, and a model-chosen URL would reach `micromamba` argv.

## Consequences

A deployment that provisioned through a mirror installs through the same mirror. A deployment configuring `micromambaPath` without `installChannels`, or the reverse, no longer loads — including any pre-existing configuration that set `micromambaPath` alone, which this repository's pre-release stance accepts as a loud break rather than a default. The model gains one tool and the standing guidance that an in-kernel `pip install`/`install.packages()` is transient; `run_python`/`run_r`'s descriptions name `install_science_packages` instead of "a separate operation."

An install pays the full latency of every failed channel before the one that succeeds, on every call: nothing remembers which channel last worked, and each call retries the list from its first entry. A failed install returns the last attempt's bounded stdout/stderr tails; earlier attempts' output is not carried in the result. Both gaps are recorded under `packages/science/science-runtime/README.md`'s Known Limitations.

## Testing

`packages/science/science-runtime/tests/environment.spec.ts` covers config resolution (the co-requirement in both directions, the empty-array unconfigured state, a non-array value reaching `resolveConfig` directly, the character allowlist against `http://`, whitespace, `;`, and backtick payloads, the three real shipped mirror URLs, and the entry cap) and the fallback loop (a failed first channel trying the next and appending a fresh revision from the second, every channel failing with no revision appended, and a cancelled in-flight attempt trying no further channel). `packages/science/science-runtime/tests/install.spec.ts` pins that one argv names exactly one channel. `packages/science/tool-science/tests/tool-science.spec.ts` covers the tool's value flattening, the takes-effect wording, and the no-Runtime, nested-dispatch, unconfigured-installer, and success paths. The `science-tools` keyless headless snapshot (`examples/headless-agent`) drives an install turn against a fixture micromamba executable and asserts the durable second `science/environment-bound` revision, the guidance and result text reaching the model, and the next unrelated `run_python` call reporting `kernel restarted (environment re-bind)` — the lazy restart end to end. `apps/cli/tests/web-agent-presets.e2e.ts` and `apps/web/tests/science-preset.snapshot.ts` pin the preset's tool roster.
