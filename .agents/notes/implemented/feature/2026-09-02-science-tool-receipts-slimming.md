# Agent Note: `dsh-tool-science` model-facing artifact fields after the store-authority migration

Status: implemented

English | [中文](2026-09-02-science-tool-receipts-slimming.zh.md)

## Problem

[T1](../architecture/2026-09-01-project-artifact-store-schema-v2.md) made the project artifact store's write transaction the sole authority for a version's provenance, and [T2a](../architecture/2026-09-02-science-artifact-event-slimming.md) slimmed `science/artifact-saved` and `ScienceArtifactVersion` to a flat presentation snapshot (`artifactId`, `logicalName`, `version`, `title`, `caption?`, `projectId`, `versionId`, `sha256`, `seenAt`) with no `origin`, `mediaType`, `byteCount`, `parent`, `runId`, `createdAt`, or `chart` field left on it. `dsh-tool-science` built every model-facing artifact value (`get_science_state`, `run_python`/`run_r`'s captured-artifact listing, `annotate_artifact`'s receipt) straight off those removed fields and no longer compiled: `artifact-schema.ts`, `state.ts`, `run.ts`, `annotate-artifact.ts`, and `edit-message.ts` (whose viewer-edit admission checks a target's media type and live chart state) all read facts that had moved into the store.

## Decision

**Two new store-owned facts reach the model face: `contentOrigin` and `curated`; every other provenance field this package used to expose stays hidden.** `packages/AGENTS.md`'s "write model-facing contracts from the model's perspective" rule and the T1 design's own stated principle (`get_science_state` exposes `content_origin` and a curated boolean, never `actor`) fix the two facts worth exposing. `scienceArtifactSchemaProperties`/`scienceArtifactValueFields` (`artifact-schema.ts`) become the one shared builder every tool spreads: `artifactId`, `logicalName`, `version`, `title`, `caption?`, `contentOrigin` (`'run-auto' | 'human-edit' | 'import'`, read from the store's `VersionRecord.contentOrigin`), `curated` (`store.latestAnnotation !== undefined && store.latestAnnotation.actor !== 'capture'` — true once a model or human annotation has replaced the auto-capture title, never exposing which actor), `mediaType`, `bytes` (both also store-owned now), and `seenAt` (the session event's own presentation-time field, replacing the removed `createdAt`). `versionId`/`sha256`/`projectId`/annotation `actor` are never added to any schema.

**`parent` (ancestry) and `runId` (producer) are dropped from model-visible text entirely, not rebuilt from a store read.** Both are provenance facts the T1 design explicitly keeps out of model-visible state ("the model was never fully shown who produced it, based on which version"); reconstructing them would mean threading `baseVersionId`/`producerRunId` from `VersionRecord` into every receipt for a fact the design says stays hidden. `run.ts`'s captured-artifact listing text drops the `edited from <artifactId> v<version>` ancestry suffix; `annotate_artifact`'s receipt drops `curated from run <runId>`.

**Chart-edit summaries (`edits`/`editCount`, "N direct edits: op (target)") are dropped from every model-facing value, not reconstructed from the store's `figure_state` table.** T2a already moved the live-figure-object state that fed this text out of the session event into the store's `figure_state` side table (per-artifact, `image/png` only). Rebuilding it for model text would need a `getFigureState` store read plus `decodeScienceChartState` per listed artifact, for a fact whose real audience is the viewer's own chart-editing panel, not the model — the model already sees each `annotate_artifact`/edit-message turn as it happens. Deferred to a future Web-row-only surface, not silently dropped: called out in the package README and here.

**Every tool that lists artifacts reads `VersionRecord` per artifact through one shared resolver.** `ResolveArtifactStoreVersion = (artifact: ScienceArtifactVersion) => Promise<VersionRecord>` (`artifact-schema.ts`) is the seam every model-facing artifact listing takes as a parameter: `runValueFromResult(result, resolveStore)`, `stateValueFromProjection(projection, historyItemLimit, resolveStore)`. The real resolver, `resolveArtifactStoreVersion(ctx, artifact)` (`run.ts`), is the one implementation every tool's `execute()` binds via `resolveArtifactStoreVersion.bind(undefined, ctx)` — a bound reference, not a wrapping arrow function, so the call site adds no function literal of its own that would need independent coverage beyond the two paths (`VersionRecord` found; `VersionRecord` missing, a durable invariant violation) `resolveArtifactStoreVersion` itself is unit-tested for. `requireArtifactStore(ctx)` reads the optional `ctx.get('scienceArtifactStore')` rather than the `ctx.scienceArtifactStore` property proxy: `scienceArtifactStore` is not in this package's own `inject` (only `dsh-science-runtime` requires it), so `packages/AGENTS.md`'s "optional services use `ctx.get`" rule applies directly — this package's tools still work when only `ctx.scienceRuntime` (which transitively requires the store) is mounted.

**`edit-message.ts`'s viewer-edit admission reads the same two store facts (`mediaType`, live chart state) through an injected async resolver, not a synchronous read off the artifact.** `resolveScienceEdit`/`resolveSelection` become `async`, taking a `ReadArtifactTargetFacts = (artifact) => Promise<TargetMatchFacts>` (`{ mediaType, chart: ScienceChartState | undefined }`) resolver; `assertTargetMatches` stays a synchronous pure check over the resolved facts, matching every other Science validation split in this package (resolve, then check). `ScienceEditService.submit` supplies the real resolver: `store.getVersion` for `mediaType`, then `store.getFigureState` + `decodeScienceChartState` only when `mediaType === 'image/png'` — a non-image target never reads `figure_state`, since only a PNG version can carry one.

## Alternatives considered

**Keep `mediaType`/`bytes` off the model face along with `parent`/`runId`, exposing only `contentOrigin`/`curated`** — rejected: unlike producer/ancestry, a file's media type and size are facts the model already reasoned about when it wrote the file (`raster_artifacts` declares a PNG; a captured `.csv`/`.json` is typed by its own write), and dropping them would remove information the model needs to describe its own output accurately, for no privacy or provenance-leakage reason — they cost one more field on a store read this package is already making per artifact.

**Rebuild `edits`/`editCount` from `store.getFigureState` since the per-artifact store read already happens for `contentOrigin`/`curated`** — rejected: it is a second store read (`getFigureState`, PNG-only) plus a decode step per PNG artifact in every bounded `get_science_state`/run-result listing, for a fact whose primary consumer is the viewer's chart panel; the model already learns about each edit from the `annotate_artifact`/edit-message turn that produced it, so the marginal token/latency cost buys no new model capability.

## Consequences

Scope: `packages/science/tool-science` only, matching T2's package boundary. `artifact-schema.ts`'s `ScienceArtifactEditSummary`/`scienceArtifactEdits`/`formatScienceArtifactEdits`/`chartEditSchema` and their `ScienceChartOp` import are deleted along with the model text they built — a deliberate removal, not code left to bit-rot. `formatArtifactReceipt`'s text changes from `curated from run <runId>` to `<contentOrigin>, curated`/`<contentOrigin>, auto-captured`; `formatRunResult`'s captured-artifact line drops its `edited from …` suffix; `get_science_state`'s per-artifact JSON drops `origin`/`parent`/`runId`/`createdAt`/`environmentRevision`/`environmentFingerprintPreview`/`edits`/`editCount` and gains `contentOrigin`/`curated`/`seenAt`. Every one of these is a stable model-visible text change, pinned by this package's own updated unit tests (100% per-file coverage on `packages/science/tool-science/src`); T5 owns bringing the keyless snapshot fixtures (`examples/headless-agent`) and the Python/TypeScript SDK expected outputs current with this same text.

`packages/host/apiproxy`, `apps/web`'s e2e/snapshot fixtures, `examples/headless-agent`'s Science driver fixture, and `packages/science/science-runtime`'s own `persistent-kernels.real.spec.ts`/`real-acceptance.ts` still construct or read the pre-T2a `ScienceArtifactVersion` shape (`origin`, `mediaType`, `chart`, `producerSessionId`, `requestHeaderSeq` fields) and fail `pnpm run doc-typecheck`'s full host/apps build; none of these are in this task's package boundary (`packages/host`, `apps/`, `examples/` are T3/T4/T5 territory, and the two `science-runtime` real-interpreter suites are that package's own leftover from its T2b-1 write-path migration). `pnpm run verify-cordis-catalog`/`verify-doc-graphs` independently fail on a pre-existing, unrelated type-link coverage gap (`ctx.scienceRuntime.installPackages`'s `InstallScienceEnvironmentPackagesRequest`/`Result` types, from the package-install feature, not this migration); `verify-client-catalog`/`verify-module-graph` are stale from earlier commits on this branch; `verify-package-readme-model-experience` fails on an unrelated package (`dsh-client-ui-brand-papermachine`). None of the four are caused by this change; `pnpm run doc-sync` was run to confirm that, not as this task's own passing gate.

## Testing

`packages/science/tool-science/tests/tool-science.spec.ts` and `tests/edit-message.spec.ts` are fully updated: every fixture that used to build the discriminated-union `ScienceArtifactVersion`/`ScienceRunArtifactVersion` shape now builds the flat session-level shape plus a companion `VersionRecord`/`TargetMatchFacts` fixture; `resolverFor`/`singleFacts`/`factsFor` test helpers inject those store facts into the now-`async` `runValueFromResult`/`stateValueFromProjection`/`resolveScienceEdit`. New direct tests cover `requireArtifactStore`'s missing-service throw, `resolveArtifactStoreVersion`'s found/missing-store-row branches, `edit-message.ts`'s non-image-target and dangling-store-reference branches, and the dropped `artifactReceiptFromArtifact` human-edit guard's replacement (the check now lives solely in `dsh-science-runtime`'s `annotateArtifact`, per DRY — this package never receives a human-edit version back from that call). `pnpm run doc-sync` was run once to confirm none of its failures trace to this change (see Consequences); it is not one of the gates this task reruns.
