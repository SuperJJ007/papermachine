# 0.1.0

[English](0.1.0.md) | 中文

`0.1.0` 是 PaperMachine 首个公开发布版本。它是 [0.1.1-rc.4](0.1.1-rc.4.zh.md) 候选版(`codex/rc4-release-candidate`,DMG 构建 commit `d65d2115c1` 加上这次文档改动)在此基础上叠加下面这些修复;候选链本身的历史见 [0.1.1-rc.3](0.1.1-rc.3.zh.md) 和 [0.1.1-rc.4](0.1.1-rc.4.zh.md)。

## 改了什么

### 修复

- **图表编辑字体别名、另存为/annotate 的 turn 归属与数据加载指引,以及内核 stdin/安装超时处理。** 这三项修复已在本次发布所基于的 rc.4 候选版里上线:[图表编辑字体别名解析与无标题图的 Title 行](../../.agents/notes/implemented/bug-fix/2026-09-03-chart-font-alias-and-title-row.zh.md)、[viewer 写入的 turn 归属与数据加载提示词指引](../../.agents/notes/implemented/bug-fix/2026-09-03-science-viewer-write-turn-attribution-and-data-loading-guidance.zh.md)、[内核 stdin 错误处理与如实的安装超时上报](../../.agents/notes/implemented/bug-fix/2026-09-03-science-kernel-stdin-error-and-install-timeout.zh.md)——经过实机验证的细节见 [0.1.1-rc.4](0.1.1-rc.4.zh.md) 的"修复"一节。
- **内置 Science 技能正文裁到剪枝阈值以下;`skill` 结果不再被截断。** `compaction-tool-result-pruner` 新增了 `exemptTools` Config 字段,Science preset 把它设为 `[skill]`,所以一旦会话大到触发剪枝,`skill` 工具结果——模型本应完整遵循的指令——也绝不会被掐头去尾。三个内置默认技能(`scientific-visualization`、`scientific-writing`、`statistical-analysis`)的正文各自被改写到 8,000 字符以下,低于 preset 8,192 字符的剪枝阈值,所以这个豁免是第二道防线,不是唯一防线;没有技能被整体删减,只是常驻加载的正文变小了,细节被挪进了该技能自己的 `references/*.md`。参见[Science 上下文预算——豁免技能剪枝、缩减内置技能正文](../../.agents/notes/implemented/feature/2026-09-04-science-context-budget-skill-bodies-and-pruner-exemption.zh.md)。
- **Science runtime context 不再每次运行都反复推送;新增运行目录与结果表引用指引。** `science:environment` runtime context 不再在每次 `run_python`/`run_r` 调用后重新渲染一行会变的"Latest run …",所以长会话不会再被迫每次运行都把一份新的上下文快照塞进历史;运行状态仍可按需通过每个运行工具自身的结果和 `get_science_state` 获取。`STATIC_GUIDANCE` 现在明确说明 `SCIENCE_ARTIFACT_DIR` 每次运行都是全新的私有目录——写在那里的文件不会留到下一次运行的目录里,中间数据应放进内核变量或 `SCIENCE_STATE_DIR`,除非它是最终交付物。`statistical-analysis` 技能的 `references/library_result_frames.md` 新增一条规则:对本次会话里还没用过的结果表,先打印其列名再索引,并附上从随桌面端一起分发的环境里读出的 pingouin、scipy.stats、statsmodels 结果对象的验证过的列名。参见[Science 上下文抖动与运行目录指引](../../.agents/notes/implemented/bug-fix/2026-09-04-science-context-churn-and-run-directory-guidance.zh.md)。

### 已知

- **Chart Provenance 下钻没有 Code/Execution-log/Messages/Environment 子标签页。** 它们在成果权威迁移把 `runId`/`toolCallId`/`producerSessionId` 移出客户端安全投影时被移除;`apps/web/tests/science-chart-outcome.e2e.ts` 仍对其中两个做断言,处于红色状态,等待恢复还是简化的裁决,该裁决记在 [0.1.1-rc.4](0.1.1-rc.4.zh.md) 的"遗留"一节里。
- **跨会话成果展示名冲突已定位但未修复。** 两个跨会话共享同一个展示标题的不同成果,可能渲染出两个可访问名相同的 DOM 元素。
- **Onboarding 没有应用内遥测开关。** 其文案说遥测可以随时关闭,但这个版本只暴露了 `DSH_TELEMETRY_DISABLED` 环境变量,没有应用内控件。
- **接收端限流只读取、不留存客户端 IP。** Cloudflare Worker 只把 IP 当作限流 key 使用,不记录也不存储它,在一个 Cloudflare 位置内对每个 IP 每 60 秒放行 20 次请求,采用最终一致计数;阈值不可在运行时配置。
- **DMG 只有 arm64 版本。** 本次发布不产出 x64 构建。
- **一套 nature 期刊风格的配色方案已评估并暂缓**,与内置 `scientific-visualization` 技能自带的 Nature 期刊风格预设及配色参考是两回事。

## 实机验了什么

`0.1.0` 原样沿用 rc.4 记录里已经记下的那次 delta 验收(2026-09-03 深夜,针对上述三项修复上线后用 `0466780272` 重新构建的 DMG),不重复记录;逐项结果见 [0.1.1-rc.4](0.1.1-rc.4.zh.md) 的"实机验了什么"表格。

另有一次探索性的人工会话,发生在 2026-09-04 约 01:00 到 02:10,针对用 `88c43d7d09` 构建的 DMG,不按 checklist 逐项进行:先说"画一张分组箱线图",再说"帮我做个 t 检验",都在 MIMIC-IV 工作区里进行。

观察到:两个中文提示词都触发了对应的内置技能(`scientific-visualization`、`statistical-analysis`),且都在两轮各自写代码之前加载完成;工作区 CSV 通过 `run_python` 加载,得到的 DataFrame 在两轮之间被复用,Kernel #1 全程未变;图表用 `read_image` 做了自检,初稿发现的图例重叠在 v2 里修好,最终成果做了 annotate;统计那一轮先检查了偏度和方差,对 log10(LOS) 跑了 Welch t 检验并配了 Mann-Whitney 稳健性检查,还报告了带置信区间的效应量;模型在会话中提出了两次 `ask_user_question` 澄清。

会话中出现并被当场自我纠正的两次小失误:一次是把中间产物 CSV 写进了某次运行的 `SCIENCE_ARTIFACT_DIR`,又想从下一次运行的目录里把它读回来——这正是上面[上下文抖动与运行目录指引修复](../../.agents/notes/implemented/bug-fix/2026-09-04-science-context-churn-and-run-directory-guidance.zh.md)现在写进 `STATIC_GUIDANCE` 里点名的失败模式;另一次是在一个 pingouin 结果表上猜错了列名,这正是同一项修复新增的 `library_result_frames.md` 参考要挡住的失败模式。这次会话发生在该修复(以及技能正文/剪枝豁免修复)上线之前,所以它是促成这两项修复的证据,不是对它们的复验:两项修复都还没有在设备上被复验过,这次会话也没有复核任何 checklist 条目。

## 遗留

- **x64 DMG。** 本次发布只有 arm64。
- **应用内遥测开关。** 关闭遥测仍需要在应用外部设置 `DSH_TELEMETRY_DISABLED`。
- **阿里云函数计算(FC)遥测接收端。** 本次发布未部署也未配置;生产环境里唯一的接收端是 Cloudflare Worker。
- **一套 nature 期刊风格的配色方案**,已评估并暂缓。
- **系统性的无障碍验收。** 迄今为止没有任何一次发布检查过键盘遍历顺序、屏幕阅读器朗读顺序、焦点可见性,或超出偶然观察范围的 WCAG 对比度。
- **rc.4 记录里的发布后队列**,自被搁置以来一直未再尝试:见 [0.1.1-rc.4](0.1.1-rc.4.zh.md) 的"遗留"一节。
- **在 0.1.0 DMG 上跑一次完整 checklist。** 迄今为止没有任何一次验收对携带本记录这些修复的 DMG 跑过完整的[设备 checklist](../product/device-checklist.zh.md);对外分发前需要补一次。
