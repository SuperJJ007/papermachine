# 0.1.1-rc.4

[English](0.1.1-rc.4.md) | 中文

## 改了什么

### 新增

- **"另存为副本。"** 成果查看器现在能把一个已提交的版本复制成一个全新的逻辑成果,复用源版本的内容寻址字节。参见 [`saveArtifactAs`](../../.agents/notes/implemented/feature/2026-09-02-science-save-artifact-as.zh.md)。
- **Restart Host 菜单动作。** 应用菜单新增 **Restart Host**(⌘⇧R),onboarding 或 Change Environment 打开时会变灰,防止它把 onboarding 窗口本身导航进工作台。
- **Change Environment… 会显示当前环境。** 从菜单打开的 onboarding 现在会在顶部先显示已应用环境的 id、版本号和状态,当已应用版本与标准声明一致时默认给出 "Reinstall",也提供 "Keep current environment",期间不停 Host。
- **Host 日志。** Host 的 stderr 会脱敏、轮转并落盘到 `<Harness 主目录>/logs/host.log`;每个错误页都会点名这个路径,启动失败的路径也不再因为某个继承了 Host stderr 管道的子进程而卡死。参见 [栅格捕获恢复与 Host 诊断](../../.agents/notes/implemented/bug-fix/2026-09-02-raster-capture-recovery-and-host-diagnostics.zh.md)。
- **`SCIENCE_WORKSPACE_DIR` 也覆盖了 R 运行**,与 Python 侧的修复(见下方"修复")对齐:两种内核都能通过相对路径读工作区。
- **有边界、可执行的 `annotate_artifact` 找不到诊断。** 给一个没有匹配成果的名字做 annotate 时,现在会检查最近保留的运行目录(一次有边界的、经过校验的扫描),找到一个合格但未捕获的文件时会点名确切的 `raster_artifacts` 恢复调用,而不是只返回一句"找不到"。同上一篇笔记。
- **对账健康状况在成果库里可见。** 项目首次打开时,一个非模态横幅会点名 `scienceLibrary`/Files 面板发现的 store 与会话日志不一致情况。参见[对账状况呈现](../../.agents/notes/implemented/feature/2026-09-02-science-reconciliation-surfacing.zh.md)。
- **匿名桌面使用遥测。** PaperMachine 会发送 `app.launch`、`environment.installed` 和 `environment.install-failed`，稳定的匿名 id 存放在 `~/.papermachine/.anonymous-user-id`；将 `DSH_TELEMETRY_DISABLED` 设为任意非空值即可禁用发送。已部署的接收端是一个以 D1 为后端的 Cloudflare Worker；本次发布未部署或配置阿里云 FC。参见[匿名桌面使用遥测](../../.agents/notes/implemented/feature/2026-09-01-desktop-usage-telemetry.zh.md)。

### 修复

- **项目成果 store schema v2——成果权威迁移(P0,T1–T5)。** 项目成果 store 成为版本内容来源、生产者、基线版本和创建时间的唯一权威;Science Session 事件现在只携带 store 引用和一份呈现快照。这是一组协同改动:[schema v2 迁移](../../.agents/notes/implemented/architecture/2026-09-01-project-artifact-store-schema-v2.zh.md)本身;[带 W2/W3 收窄的 store↔会话对账](../../.agents/notes/implemented/architecture/2026-09-01-artifact-store-session-reconciliation.zh.md),之后又用基于版本号的缓存失效机制加固,防住了一个陈旧缓存假阳性风险;[经由 HTTP 的原始字节成果读取](../../.agents/notes/implemented/architecture/2026-09-01-science-artifact-raw-byte-reads.zh.md)取代了 base64 RPC,并配了一条匹配的 [HEAD 路由](../../.agents/notes/implemented/bug-fix/2026-09-02-science-artifact-head-route.zh.md);[`science/artifact-saved` 事件瘦身](../../.agents/notes/implemented/architecture/2026-09-02-science-artifact-event-slimming.zh.md)及其 store-is-authority 折叠规则;[客户端图表状态读路径](../../.agents/notes/implemented/architecture/2026-09-02-science-client-chart-state-read-path.zh.md);[由 Runtime 写溯源](../../.agents/notes/implemented/architecture/2026-09-02-science-runtime-provenance-writes.zh.md);以及随之而来的[面向模型的回执字段瘦身](../../.agents/notes/implemented/feature/2026-09-02-science-tool-receipts-slimming.zh.md)。
- **rc.3 6.3——会话恢复丢轮次/步骤。** Science Session 投影现在自带一份浏览器安全的轨迹索引(轮次的生命周期和绑定后每次工具调用的身份/轮次/步骤),Process 视图的归属不再取决于当前加载了哪些对话页;用事故本身导出的会话日志复现并验证了修复。参见[冷态轨迹归属](../../.agents/notes/implemented/bug-fix/2026-09-02-science-cold-trajectory-ownership.zh.md)。同一次排查中还发现并修了一个相关问题——一次纯元数据的重记录(运行已经结算后再做 `annotate_artifact`)会把轨迹锚点的归属改到 annotate 这次调用上。
- **rc.3 9.2——Restart Host。** 已新增,onboarding 打开时变灰(见"新增")。
- **rc.3 2.4——侧栏 Artifacts 开关。** 这个入口现在是真正的三态开关:打开成果库、关闭详情面板,或者从打开的文档返回成果库,不会卡在打开状态。
- **rc.3 3.1——内核当前目录。** 运行工具的说明不再声称运行的当前目录就是它的输出目录(它是不被捕获的私有暂存区);`SCIENCE_WORKSPACE_DIR` 给两种内核都提供了按相对路径读工作区的途径。
- **rc.3 7.6——Skill 产出 PNG 的捕获与恢复。** 见"新增"里的有边界 annotate 诊断,以及同一篇笔记里改正过的恢复说明。
- **一张加载失败的图表图像现在会到达一个终态的失败状态。** 成果图像组件之前没有 `onError` 处理,导致一个缺失或无法读取的 blob 会一直静默处于损坏状态,不提供重试。
- **对账过程中的假阳性孤儿判定被修了。** 一次不完整的事件集合扫描不再设置或清除持久的孤儿健康标记;分类在能做出完整判定之前保持 `unverified`。
- **v2 对账/环境绑定代码里的三处重复实现被抽取消除了。**
- **退出竞态导致 `environment.install-failed` 遥测丢失。** ⌘Q(或应用退出的其他路径)触发的 `before-quit` 让 `app.quit()` 在飞行中的遥测上报请求完成前就放行,把该事件在进程退出时丢弃。`TelemetryReporter` 新增 `flush()`,`ProvisioningCoordinator` 的 `beforeQuit` 钩子改为 `await` 该 flush(commit `ab6924713508`)。已被单测覆盖,尚未随重新打包的 DMG 在设备上复验。
- **rc.3 5.3——图表字号别名解析失败。** `FontProperties(family=<裸字符串>)` 走了 matplotlib 的 fontconfig-pattern 解析路径,拒绝了 `"sans-serif"` 里的连字符,导致一次泛型别名的字号修改被误判为缺字体;R 的 `.dsh_font_available` 对 `sans`/`serif`/`mono` 有同样的失败。一次没能解决任何操作的提交现在会点名每个操作各自的原因,而不是一句笼统的话;图表编辑面板现在始终带一行 Title,即使该图还没有标题。参见[图表编辑字体别名解析与无标题图的 Title 行](../../.agents/notes/implemented/bug-fix/2026-09-03-chart-font-alias-and-title-row.zh.md)。
- **6.5/5.9——另存为归属与 annotate 找不到时的指引(本轮新增);rc.3 3.1/3.2——表格数据经内核加载。** `saveArtifactAs` 和图表编辑的人工编辑提交现在记录查看者操作那一刻正在进行的轮次,而不是等轨迹下次渲染时飘到最新的那一轮。Science 人设现在把 CSV/TSV/xlsx 等表格数据的读取导向 `run_python`/`run_r` 并绑定到一个命名的 DataFrame,而不是 `read`/`glob`,这样后续轮次才能复用它。`annotate_artifact` 的描述现在告诉模型:对一个叫得出名字但没记录的成果也要调用它并转达诊断,而不是自己造一个替代文件。参见[查看者写操作的轮次归属与数据加载提示指引](../../.agents/notes/implemented/bug-fix/2026-09-03-science-viewer-write-turn-attribution-and-data-loading-guidance.zh.md)。
- **9.3——内核 stdin 在收尾期间的 EPIPE;8.1——安装超时与无变化对账。** `KernelProcess` 现在给内核的 stdin 管道挂了一个 `'error'` 监听器,一次与收尾竞态的写入不会再让 Host 以未捕获异常崩溃。`install_science_packages` 有了自己的 `installTimeoutMs`(默认 15 分钟,最多一小时),不再用共享的、以分钟计的 `timeoutMs`;一个在超时宽限期内以 0 退出的进程会被如实报告为成功;一次什么都没改变的安装不会追加环境版本,而一次对账了此前超时写入的安装会追加。参见[内核 stdin 错误处理与诚实的安装超时报告](../../.agents/notes/implemented/bug-fix/2026-09-03-science-kernel-stdin-error-and-install-timeout.zh.md)。

### 已知

- **2.3 深色不是 bug(偏好为 Light)。** rc.3 那次针对"窗口不跟随系统深色模式"的修复,让窗口绘制前的背景无条件跟随操作系统主题,这本身对一个在应用内明确设了 Light/Dark 偏好的用户来说是个回归:他们会看到一闪而过的错误颜色。窗口现在会在绘制前先从存好的 `ui-theme.preference` 解析背景,只有偏好是 `system` 时才订阅系统主题变化。
- **两次实机验收跑在了不同模型上。** 第一轮(针对 `bac8323a8f`)跑在 `deepseek-v4-flash-vision-exp` 上;第二轮(针对 `0466780272`)跑在默认模型上。除了各轮测试者备注自己写明的差异外,没有把某个行为差异具体归因到换模型这件事上。
- **图表溯源下钻没有 Code/Execution-log/Messages/Environment 子标签了。** 成果权威迁移把 `runId`/`toolCallId`/`producerSessionId` 从客户端安全投影里拿掉时,这几个子标签一并被移除;`apps/web/tests/science-chart-outcome.e2e.ts` 里仍有两个断言在测它们,处于红色状态,等待"恢复 vs 简化"的裁决(见下方"遗留")。
- **一个跨会话的成果显示同名冲突已经被定性,但还没修。** 两个不同的成果如果在不同会话间共用同一个显示标题,可能渲染出两个带相同可访问名称的 DOM 元素;这是 rc.4 收口期间发现并记录的,本轮没有独立复现,也没有归到具体某个修复上。
- **rc.3 留下的发布后队列没有变化**:框选改色的作用范围(5.4)、文献检索的年份过滤(7.3)、`/plan` 过度勘察(7.5)、统计 skill 反复重试与未经确认装包(7.7)、一个真正不存在的包的失败被镜像超时盖住(8.2)、Export 依旧禁用(5.6),以及模型切换器的位置属于设计如此(9.1)。
- **Onboarding 没有遥测开关。** 其文案说可随时关闭遥测，但本次发布只提供 `DSH_TELEMETRY_DISABLED` 环境变量，没有应用内控件。
- **接收端限速会读取客户端 IP，但不保留。** Cloudflare Worker 只将 IP 作为限速键，不记录、不落库；每个 Cloudflare location 内每个 IP 在 60 秒内最多接受 20 次请求，计数是最终一致的；该阈值不可在运行期配置。
