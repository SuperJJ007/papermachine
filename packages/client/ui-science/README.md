# @deepseek-ai/dsh-client-ui-science

English | [中文](README.zh.md)

Browser presentation for Science execution cells, Turn-end artifact groups, the Process view, the artifact viewer, the Science settings card, and the Files toggle. The package consumes frozen Tool call/result data and the client-safe `science` Session projection; it does not create Science facts or change model-visible content. The Process view and artifact viewer share the projection and one package-local artifact selection store.

Direct-edit rows use localized, complete kind names in one content-sized label column. Multiple axes group under numbered panel headings, with figure-wide rows first; single-panel figures have no headings. Element references outside grouped rows carry a localized panel suffix only for `axes[n].` ids. Open artifact and file tabs occupy `conversation.details.header.tabs`; the page selector occupies the first header row. Both read the same selection store.

## Process view

Runs and artifact versions place into a turn from the Science projection's own trace — the durable session-log index of every turn boundary and authorizing tool call — independent of which conversation pages are loaded; loading earlier pages adds request text and results but never changes ownership. A run whose authorizing call has no trace entry appears in a separate unassigned-history section with a count and contributes no steps, failures, or elapsed time to a request. An artifact version uses its trace owner coordinate when the projection recorded one; otherwise it uses the store's `createdAt` for that version (read through `sessions.scienceVersions`, batched per artifact by `useScienceVersionSummaries` — see [Artifact viewer](#artifact-viewer-details-entry)) against a turn's own timing window, the same store-time rule a direct human edit already used. The timestamp fallback always resolves some turn (falling back to the most recent inferred turn outside every declared window), so no artifact version reaches the unassigned section. A version whose trace owner coordinate names an exact step also renders its chip inside that step's own row, alongside the turn-level group's chip for its logical artifact's latest version; a version with only a turn (the store-time fallback) renders in the turn-level group alone. A metadata-only re-record — `annotate_artifact` curating title or caption after its producing run has already settled — keeps the version's original producing step, never the currently open call's.

Process contributes `trajectory.view` id `process` and appears only for a Session whose preset or resolved projection is `science`. It is ordered before Detailed, so Science Sessions open Trajectory on Process while other Sessions retain only the Detailed ledger. A single left rail places agent and human-edit cards at full width; human edits retain a user icon and blue left border. A collapsed Turn card has four structured rows: a clamped user request, a full-width ordered step strip, right-aligned totals and disclosure, and artifact chips retaining each artifact's final version for that Turn. No free-form explanation accompanies the request. Long strips and chip rows wrap within the card. The strip caps rendering at 120 calls and reports the full count; the expanded list remains complete.

Clicking a card’s request or background toggles its steps; the native disclosure button supports Enter and Space and reports its expanded state. Strip pips expand and highlight their corresponding row. Independent controls and the entire input/output inspection area retain their own clicks, scrolling and text selection. A row title expands every represented call in place, including all members of a merged browse group. It never selects Detailed. Exact-version artifact buttons open the shared file viewer without changing the active trajectory subview. Turn expansion, call expansion and highlighting survive subview switches but are not persisted.

Each row shows its assistant step number, kind marker, structured title, result and produced artifact versions. Runs also show a bounded literal code preview; grouped reads list their member titles. Local inspection shows logged code, remaining input arguments, tool-result text, separate stdout/stderr when the recorded run format supports them, and available kernel, environment-revision, failure and output-retention facts. Missing results are distinguished from empty results. Code, arguments and output each use the artifact text display limit, show truncation notices and scroll independently; the log is unchanged. Non-text result blocks show their count and types rather than raw attachment data. No assistant prose or inferred code intent enters Process.

Titles use tool names, validated JSON argument fields and Science events. File titles omit directories; annotation and legacy publication titles stop at forty characters. Explicit input inspection can show the original logged paths. Run records determine run status and duration; other failures use tool-result errors. Non-failed consecutive browse calls merge within one Turn while retaining each member. Runs, annotations, legacy publications, delegations and failures remain separate. Step totals count all distinct assistant step numbers containing calls, including numbers inside merged rows; answer-only steps are excluded and parallel calls share a step. Session totals count unique artifacts and sum turn wall time, falling back to completed run durations where turn-end timing is absent. Durations of at least one minute use whole minutes and seconds.

Kernel start, exit and interruption facts appear as timeline markers instead of a separate environment card. A terminal epoch supplies both its start and its end marker; exit reasons explain when variables were cleared. Markers precede the turn containing their timestamp (inclusive start and end), otherwise the first later turn, or follow the final turn. A turn without an end time contains all timestamps at or after its start. The current environment profile labels starts when available.

Visibility is registered through `ctx.trajectorySubviews.registerVisibility('process', source)`. The source rebinds projection subscriptions when the Session list changes, so preset assignment, Session creation, projection resolution, plugin unload, and hot reload invalidate the inner Trajectory switcher directly.

Annotation titles require a logical name and title; a numeric version is displayed only when supplied in the call.

Strip and list markers share two status colors and neutral shapes: muted green run squares, red failure squares, pale neutral browse/delegation/other squares, outlined neutral annotation squares and solid neutral publication circles. Results use plain caption-colored text, with failures in red; blue identifies only the selected row and human operations.

## Turn-end artifacts

Science follows the application theme. Artifact images retain a fixed light canvas in previews and the viewer, without image inversion or dimming.

Science artifact presentation metadata accumulates in authoritative Turn data. After the Assistant reply, one Turn-tail group renders one card per logical artifact and keeps only the highest version produced in that Turn. Cards show a thumbnail or media-type tile, a display name (this Turn's own kept version's curated title, or logical name when that title is empty), and version; activating a card opens that exact version in Science Details. `annotate_artifact` remains a folded process cell and does not render an artifact card at the call site, so files appear once in the transcript. At 6 or fewer artifacts the group shows every card; at 7 or more it shows the first 5 plus a "+N more" button that expands the rest in place. The title's count is always the Turn's total, never the visible slice, and the expanded/collapsed choice is component-local view state that resets on reload.

## Execution cells

`run_python` and `run_r` render running, settled, and unavailable-kernel states (`ScienceExecutionRow.tsx`, `run-output.ts`), driven from the durable tool-result text `tool-science`'s `formatRunResult` produces and the joined `science` Session projection run entry (matched by `toolCallId`) — never a new Host fact. A captured table/chart artifact never renders a chip on the row; every artifact surfaces once, in the Turn-tail group (see above).

1. **Running** — a live `mm:ss` elapsed status and a turn-level Stop (the composer's own control, reused through an injected `cancel`); the row degrades to a static "Running…" summary line since no stdout-streaming channel exists yet — a live tail is future work, not a new channel this row opens.
2. **Success, non-empty output** — stdout stays behind a collapsed row showing line count and byte size; expanding reveals all retained lines.
3. **Success, output truncated** — the fold instead names the retained tail's byte size, with a banner explaining the cap and that the complete output is recoverable from provenance.
4. **Failed** (any non-success status except a died kernel) — a tail-first stderr summary (its last two lines) renders inline in the error color; a second fold reveals the complete stderr.
5. **Kernel exited mid-run** (`failureCode: 'KERNEL_DIED'`) — a distinct amber state naming the exited kernel epoch and the epoch the next run will start, with a "View exit reason" action reusing the row's own `inspect` (the same call-level Trajectory jump every other state offers — no separate kernel-state-event navigation exists yet).

A row falls back to a plain folded cell (collapsed code + settled output, expand-on-click) whenever the science projection has no run entry for this call, or the flattened text does not carry `formatRunResult`'s fixed section markers (a hand-built fixture, or a genuine tool-level exception/turn interruption) — both degrade rather than invent a state the durable facts do not support. Expansion and the live elapsed counter are component-local frontend state, never logged or projected into provider requests.

**Deferred**: promoting an in-memory DataFrame result to its own artifact-like row (the design board's `df — …` chip) waits for the Notebook/Compute data-grounding stage; a "Restart and rerun" action on the kernel-exited state is deferred to keep a rerun routed through the model/conversation rather than a direct client control that would break trajectory consistency.

Every other Tool call (`get_science_state`, `read`, `grep`, `todo_write`, and so on) collapses to a one-line-cell-plus-expand interaction — now organized into `ui-conversation`'s generic Tool group when adjacent — through `ui-tool`'s generic `ToolRow` dispatch fallback, unregistered here — Science neither shadows nor duplicates it.

## Transcript process-detail chrome

The plugin registers `science-edit` as user-authored input through `conversationEvents.registerUserInput`. Chat and Detailed Trajectory show its original instruction and ordered, versioned references; generated transport text stays out of the user bubble. Process uses the logged Turn location, so reference messages survive reload without shifting later requests.

`registerTranscriptDetailVisibility` (`ui-conversation`'s `IConversation`) hides the chat flow's injected-context disclosure row and each turn's `Ran for`/TTFT/throughput labels for a Session that qualifies for Process (`createTranscriptDetailVisibilitySource`, the same reactive predicate as Process's own visibility source, inverted). Both stay reconstructable from the durable log — the context row through the Trajectory detailed subview, the timing figures through the composer dock's whole-session stats strip, which this suppression does not touch. `ui-conversation` renders both unconditionally on its own and only consults registered sources through its `processDetailVisible` chat-node Hook, so it carries no Science-specific code; this package is the sole registrant today.

## Recorded Outcome row

An existing session's settled `publish_outcome` result defaults to a one-line revision summary. Expanding the cell reveals its immutable title, Markdown summary, and run/chart/message evidence; exact chart citations still resolve against the current client-safe `science` projection. Expansion is frontend-only state. The Science tool Consumer offers no publication tool for new calls.

## Settings card

The card registers into `settings.plugin.item` under the fixed `science-runtime` namespace — the namespace `@deepseek-ai/dsh-science-runtime/with-settings` registers, not a package or product id — so it appears whenever the Host serves that namespace and stays absent otherwise, with no navigation row or Host change of its own. It binds the namespace through `ctx.settingsScope` and edits only `['science', 'pythonPrefix']` and `['science', 'rPrefix']` (the section root is the profile map itself, addressed by the fixed `science` profile id, not a `profiles` wrapper field), plus `unsetPath(['science'])` for the explicit remove-override action; no code path writes the section root. Both fields are `role('secret')`, so their stored value never rides a settings response — the card learns per-field presence from `SettingsScopeSnapshot.secrets` and never echoes a stored path back into an input. A blank replacement input is a no-op. The card's status line reports the running Host's actually-bound state against what is currently stored — `effective` (the profile is bound and the Host has already read it), `pendingRestart` (stored and bound disagree, in either direction: a save the Host has not read yet, or a removal the Host is still bound to), or `notConfigured` — read from `SettingsScopeSnapshot.effective` (the value the Host's `restart`-applies Science Runtime entry read at its own registration, frozen until the next Host start) against `.value` (the currently stored section), never from a client-local flag, so the reading survives a page reload. The card owns its own staging and revision fencing rather than importing the Plugins section's card chrome or staged-form model as values, which the bundle-purity gate forbids. Its chrome is built on `@deepseek-ai/dsh-client-ui-primitives`' shared atoms — `Input` for both prefix fields, `Pill` for the Configured/Not configured badge, and `Button` for Save/Discard/Remove override — rather than raw unstyled elements, so the card matches the app's own controls; only the card container's border/radius/background and the collapsed-by-default header/chevron layout, none of which any primitive provides, are this package's own CSS. Collapsed, only the header (name, description, and the expand toggle) is in the accessibility tree — every field, hint, and action button renders only once expanded, matching every sibling card's behavior and accessible-naming register.

## Selection store

The artifact viewer and transcript row share one package-local per-session store (`selection-store.ts`) holding an ordered `openArtifacts` union: `{ kind: 'artifact', artifactId, version }` or `{ kind: 'file', path }`. `activeTabId` is `artifact:<artifactId>`, `file:<path>`, or null for the library home; `libraryPage` remembers whether that home shows artifacts or project files. Artifact entries remain unique by logical artifact and carry their selected durable version in one place. `view` is a shared viewer field: activating a document always returns to content. `provenanceSubTab` selects and persists the Code, Execution log, Messages, or Environment page of the provenance drill-in. The framework's handle × session cache keeps this state shared with transcript rows and alive across a Details-column close/reopen. The engine persists this selection under a session-scoped localStorage key, including the open tabs, library page, provenance page, and collapsed groups, so it survives a browser reload; `view` and `lightboxOpen` are declared transient (`defineStore`'s `transient` list) and always come back from `init()` — a lightbox or provenance drill-in left open when the tab closed must not reopen over the content on the next load.

Artifacts are grouped by the conversation that produced them; groups are collapsible and their collapsed state persists with the selection store. The current conversation stays first, other groups follow their latest artifact time, and sorting applies only within groups. Search filters cards and hides empty groups. Group headers show the conversation title, visible count, and latest relative time using the shared workspace formatter; grid cards are one bordered unit — a full-width 1:1 thumbnail (an image cropped to its top-left corner, or a centered file-type tile) over a footnote with the display title and `vN · <relative time>`, no mediaType text. The list layout keeps its 76px row with the same footnote text. `ProjectLibrary` reads `Date.now()` once per render for both the group headers and every card's footnote.

## Artifact viewer (Details entry)

File previews mount by workspace path and ignore responses after that mount ends. The viewer owns one toolbar lightbox for local and cross-session PNG versions. A settled chart preview does not restart its debounce; see the [viewer lifetime decision](../../../.agents/notes/implemented/bug-fix/2026-08-31-science-viewer-lifecycle.md).

The viewer registers into `conversation.details.view` with id `science` and `primary: true` — the Details column's default entry whenever a session has not explicitly picked one (ui-conversation's `DetailsPanel.tsx resolveActiveDetailsView`; at most one entry in the whole registry may declare `primary`, and a second throws at registration). Its keyed `conversation.details.header.actions` entry places the top-level **Artifacts** and **Project files** page tabs in the Details header while the generic shell retains its close control. It renders from the same `science` Session projection the chart/Outcome rows read, plus the selection store above; its write paths call the Host-owned `scienceEdits` Remote rather than mutating projection state in the browser:

- **Tab strip** — one shared second-level strip for closable artifact and workspace-file tabs; it is absent when no document is open. The library home has no document tab of its own. Clicking either top-level page tab returns an active document to the selected library page without closing its open tabs. Clicking a transcript artifact opens its exact version, toolbar Back returns to the remembered library page, and closing the last document returns there automatically.
- **Toolbar** — for the active tab's content view: a library return button, a version stepper (‹ v*n* ›), provenance/download/save-as/close-tab controls, plus maximize for an image artifact only (a text attachment has no raster to maximize). The stepper skips a same-turn intermediate draft when a later version of the same artifact has the same store-reported producer Session and turn; a human edit and a version without complete producer facts remain in the walk. The currently open version also remains walkable, so a direct link can still open a folded draft; there is no intermediate-draft toggle, per the [removal decision](../../../.agents/notes/implemented/simplification/2026-09-01-remove-intermediate-toggle.md). Each version shows its own current title (via `useScienceVersionSummaries`; D9 — the Files panel and this toolbar read the same store facts). Download HEAD-preflights `scienceArtifactUrl(sessionId, versionId)` (`@deepseek-ai/dsh-client-runtime`'s raw-bytes endpoint) to classify a 410 `missing_content`/409 `content_corrupt`/other failure into inline text before ever creating an anchor, then triggers a bare `anchor.href = url; anchor.click()` relying on the endpoint's own `Content-Disposition` filename — no base64, no `data:` URI, no client-computed filename. Save-as opens an inline naming form calling the injected `saveArtifactAs` (`scienceEdits.saveArtifactAs`); a successful call switches the open tab to the new artifact. Maximize opens the shared lightbox (a second, store-driven `ImageLightbox` instance, since the toolbar is a sibling of the content image's own private click-to-open state, not an ancestor of it).
- **Content** (`ArtifactContent.tsx`) — dispatched by the artifact's current project-store media type (read through the same `useScienceVersionSummaries` batch as the toolbar): `image/png` renders through the package-local `ScienceArtifactImage`, an `<img>` reading `scienceArtifactUrl` directly; a text media type `fetch()`es the same URL and dispatches by media type — `text/csv` as a sortable, scrollable table (`ArtifactTable.tsx`), `application/json` as `JsonTree` (`@deepseek-ai/dsh-client-ui-primitives`), `text/markdown` through `MarkdownText`, and `text/plain` as preformatted text; the browser decodes the response by its `Content-Type` (the endpoint declares none, deliberately — see the raw-byte-reads Agent Note for why guessing a non-UTF-8 encoding client-side is worse than leaving the decision to the browser). The user-facing content omits internal run ids and raw byte counts. JSON and plain text apply `MAX_ARTIFACT_TEXT_CHARACTERS` (100,000) before rendering, and a CSV table renders at most `MAX_ARTIFACT_TABLE_ROWS` (500) rows. These fixed browser presentation bounds (`format.ts`) are not `Config` fields and do not change the deployment's durable file-admission limits.
- **Chart editing** (`ScienceChartEditPanel.tsx`) — `ArtifactContent.tsx`'s `ChartEditSlot` fetches the open PNG version's live chart-object state through `loadChartState` (`sessions.scienceChartState`, via `ISession.readScienceChartState`) once when that version's content mounts, and renders the panel once the read resolves to a non-`null` chart; a version with no stored figure state (imported or legacy content) or a fetch failure mounts nothing. For an `image/png` version whose chart is addressable, a compact always-visible form below the raster exposes title/subtitle, x/y label, grid, font family/size, and legend position without cards or accordions. These controls produce the closed `set_title`, `set_subtitle`, `set_axis_label`, `toggle_grid`, `set_font`, and `set_legend_position` operations. The font field accepts free text through a short fixed suggestion list rather than enumerating installed fonts, and reports an unavailable family as a localized operation failure. Every directly editable row stages a precise reference only through its `+`/`−` action; clicking the row or editing its control never changes reference state. The remaining extracted elements render as wrapping reference rows with complete names and recorded chart colors; their entire surface toggles the reference, with annotations after the first six hidden behind one count control. Direct edits accumulate as pending `ScienceChartOp`s in component-local state — never touching the model or the session log — and receive a debounced Runtime preview. Reference changes never request a preview. Save submits the pending operations through the injected `applyChartOps` (`scienceEdits.applyChartOps`), which commits a new `origin: 'human-edit'` version and steps the open tab to it; Discard clears the pending list. Committed operations stay collapsed, pending operations use one summary line, and a non-empty `failedOps` names each unresolved operation's index and reason. Direct-edit rows and reference chips sit in two side-by-side columns; a details column narrower than 440px stacks them, reference chips below direct edits. While a direct edit is staged or an unsaved preview is displayed, every reference `+` control is disabled and the panel's notice paragraph names the reason (staged edits pending commit or discard, or a preview in view).
- **Edit selection** — every row's `+`/`−` control references the exact artifact version and target into the main composer through the shared `composerSelections` store: a raster's opt-in normalized drag surface for a region target, or an element row's `ScienceElementTarget` (`{ elementId, elementKind, axes, label, current }`, no pixel coordinates). Every PNG offers normalized region selection, including versions with an element catalog. Selecting, hovering, or focusing an element leaves the PNG unobscured. A displayed unsaved preview blocks new element and region references until saved or discarded. Annotation text, Greek series symbols, and duplicate occurrence suffixes use one naming function in the viewer, composer, and sent message; raw ids remain unchanged. Drawing or listing alone stages nothing; the explicit `+`/`−` control stages or unstages the exact target and optional comment. Every comment draft is scoped to its exact artifact identity (artifact id, version, and element id for an element target), and editing a staged comment updates the staged selection immediately. Composer chips show the artifact's display name (the same latest-version curated title the tab strip shows), exact version, and localized element name; `selection.logicalName` stays the wire identity the Host validates admission against, unaffected by the displayed text. Sending one instruction calls `remote.scienceEdits.submit` with an ordered `{ targets, instruction }` request. The Host validates every exact current version and every element field against the addressed chart catalog before enqueueing one `user/message` — a region target also requires a raster media type and mints its selected image as a message attachment; an element target reads neither the store nor mints one. Any missing, media-mismatched, malformed, stale, or catalog-mismatched target rejects the complete request and identifies its list position. The artifact viewer contains no second instruction field or send action.
- **Review notes** — the content viewer lists private notes for the logical artifact and accepts notes against the exact visible version. Add/remove operations use dedicated Remotes and a Session projection; the Host enforces the 8,192-character limit. The empty input contains both the note hint and privacy notice on separate lines. Notes are user-only and never enter model context, and the provenance drill-in does not duplicate them.
- **Provenance drill-in** — one toolbar click away from content (see below); a breadcrumb returns to content.
- **Library home** — the top-level Artifacts page uses `sessions.scienceLibrary` to supply one latest card per logical artifact across the Session's project, with search, sort, and grid/list controls. The top-level Project files page uses `sessions.workspaceFiles` for a searchable, one-level directory browser; a file tab reads at most 2 MiB through `sessions.workspaceFile` and dispatches supported media to the existing content renderers. The home contains no additional section switch. The selected page reloads whenever it becomes visible and when the current Session's artifact projection changes.
- **Reconciliation banner** — the Artifacts page shows a non-modal banner (`ReconcileBanner`, `ScienceDetailsView.tsx`) whenever `scienceLibrary`'s `health.reconstructed` or `health.missingContent` is non-zero, naming each count and offering an expandable list of the affected artifacts (drawn from each artifact's own `latest.health` mark, when its exact latest version is one of the affected ones — an older, non-latest affected version counted in `health` but not itself the library's `latest` row is not individually listed). `health.orphan` is never mentioned by the banner or by any per-artifact mark: an orphan version is `dsh-science-artifact-store`'s documented, accepted crash-window outcome, not a fact worth surfacing as a warning. A library-opened tab whose `latest.health.missingContent` is set shows explicit "content is missing" text instead of its content, and its toolbar disables Download (and hides Maximize for an image) rather than attempting a load that would fail — this treatment applies only to the exact latest version a `scienceLibrary` response marked; there is no version-stepper-reachable equivalent yet (older versions carry no per-item health mark at all).

The viewer renders the artifact library for any current Session regardless of its own `science` projection's state: a Session whose Science mode has not bound yet (`science === null` — a blank Session, or one before its first `science/mode-bound` event) renders the same library home a bound Session with no artifacts would, backed by an inert placeholder projection (`EMPTY_SCIENCE_PROJECTION`, `ScienceDetailsView.tsx`) — the library itself loads through `sessions.scienceLibrary`, a project-wide RPC independent of any one Session's projection, so it needs no real binding to show. Missing projection support (`science === undefined` — the deployment does not compose a Science Session projection at all), an unavailable attachment, and a stale tab naming an artifact/version the projection no longer resolves each render distinct text.

**Design notes — where the former dashboard's facts went.** The resident Environment strip and Runs list do not reappear as session-wide panel sections. Environment facts live only in the provenance drill-in's Environment sub-tab, scoped to one artifact's run. Outcomes remain in the collapsed `publish_outcome` transcript cell rather than a separate Details destination or landing-view section.

Artifact thumbnails and content resolve through this package's own session-scoped loaders (`science-artifact-url-loader.ts`), not the conversation-owned attachment loader. Both resolve to `scienceArtifactUrl(sessionId, versionId)` — the Host's raw-bytes GET route, which accepts a version proven by the Session fold, a corroborated cross-Session input, or exact membership in the Session's derived project, streamed as-is with no base64 pass. `loadImage` resolves immediately to the URL itself (an `<img src>` target); `loadText` `fetch()`es it and returns the decoded response text. Neither keeps a second persistent cache. `science-attachment-loader.ts`'s original base64 loaders (`ISession.readScienceArtifact`) remain, unwired from every registration in this package — see Known Limitations.

**The CSV table (`ArtifactTable.tsx`) is package-local, not a `dsh-client-ui-primitives` export.** A repo-wide grep at design time found no table component anywhere in `packages/client` and no second consumer that would need one; `JsonTree`/`MarkdownText` are reused as-is from `ui-primitives` because they already exist there for other consumers. Parsing (`csv.ts`) is a hand-rolled, RFC4180-style parser (quoted fields, embedded commas/newlines, doubled-quote escaping) rather than a dependency: this is a read-only preview over auto-captured or model-annotated files, never arbitrary untrusted upload, and "configurability does not justify an unsupported... public operation set" (`packages/AGENTS.md`) applies the same way to a speculative shared primitive. A future second consumer is the trigger to promote both into `ui-primitives`, not this one.

## Files toggle

Where the toggle renders is `toggleScope` in this package's Host `Config`: `session` (default) or `global`, validated `z.union(['session', 'global'])`. `session` matches the generic Web presentation fence: the action registers into `conversation.session.header.utilities` and renders nothing unless the current Session summary's `agentPreset` names the built-in `science` preset — a Standard or custom non-Science Session shows no action — with a second `conversation.page.utilities` registration (`ScienceHeroAction`) covering the welcome page while the current Session is blank and already staged to `science` (the header owns the action once that Session starts). `global` registers one unconditional `conversation.page.utilities` action (`ScienceGlobalToggle`) instead and skips the session-header registration entirely, so the toggle is visible app-wide — before any workspace is selected, before any Session exists, and through every later Session state — with exactly one owner; no Session state gates it. Activating either registration calls the owner-supplied toggle callback (`toggleDetailsView('science')` in `session` mode, `toggleDetails` in `global` mode), so the one control both opens the Details column and closes it again; it opens no panel of its own and holds no panel state.

The Host half publishes the resolved `toggleScope` as a `globalThis` boot value ahead of every plugin bundle (`webserver/index-inject`, mirroring `@deepseek-ai/dsh-client-ui-theme`'s own boot-value injection) — the browser half reads it once, synchronously, at its own `apply()`; an absent or malformed value falls back to `session`.

## Provenance drill-in

Reached from the artifact viewer's toolbar (not a separate `conversation.view` tab, and not a keyed `conversation.details.header.actions` entry): a breadcrumb (`<chart title> › Provenance`) whose root segment returns to the content view, over four sticky sub-tabs. Code shows the exact producing run's source; Execution log shows that run's stdout/stderr; Messages shows only the producing Question and Result rows, with actions to inspect the exact tool call and return to its conversation location; Environment shows the current binding for that run. Missing facts produce an explicit unavailable state on the affected page.

The version's `sessions.scienceVersions` summary carries the store-owned producer `sessionId` and optional exact run/call/request coordinates. For a producer in the current Session, the viewer joins those ids to the already-loaded `science.runs` and conversation tool-call projections; it never guesses from a nearby turn or step. A producer in another Session shows the source Session title or id on all four pages and does not attempt a local run/call join. Library-opened artifact tabs request the same authorized version summary before rendering provenance, so the four-page drill-in behaves consistently outside the producer's live projection without widening project-library authorization.

## Workbench shell

Beyond the Files toggle and the Details entries above, this package composes the rest of the Science workbench through additive slots ui-conversation and ui-sidebar declare, each gated on the current Session's `agentPreset` (or, off-Session, on a blank Session already staged to `science`) — no Science surface other than the `global`-mode Files toggle ever appears for another preset or for no Session at all:

- **`sidebar.destinations`** (`ScienceDestinations`) — one Artifacts row beside the sidebar's ordinary destinations for the current Science Session; it renders nothing without a current Science Session. Clicking it toggles the Details column when the artifact library's Artifacts page is already selected, opens that page when the column is closed, and returns an open artifact tab or Project files page to it without closing the column. The mounted Details entry publishes the per-session library predicate and return action because the root-scoped sidebar registration cannot declare the entry's session-scoped selection store; `ctx.conversation.toggleDetailsView` retains the selection-aware panel transition.
- **`conversation.page.utilities`** — the Files toggle's `session`-mode welcome-page hand-off (`ScienceHeroAction`) or its `global`-mode sole registration (`ScienceGlobalToggle`); see [Files toggle](#files-toggle).
- **`conversation.input.accessory`** (`ScienceComposerChips`) — the staged targets above the main composer as removable chips (raw comment text, never re-escaped), reading the package-local `ScienceComposerSelections` per-session store the artifact viewer's `+`/`−` controls also write. A registered `registerSubmissionHandler` claims an ordinary send whenever any target is staged, calls `remote.scienceEdits.submit` with the staged targets and the composer text as the instruction, and clears the staged targets only once the Host accepts; a submission carrying ordinary images is rejected before the Remote call.
- **`conversation.composer.dock`** (`ScienceKernelStatus`) — the latest lifecycle state (`live`/`exited`/`interrupted`) per language from the `science` projection's `kernels` list, below the composer; renders nothing without a projection or a live kernel.
- **`details.files`** (`ScienceEmptyDetails`) — the Details column's placeholder for the true welcome page (no current Session at all — `ui-layout`'s `AppFrame` renders this slot only then; any current Session, blank or Science-unbound included, renders the shared artifact library in the ordinary `details` slot instead, see [Artifact viewer](#artifact-viewer-details-entry)). Explains that opening a session shows the project's artifacts here, and closes the column through the owner-supplied `closeDetails`.

## Composition

Load this browser plugin after `@deepseek-ai/dsh-client-ui-tool`, `@deepseek-ai/dsh-client-ui-attachment`, `@deepseek-ai/dsh-client-ui-conversation` (the header-action and Details-view seats), the client locale/runtime packages, `@deepseek-ai/dsh-client-ui-settings` (`ctx.settingsScope`), and a Host composition that exposes the `science` Session projection. The shipped Web bundle mounts `@deepseek-ai/dsh-science-runtime/with-settings` with an intentionally empty profile map, so the card appears with an unconfigured `science` profile until a person names Python/R Conda prefixes and restarts the Host; CLI and headless bundles keep their own explicit Runtime composition and show no card. The Host row (this package's `main` entry) subscribes to `webserver/index-inject` without declaring `webServer` as an injection (mirroring `@deepseek-ai/dsh-client-ui-theme`'s own Host half); a composition without a webserver row simply never collects the subscription. The desktop app's overlay (`apps/desktop/src/runtime-overlay.ts`) sets this row's `toggleScope: global`, since its own overlay already forces Science as the product default.

## Model Experience

None, as this package does not assemble provider requests; the artifact viewer can ask the Host's `scienceEdits` Remote (`@deepseek-ai/dsh-tool-science`, "Viewer edit message" section) to validate a submitted selection and queue the structured exact-version user message that the model reads.

#### KV Cache effect

None; this package neither assembles nor sends provider requests.

## Known Limitations and Deferred Work

- **Preview is limited to the six direct operations** — title, subtitle, axis-label, legend-position, grid, and font changes use the Runtime's debounced preview path. Reference-only element selection does not render or mutate the chart, or overlay a selection rectangle on the PNG. Reference chips show a swatch after the element name only when its recorded current value supplies a color.
- **The running row's mid-execution summary is static, not a live tail** — no stdout-streaming channel exists between the Runtime and the browser, so a running `run_python`/`run_r` row shows a fixed "Running…" line instead of the design board's latest-stdout-line preview until such a channel exists.
- **A kernel-exited row's "View exit reason" jumps to the failing call, not its own `kernel-state` event** — the row reuses the same call-level Trajectory `inspect` every other state offers; a dedicated jump to the exact `science/kernel-state` fact is future navigation work.
- **No in-memory DataFrame promotion** — a `run_python`/`run_r` result that only produced an in-memory value (the design board's `df — …` row) has nothing to promote to an artifact-like chip until the Notebook/Compute data-grounding stage lands.
- **Turn-end artifacts depend on tagged presentation metadata** — a completed Turn whose tools do not publish `science/artifact` presentation values has no artifact group even if a separate projection later contains related files.
- **No independent artifact cache** — conversation attachments keep using their conversation-owned loader. Science thumbnails and content use stateless loaders over `scienceArtifactUrl`; neither path adds a persistent Map-based cache of its own (`useScienceVersionSummaries`'s own accumulated cache is metadata only, never bytes).
- **`science-attachment-loader.ts`'s base64 loaders are pending removal** — `ISession.readScienceArtifact`'s base64 RPC and its `createScienceImageLoader`/`createScienceTextLoader` factories remain, unwired from every registration in this package (`science-artifact-url-loader.ts`'s raw-bytes factories replaced them everywhere), kept only because the RPC itself may still have non-browser consumers (see the raw-byte-reads Agent Note's own consumer grep). Remove both once nothing needs the RPC.
- **One fixed profile, two fields** — the card edits only the shipped `science` profile's `pythonPrefix`/`rPrefix`, because the built-in preset is the only current product consumer; another deployment profile id remains a file/configuration concern, not a browser-managed one.
- **No discovery, probing, or live apply** — the card never lists, probes, or validates a Conda environment and carries no filesystem picker or live-apply control; a stored prefix only takes effect at the next Host restart, which the card's `pendingRestart`/`effective` status reports but cannot shorten.
- **Environment history is single-revision** — the `science` projection retains only the latest environment binding, so the provenance drill-in's Environment sub-tab cannot show the exact revision an older artifact ran under once the binding has moved on; it reports the revision number and fingerprint preview it still has instead.
- **A text artifact past its applicable render cap is not fully browsable in place** — tables and JSON/text use `MAX_ARTIFACT_TABLE_ROWS`/`MAX_ARTIFACT_TEXT_CHARACTERS`. Download still recovers the complete durable bytes.
- **No PDF chart export** — a disabled localized Export control makes the deferral visible; deterministic PDF export remains deferred.
- **A spec exposing no structural target cannot add a composer chip** — target discovery walks `mark`/`encoding.*` through `layer`, `hconcat`/`vconcat`/`concat` members, and the `facet`/`repeat` sub-`spec`; a document with none of those offers no structural selection, while its read-only render and download remain available.
- **A rendered chart has no text alternative** — PNG artifacts have no accompanying summary or data-table alternative; their source data may be available as a separate artifact.
