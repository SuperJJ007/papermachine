# @deepseek-ai/dsh-client-ui-science

English | [中文](README.zh.md)

Browser presentation for the durable `run_python`/`run_r`, `annotate_artifact`, and `publish_outcome` transcript rows, the Science settings card, the artifact viewer (a tabbed viewer with per-media-type content and a per-version provenance drill-in), and the session-header action that opens it. The transcript rows register keyed `tool.call.toolview` entries and consume only frozen Tool call/result data, the client-safe `science` Session projection, and (for images) the conversation-owned session attachment loader; they neither create Science facts nor load attachment bytes through a separate route. The settings card registers a keyed `settings.plugin.item` entry and reads/writes the fixed `science` profile's Conda prefixes through the bound settings scope. The header action and the artifact viewer register into `@deepseek-ai/dsh-client-ui-conversation`'s `conversation.session.header.actions` and `conversation.details.view` seats; both are pure readers of the same client-safe projection plus one package-local selection store, and neither builds a second projection reader, artifact history, or Outcome editor.

## Artifact row

A settled `annotate_artifact` result with supported tagged presentation metadata renders as a compact navigation row: a thumbnail (an image renders through `MessageImage`; any other accepted media type renders `ArtifactFileTile`, a static icon-plus-extension tile — never a fetch, since a non-image artifact has no raster to load), the logical artifact name, its version badge, and title — no caption, source run, or byte count, which live in the artifact viewer's content toolbar. Activating the row (anywhere but the thumbnail) opens (or activates, at that exact version) that artifact's tab in the shared selection store and opens the Details column on the `science` entry. A hover-revealed control on an image thumbnail opens the shared lightbox directly, so full-screen viewing never opens the column; a non-image tile carries no such control. Running, failed, interrupted, missing, malformed, or unsupported presentation values retain a readable text fallback.

## Run row

A `run_python`/`run_r` result always renders its full rendered text (status, exit code, stdout/stderr, and the durable capture-receipt line) through the same plain-text card the fallback rows share — a run's primary content is that text, not a card the presentation replaces. When the settled result's tagged presentation names one or more files that call's auto-capture produced, the row appends one clickable reference chip per file below the text (icon, logical name, version badge; no thumbnail fetch), each opening that artifact's tab exactly like the artifact row's own activation.

## Outcome row

A settled `publish_outcome` result renders its own immutable revision, title, Markdown summary, and run/chart/message evidence labels. Exact chart citations resolve against the current client-safe `science` projection: an image attachment reuses the same attachment loader for its thumbnail, a non-image attachment renders `ArtifactFileTile`, and an unresolved citation (the projection no longer has that exact version) reports the unavailable visual distinctly from either.

## Settings card

The card registers into `settings.plugin.item` under the fixed `science-runtime` namespace — the namespace `@deepseek-ai/dsh-science-runtime/with-settings` registers, not a package or product id — so it appears whenever the Host serves that namespace and stays absent otherwise, with no navigation row or Host change of its own. It binds the namespace through `ctx.settingsScope` and edits only `['science', 'pythonPrefix']` and `['science', 'rPrefix']` (the section root is the profile map itself, addressed by the fixed `science` profile id, not a `profiles` wrapper field), plus `unsetPath(['science'])` for the explicit remove-override action; no code path writes the section root. Both fields are `role('secret')`, so their stored value never rides a settings response — the card learns per-field presence from `SettingsScopeSnapshot.secrets` and never echoes a stored path back into an input. A blank replacement input is a no-op. The card's status line reports the running Host's actually-bound state against what is currently stored — `effective` (the profile is bound and the Host has already read it), `pendingRestart` (stored and bound disagree, in either direction: a save the Host has not read yet, or a removal the Host is still bound to), or `notConfigured` — read from `SettingsScopeSnapshot.effective` (the value the Host's `restart`-applies Science Runtime entry read at its own registration, frozen until the next Host start) against `.value` (the currently stored section), never from a client-local flag, so the reading survives a page reload. The card owns its own staging and revision fencing rather than importing the Plugins section's card chrome or staged-form model as values, which the bundle-purity gate forbids. Its chrome is built on `@deepseek-ai/dsh-client-ui-primitives`' shared atoms — `Input` for both prefix fields, `Pill` for the Configured/Not configured badge, and `Button` for Save/Discard/Remove override — rather than raw unstyled elements, so the card matches the app's own controls; only the card container's border/radius/background and the collapsed-by-default header/chevron layout, none of which any primitive provides, are this package's own CSS. Collapsed, only the header (name, description, and the expand toggle) is in the accessibility tree — every field, hint, and action button renders only once expanded, matching every sibling card's behavior and accessible-naming register.

## Selection store

The artifact viewer and the transcript row share one package-local per-session store (`selection-store.ts`) holding the open-tabs model: an ordered `openArtifacts` list (one entry per logical chart, each carrying the durable version that tab currently shows), the `activeArtifactId`, a `view` of `'content' | 'provenance'` for the active tab, the `provenanceSubTab` the drill-in last showed, and a `lightboxOpen` flag. The active tab's version is not its own field — it is always read off the matching `openArtifacts` entry, so there is exactly one place a tab's shown version is recorded. `view` and `provenanceSubTab` are single fields, not per-tab: activating a different tab always returns to `'content'`, and the last-chosen provenance sub-tab is a sticky preference carried across tabs. The store is Science viewing state, so ui-science owns it directly rather than adding it to `@deepseek-ai/dsh-client-ui-conversation`'s `ChatStoreState`, which that package owns for state its own skeleton dispatches. One handle is created per plugin fiber and passed as the `store:` registration seat to every entry that needs it, so the framework's own handle × session cache is what makes the transcript row and the viewer agree on one live instance, not a value import between them; that same per-session cache is what keeps a session's open tabs intact across a Details-column close/reopen, independent of `@deepseek-ai/dsh-client-ui-layout`'s own force-close-on-session-switch behavior.

## Artifact viewer (Details entry)

The viewer registers into `conversation.details.view` with id `science` and a registered label from the `science` namespace. It stays read-only and renders from the same `science` Session projection the chart/Outcome rows read, plus the selection store above:

- **Tab strip** — one tab per opened artifact (logical chart), each closable on its own; clicking a transcript chart row opens or activates that artifact's tab at the exact version the row names. With no open tabs the viewer shows its landing view instead of an empty strip.
- **Toolbar** — for the active tab's content view: the artifact's title and logical name, a version stepper (‹ v*n* ›) that steps to the adjacent durable version on either side, and provenance/download/close-tab controls, plus maximize for an image artifact only (a text attachment has no raster to maximize). Download resolves the durable bytes through the same session-scoped loader (`loadImage` for an image, `loadText` for text) and triggers a browser save through a throwaway URI anchor — an image's `data:` URI from `loadImage`, or a `data:` URI built from `loadText`'s decoded string for text; maximize opens the shared lightbox (a second, store-driven `ImageLightbox` instance, since the toolbar is a sibling of the content image's own private click-to-open state, not an ancestor of it).
- **Content** (`ArtifactContent.tsx`) — dispatched by the artifact's durable attachment media type: an `ImageMediaType` renders through `MessageImage` (large image, caption, source run, dimensions); a `TextMediaType` fetches its decoded bytes through `loadText` and dispatches again — `text/csv` as a sortable, scrollable table (`ArtifactTable.tsx`), `application/json` as `JsonTree` (`@deepseek-ai/dsh-client-ui-primitives`), falling back to raw preformatted text for content that parses to a non-object/array or fails to parse at all, `text/markdown` through `MarkdownText`, and `text/plain` as preformatted text. This dispatch is the seam a later accepted media type extends: a new case, never a change to the tab strip or toolbar. A CSV table renders at most `MAX_ARTIFACT_TABLE_ROWS` (500) rows, and non-CSV text is capped to `MAX_ARTIFACT_TEXT_CHARACTERS` (100,000) characters before a JSON parse attempt or a `<pre>` render — both fixed presentation bounds (`format.ts`), not `Config` fields, independent of the deployment's own `textLimits` byte cap that admits the file; a capped render shows a "showing first N" notice.
- **Provenance drill-in** — one toolbar click away from content (see below); a breadcrumb returns to content.
- **Landing view** — shown with no open tabs: a gallery of every logical chart's latest version (opening one opens its tab), and the latest Outcome with its evidence references below it, kept reachable but secondary since it carries no version history or provenance of its own to navigate.

Before the first Science event the viewer shows an unbound state, with the selected preset when the session summary carries one. Missing projection support, an unavailable chart attachment, a stale tab (naming a chart/version the projection no longer resolves — not reachable through ordinary interaction, since a tab is only opened from a resolved selection, but defended against a corrupted store), and no Outcome each render distinct text.

**Design notes — where the former dashboard's facts went.** The resident Environment strip (profile, revision, per-language capability/version/fingerprint/package-count) and the Runs list are gone; they do not reappear as a session-wide panel section anywhere. Environment facts live only in the provenance drill-in's Environment sub-tab, scoped to one artifact's run — the same JSON-with-superseded-revision-fallback behavior the provenance drill-in has always had (see below), now reachable per open artifact instead of duplicated as an always-resident strip. There is no replacement session-wide "environment not applied" notice: that notice belonged to the deleted strip specifically, and a session with no artifact open has nothing to drill into. The two top-level notices that predate the strip — missing projection support and the unbound state — are unrelated to it and are unchanged. The Outcome section stays reachable but moves to the landing view rather than a pseudo-tab of its own, since (unlike a chart) it carries no version history or provenance to navigate — a landing-view section costs no extra chrome and the transcript's own `publish_outcome` row remains the primary way to reach a specific Outcome revision's evidence.

Artifact thumbnails and content resolve through this package's own session-scoped loaders (`science-attachment-loader.ts`), not the conversation-owned one the transcript rows use for images: the Details entry's owner share carries only the Details seam's own `inspectCall` (below), so it calls `ISession.readAttachment`/`readTextAttachment` directly. `loadImage` converts the returned bytes to a `data:` URI; `loadText` returns `readTextAttachment`'s already-decoded UTF-8 string as-is (text is always valid UTF-8 post-admission — no base64 step). Neither keeps a `Map` or an `URL.createObjectURL` handle — nothing to revoke on session release, and no second cache alongside the conversation loader's own.

**The CSV table (`ArtifactTable.tsx`) is package-local, not a `dsh-client-ui-primitives` export.** A repo-wide grep at design time found no table component anywhere in `packages/client` and no second consumer that would need one; `JsonTree`/`MarkdownText` are reused as-is from `ui-primitives` because they already exist there for other consumers. Parsing (`csv.ts`) is a hand-rolled, RFC4180-style parser (quoted fields, embedded commas/newlines, doubled-quote escaping) rather than a dependency: this is a read-only preview over auto-captured or model-annotated files, never arbitrary untrusted upload, and "configurability does not justify an unsupported... public operation set" (`packages/AGENTS.md`) applies the same way to a speculative shared primitive. A future second consumer is the trigger to promote both into `ui-primitives`, not this one.

## Session-header action

The header action registers into `conversation.session.header.actions` and renders nothing at all unless the current Session summary's `agentPreset` names the built-in `science` preset — a Standard or custom non-Science Session shows no action, and no Session ever opens the Details column automatically. Activating it calls the owner-supplied `toggleDetailsView('science')`, so the one control both opens the panel and closes it again; it opens no panel of its own and holds no panel state — the header resolves which direction a click means.

## Provenance drill-in

Reached from the artifact viewer's toolbar (not a separate `conversation.view` tab, and not a keyed `conversation.details.header.actions` entry): a breadcrumb (`<chart title> › Provenance`) whose root segment returns to the content view, over four sub-tabs for the active tab's resolved chart/run:

1. **Code** — the source run's `code` argument, resolved from the conversation snapshot by the run's `toolCallId`, with the durable `codeSha256` shown as the anchor (unlike the environment fingerprint, shown whole — it is a digest over source text the same call already restates verbatim, not a Host-infrastructure fact).
2. **Execution log** — stdout/stderr text from the same call's settled result, with the projection's durable byte counts and truncation flags shown alongside as the authoritative measure — visible even before the transcript is loaded.
3. **Messages** — the request sequence and start time, with a jump-to-transcript action reusing the Details seam's `inspectCall` owner callback (write the one-shot inspect target, switch to the trajectory view) — a summary and a jump, not a message replay.
4. **Environment** — the environment revision as JSON (profile, revision, status, timestamps, per-language capability/version/fingerprint preview, and the package inventory) when the projection still retains that exact revision; a superseded revision (the projection retains only the latest) reports that distinctly, with the run's own fingerprint preview as the retained fact.

Resolving the chart/run pair (and reporting it as unavailable when either no longer resolves) is the artifact viewer's job, not this drill-in's: it always renders for an already-resolved pair.

## Composition

Load this browser plugin after `@deepseek-ai/dsh-client-ui-tool`, `@deepseek-ai/dsh-client-ui-attachment`, `@deepseek-ai/dsh-client-ui-conversation` (the header-action and Details-view seats, and the Details seam's `inspectCall` owner callback the artifact viewer's provenance drill-in reuses), the client locale/runtime packages, `@deepseek-ai/dsh-client-ui-settings` (`ctx.settingsScope`), and a Host composition that exposes the `science` Session projection. The shipped Web bundle mounts `@deepseek-ai/dsh-science-runtime/with-settings` with an intentionally empty profile map, so the card appears with an unconfigured `science` profile until a person names Python/R Conda prefixes and restarts the Host; CLI and headless bundles keep their own explicit Runtime composition and show no card.

## Model Experience

None, as the transcript rows render already-logged Tool results, the settings card edits deployment configuration, and the header action and artifact viewer only read current-state Session projection and conversation snapshot; none changes a model request.

#### KV Cache effect

None; this package neither assembles nor sends provider requests.

## Known Limitations and Deferred Work

- **`annotate_artifact`'s row shows one artifact only** — its tagged presentation always names exactly the one curated entry, so the row is a single compact card, never a chip list; a curation call that could someday annotate more than one file at once would need this row's own list-rendering path (currently only the Run row's chip list has that).
- **No independent attachment cache** — the transcript rows' image thumbnails ride the conversation-owned session attachment loader (owner-supplied `loadImage`), whose lifetime, retry, and object-URL revocation stay owned there. The Details entry's thumbnails and content resolve through its own stateless loaders over `ISession.readAttachment`/`readTextAttachment`; neither path adds a persistent Map-based cache of its own.
- **One fixed profile, two fields** — the card edits only the shipped `science` profile's `pythonPrefix`/`rPrefix`, because the built-in preset is the only current product consumer; another deployment profile id remains a file/configuration concern, not a browser-managed one.
- **No discovery, probing, or live apply** — the card never lists, probes, or validates a Conda environment and carries no filesystem picker or live-apply control; a stored prefix only takes effect at the next Host restart, which the card's `pendingRestart`/`effective` status reports but cannot shorten.
- **Environment history is single-revision** — the `science` projection retains only the latest environment binding, so the provenance drill-in's Environment sub-tab cannot show the exact revision an older artifact ran under once the binding has moved on; it reports the revision number and fingerprint preview it still has instead.
- **Open tabs are not durably persisted** — the selection store lives only in the framework's per-(handle, session) cache, not `localStorage`: open tabs and the active view survive a Details-column close/reopen or a session switch-and-back within the same page load, but not a page reload.
- **A CSV/JSON/plain-text artifact past its render cap is not fully browsable in place** — `MAX_ARTIFACT_TABLE_ROWS`/`MAX_ARTIFACT_TEXT_CHARACTERS` (`format.ts`) stop the table/text render before the whole payload reaches the DOM, so a table sorts and a JSON document parses over the shown prefix only; download still recovers the complete durable bytes.
