# @deepseek-ai/dsh-science-runtime

English | [中文](README.zh.md)

`@deepseek-ai/dsh-science-runtime` provides the folded, host-local Conda Runtime for durable Science environment, run, and artifact facts. It owns `ctx.scienceRuntime`, private per-Session scratch, a persistent per-(session, language) Python/R kernel process, stable prefix observation, exact-Session leases, terminal result classification, auto-capture of run-written files into versioned artifacts, and metadata-only curated re-annotation of an already-captured artifact version. It registers no model-facing tool, prompt, preset, or UI.

## Composition

Load `@deepseek-ai/dsh-session`, `@deepseek-ai/dsh-science-session`, `@deepseek-ai/dsh-science-artifact-store`, `@deepseek-ai/dsh-subprocess-local`, `@deepseek-ai/dsh-sandbox-local`, and this package on the Host; select `@deepseek-ai/dsh-science-session/invariant` where Science Session facts are admitted. The Runtime requires the project artifact store, a `host-local` subprocess provider, and a sandbox provider reporting at least the configured `minimumEnforcement` (`'full'` by default) — no attachment provider: artifact bytes and their cross-session index live in the project artifact store, not the session-scoped attachment store. Its `./invariant` companion has no duplicate event relation because the Science Session invariant owns durable stream validation.

The package configuration names existing absolute Conda prefixes. It does not invoke Conda or create, clone, update, install into, repair, or delete a prefix.

```yaml
- name: '@deepseek-ai/dsh-science-runtime'
  config:
    dshHome: /absolute/test-owned/dsh-home
    timeoutMs: 120000
    kernelIdleTimeoutMs: 1800000
    kernelStartTimeoutMs: 30000
    profiles:
      analysis:
        pythonPrefix: /absolute/conda/python
        rPrefix: /absolute/conda/r
```

`profiles` is a closed map keyed by `ScienceEnvironmentProfileId`. An empty map is a valid explicit unconfigured state; each declared value still has at least one absolute `pythonPrefix` or `rPrefix`. `timeoutMs` defaults to 120,000 and accepts only safe integers from 1 through 600,000; it bounds one `bindEnvironment` or `startRun` operation, including verified project-artifact-store blob reads, a fresh kernel's spawn/`READY` handshake, and the kernel protocol exchange a run waits on. `installTimeoutMs` defaults to 900,000 and accepts only safe integers from 1 through 3,600,000; it bounds one `installPackages` micromamba solve/install attempt separately from `timeoutMs`, since a package solve routinely runs minutes longer than a bind or a run. `kernelIdleTimeoutMs` (default 1,800,000 — 30 minutes, matching Claude Science) and `kernelStartTimeoutMs` (default 30,000) accept only safe integers from 60,000 through 86,400,000 and from 1,000 through 600,000 respectively; `chartExtractTimeoutMs` (default 5,000; 1 through 600,000) independently bounds the post-run chart exchange, and `chartLiveRunsRetained` (default 4; 1 through 64) bounds the kernel's live-figure run registry. `packagesMaxEntries` (default 2,000; 1 through 20,000) and `packagesMaxBytes` (default 65,536; 1,024 through 1,048,576) bound the package inventory retained per observed interpreter, described under Operations below. `bindEnvironment` and `startRun` both resolve the requested profile id through the same map; an id absent from it rejects with `ScienceRuntimeError('PROFILE_NOT_CONFIGURED', …)`, whose message names the missing prefix and points at the Settings → Plugins → Science card rather than the internal profile-id vocabulary. `rasterCapture` (`'declared'` default, or `'always'`) governs whether a `.png` needs the writing run's own declaration to be auto-captured, described under Auto-capture below. `captureMaxFileBytes` (default 5 MiB; 1 through 50 MiB), `captureMaxFilesPerRun` (default 50; 1 through 1,000), and `captureMaxArtifactVersionsPerSession` (default 500; 1 through 10,000) bound auto-capture, described under Auto-capture below. `inputMaxFilesPerRun` (default 20; 1 through 1,000) and `inputMaxBytesPerRun` (default 50 MiB; 1 byte through 1 GiB) bound one run's materialized artifact inputs. Successful curation (`annotateArtifact`) never reads output or store blob bytes, so it has no byte bound of its own; a missing logical name may trigger a bounded, safe path walk over retained per-run directories solely to distinguish a retained-but-uncaptured raster path from an unknown name — `annotateDiagnosticMaxRuns` (default 20; 1 through 1,000) bounds the number of most-recent runs that walk inspects. `micromambaPath` and `installChannels` are each optional but must be configured together — a deployment that sets one without the other fails config resolution; when neither is set, `installPackages` (described under Operations below) rejects with `ScienceRuntimeError('INSTALLER_NOT_CONFIGURED', …)` and no other operation is affected, since binding and running an environment need no installer. `micromambaPath` is an absolute path to the deployment's micromamba executable. `installChannels` is an ordered, non-empty list of `https://` conda channel URLs, each validated by a fixed character allowlist (letters, digits, and `._~/-` after the scheme — no whitespace, control character, or shell metacharacter) since the value reaches `micromamba` argv unescaped; `installPackages` tries each URL in turn as one complete, independent `micromamba install` invocation, stopping at the first success — only a `'failed'` attempt tries the next URL, never a `'cancelled'`/`'timed-out'` one, and no single invocation is ever given more than one channel. `reconcileMaxSessions` (default 500; 1 through 100,000) bounds how many of a project's own session logs one store ↔ session reconciliation pass reads. `reconcileRetryDelayMs` (default 1,000; 1 through 600,000) is the minimum interval between attempts until one complete, cursor-free, error-free pass succeeds; retries are triggered only by a later project resolution, never by a background timer. Both fields are described under Reconciliation below. `minimumEnforcement` (`'full'` default, or `'partial'`) is the lowest sandbox enforcement level Science accepts for an interpreter probe, persistent kernel confinement, or a package install; described under Confinement and environment below for what `'partial'` means and when a deployment sets it.

## Settings-bound entry

`@deepseek-ai/dsh-science-runtime/with-settings` provides the same service over the same `Config`, and additionally resolves `profiles` through the restart-scoped `science-runtime` user-settings namespace, which holds only that map. The Cordis `profiles` map is its composition `base`. The Runtime snapshots the resolved map once at load and does not watch it, so a successful write changes only the next Host start. `pythonPrefix` and `rPrefix` are write-only secrets on every browser-facing settings descriptor.

That entry declares `settings` among its injections, which is what fixes the resolution order: Cordis constructs it only once the settings provider is ACTIVE. A composition that mounts it without a settings provider leaves it PENDING on the unmet injection. Deployments that own their profile map in configuration alone mount the root entry, which never reads settings.

Both entries provide the same `ctx.scienceRuntime` Cordis service, and that service holds exactly one provider: they are alternatives, never mounted together. The shipped Web bundle mounts `with-settings` by default under the Cordis entry id `science-runtime`; a deployment that instead owns its profile map in Cordis configuration overrides that row by id (a patch replacing the row, matching every other bundle-row override) rather than `insert`ing a second Runtime row — inserting a second row throws `service "scienceRuntime" has been registered` at load.

## Operations

`bindEnvironment({ session, profileId, signal })` requires the exact live Science Session object with a durable `science/mode-bound` fact, observes the selected profile, and appends one complete `science/environment-bound` value. A blank session recomposed from another preset into `science` qualifies through that durable fact even though its frozen creation header still names the original preset. Static missing or unusable interpreters become an `invalid` value; cancellation, timeout, prefix I/O failure, confinement reported below the configured `minimumEnforcement`, or an overlapping writable root rejects without an environment event. On success, the enforcement level the confinement actually reported is recorded on the appended binding as `sandboxEnforcement` — the weaker of the two declared languages' own reported levels when both ran (they confine under the same sandbox provider and the same configured minimum, so they report the same level in practice, but the recorded value stays an honest minimum rather than depending on which one happened to run first). Each available interpreter's identity also carries a package inventory: name/version pairs sorted and digested over the complete observation, then retained up to `packagesMaxEntries`/`packagesMaxBytes`; exceeding either cap truncates the retained list and sets `packagesTruncated`, while the digest still covers the complete pre-truncation inventory. A package-inventory probe that does not produce parseable output makes the whole interpreter observation `invalid`, matching the version and UTF-8 probes' honest-failure behavior. `bindEnvironment` itself rejects a second call once the session has any run (`ScienceRuntimeError('ENVIRONMENT_NOT_READY', …)`); that guard, not the durable projection, is what stands between this Runtime and representing a later environment revision against a session that has already run — the Science Session fold already admits an `applied` revision superseding an earlier one once no run is currently in flight. `bindEnvironment` itself is never called a second time in the shipped product: `installPackages` (described under Operations below) reaches a later environment revision through an entirely separate, deliberately unguarded append path instead of lifting this guard.

`startRun({ session, language, code, artifactInputs, editBaselines, toolCallId, requestHeaderSeq, signal })` executes `code` in this session's persistent kernel for `language`: one long-lived confined process per (session, language), so a Python and an R kernel may both be live in the same session at once. A kernel starts lazily on the first run that needs it and keeps the interpreter's in-memory state — variables, imports, definitions, and any inline `pip install`/`install.packages()` effects — across every later run for the same language until it ends. Each kernel instance carries a `kernelEpoch`, a session-local counter strictly monotonic across both languages: two runs sharing an epoch shared the kernel's in-memory state; a run whose epoch differs from an earlier one ran against a fresh kernel that never saw it. The kernel environment exposes the immutable Session workspace as `SCIENCE_WORKSPACE_DIR` for reads without changing the kernel's scratch working directory or the per-run output directory. Before start publication, the Runtime resolves every `artifactInputs` entry against the live Science projection — falling back to the owning project's artifact store when this session's own projection has never recorded the referenced artifactId, so a run may also name an artifact a different session in the same project produced — reads its immutable content through the project artifact store's verified blob-read path, and writes the exact bytes below `<run>/inputs/<path>`, the same directory the kernel driver publishes to the running process as `SCIENCE_INPUT_DIR`; input paths are forward-slash relative file paths and reject escape, case-folded/Unicode, duplicate, and file-versus-directory collisions. `SCIENCE_INPUT_DIR` is outside `SCIENCE_ARTIFACT_DIR`, so an input cannot be auto-captured. The complete ordered mapping is appended on `science/run-started` and repeated by the terminal fact. A missing version rejects with `INPUT_NOT_FOUND`, an invalid or colliding path with `INPUT_PATH_INVALID`, and either configured input bound with `INPUT_TOO_LARGE`; all reject before publication and leave no published run or retained unpublished run tree. `startRun` writes `code` unchanged into the same private run directory, appends `science/run-started` naming the executing kernel's `kernelEpoch` before the exchange begins, and returns a `ScienceRunHandle`. The handle exposes only `runId`, `done`, and idempotent `cancel()`; it exposes neither a PID nor Host scratch paths. Its resolved result carries the committed terminal record plus bounded operational stdout/stderr tails, exact byte counts, and truncation facts. Output text never enters a Science Session event.

Immediately after resolving the applied environment, `startRun` also checks whether the shared prefix backing it has drifted since this session's own binding last observed it (#15: a different session's `installPackages` call writes the same shared prefix without ever touching this session's `science/environment-bound` history): for each declared language with an `available` binding, it re-reads `<canonicalPrefix>/conda-meta/history` and compares its SHA-256 against the binding's recorded `condaHistorySha256` — one small file read per declared language, no probe, no confined subprocess, and this check runs on every `startRun` call. A digest that no longer matches, including one that can no longer be read at all (missing, replaced with a directory or symlink, or any other read failure — all count as drift, never as "no drift"), re-observes the whole profile through the exact re-observe/append path `installPackages` uses below and, only when the re-observed profile actually differs, appends a fresh whole-value `science/environment-bound` revision; `startRun` then plans and runs against that fresh revision, and a kernel still serving the stale one restarts (`environment-rebound`, described above) the same way it would after this session's own `installPackages` call. The genuinely expensive part — both declared languages' version/UTF-8/package-inventory probes — runs only once drift is actually detected, not on every call. A re-observation that comes back anything other than fully `applied` never appends: `bindEnvironment` cannot rebind a session past its first run, so appending an `invalid` revision here would strand the session permanently; `startRun` instead rejects only that one call with `ENVIRONMENT_NOT_READY`, leaving the session's last-known-good binding in place so a later call against a recovered prefix still goes through.

The kernel is a small driver script the Runtime ships as a package asset — `kernel_python.py` (Python standard library only) or `kernel_r.R` (base R only, no `jsonlite`, matching the R package-inventory probe's own TSV choice) — since a user-configured prefix cannot be assumed to contain any notebook-kernel package and the Runtime never installs into a prefix. The host writes one-line requests to the kernel's stdin and reads one-line responses over a response-channel transport selected once per kernel by `selectKernelTransportKind` (a pluggable `KernelResponseTransport` seam in `kernel-transport.ts`): on darwin and linux, a FIFO it creates in the kernel's private scratch, forwarded through an owned POSIX `cat` subprocess so idle reads never occupy Host filesystem workers; on win32, a loopback TCP listener on `127.0.0.1` bound to an ephemeral port, accepting connections until one presents a 32-hex-char random token minted for that kernel — a connection with an incorrect or missing token, or one that otherwise fails the handshake, is destroyed while the listener keeps accepting further connections until the kernel-start deadline or the kernel process itself exits; only the correctly-tokened connection stops the listener, so a genuine second connection attempt after that one is refused. Both transports hand `KernelProcess` the same thing: a readable byte stream carrying the identical wire-protocol frames, and an "ended"/"errored" signal; the frame parser and kernel state machine never know which transport produced them. Named pipes were rejected as the win32 choice: a Windows ACL sandbox may not grant the write-restricted kernel process token write access to a Host-created named pipe, while a loopback socket is not an ACL-securable object at all. A run's stdout/stderr are written to per-run capture files the request names, not to the kernel's own stdio. Python redirects a run's output at the file-descriptor level (`os.dup2`), so C-extension and child-process writes are attributed to the correct run. R captures only at the `sink()` level: R-level `print`/`cat`/`message` output is attributed correctly, but C-level or child-process writes bypass `sink()` and land in the kernel's own long-lived, bounded stdout/stderr collectors instead, never attributed back to any run (see Known Limitations). When the driver detects it could not fully restore or attribute a run's output capture, the run's terminal event carries `outputDegraded: true`; the run's own result still stands, only its captured tails may be incomplete.

Accepted TCP sockets retain error handling while queued, during token parsing, and after response-channel handoff. A reset during failed-startup cleanup closes the connection without escaping as an uncaught Host exception; token and frame consumers retain their normal error classification.

A kernel ends for one of a closed set of reasons, normally appended as `science/kernel-state` (`state: 'exited'`): `idle` (`kernelIdleTimeoutMs` elapsed since the kernel's last completed run, with none since — disarmed while a run is in flight), `session-end` (the owning Session detached — this append targets the already-detached in-memory log, so it is never published or durably persisted; replay recovers the kernel as `interrupted` from `session/end-seed` instead, see Known Limitations), `environment-rebound` (a newer applied environment revision exists for the kernel's language; the next run for that language ends the stale kernel first and starts a fresh one against the new revision), `run-escalation` (an interrupted run left the kernel's own state unproven, see below), `protocol` (the driver broke the wire protocol — an unparseable frame, an unexpected end of the response channel, or a `READY` handshake slower than `kernelStartTimeoutMs`), and `crash` (the kernel process exited uncommanded with no protocol violation observed). A run whose kernel died uncommanded mid-run settles with `failureCode: 'KERNEL_DIED'`. Every run's terminal event, and `get_science_state`, name the executing `kernelEpoch`, so the model and a Reviewer can tell exactly which runs shared memory. A response-channel TCP reset receives the same bounded process-exit observation as EOF: a dead kernel is a crash, while a still-live kernel with a closed channel is a protocol failure. Stream errors during requested shutdown do not replace its commanded exit cause.

Cancelling or timing out a running kernel execution interrupts before it kills: the Runtime sends the kernel process `SIGINT` and waits a fixed grace window for the kernel to reply that it caught the interrupt. If it does, the run's terminal is `cancelled`/`timed-out` as usual and the kernel keeps running with its state intact — the next run for that language still sees every earlier variable. If the kernel instead finishes the run normally (its own code raced the interrupt, or caught and swallowed it) or does not reply within the grace window, the kernel's own state is no longer trustworthy: the Runtime ends it once the run settles (`run-escalation`), and the next run for that language starts a fresh kernel. Either way the run's own terminal status is decided purely by what caused the abort (cancel vs. timeout), never by what happened to the kernel. On win32, `interrupt()` is a documented no-op (there is no `SIGINT` equivalent this Runtime sends): every cancelled or timed-out win32 run falls straight through the no-reply path above, always escalating to `run-escalation` and always losing the kernel's in-memory state — see Known Limitations.

### Auto-capture

Auto-capture advances its session projection through every event committed during artifact-store writes, including kernel exits and user title changes. A concurrent event does not invalidate the capture receipt.

Immediately after every run's terminal fact commits — success, failed, timed-out, or cancelled alike — the Runtime walks that run's private `SCIENCE_ARTIFACT_DIR` and durably saves every eligible file as the current version of the logical artifact named by its path relative to that directory (`plots/loss.png`, `summary.csv`). A version is the project artifact store's own per-artifact ordinal: changed content always opens the next version, regardless of which turn or run produced it (only a model curation, `annotateArtifact` below, supersedes a version in place). The store row commits before its `science/artifact-saved` event, so the event's `version`/`versionId` and the store's own ordinal always agree. `requestHeaderSeq` remains authorization and provenance, not version identity. Eligible means: no dotfile or dot-directory path segment, and a lower-cased extension in the fixed allowlist `.csv`, `.json`, `.md`, `.png`, `.txt` — a file-format allowlist matching Science's own frozen `ScienceArtifactMediaType` set (`dsh-science-session`), not a Loader-exposed knob. Under the default `rasterCapture: 'declared'` policy, an otherwise-eligible `.png` is captured only when `StartScienceRunRequest.rasterArtifacts` names its capture-relative path for that same run; an undeclared `.png` is left uncaptured and its path is returned in the result's `skippedRasterPaths` (`'always'` captures every eligible `.png` unconditionally, matching every other extension). Each run owns a different private output directory, so an empty later run cannot capture a file the earlier run left undeclared; the caller must rerun the code that writes the PNG and declare that same path in the new run's `rasterArtifacts`. A captured version's store row carries `content_origin: 'run-auto'`, its full producer provenance (`producerSessionId`/`producerRunId`/`producerToolCallId`/`producerRequestHeaderSeq`/`producerTurn`, the authorizing run's own turn number), and the full 64-hex-character `environmentFingerprint` (not a preview); a separate `actor: 'capture'` annotation sets the title to the file's basename. Content addressing makes admission idempotent — the store's current head for that logical name, not this session's own local history, is the authority both for that check and for the human-edit stale-skip below (T1's authority rule; a `getLatestVersion`/`listVersions` read, not `origin` on the session event) — so a byte-identical rerun of the same logical name is silently skipped rather than committing a redundant version. A `science/artifact-saved` append the Session refuses after the store row already committed marks that row `orphan` on the store's own `version_health` immediately, rather than leaving it for a later reconciliation pass to discover. Captured images are admitted exactly as written: the project artifact store is a pure content-addressed byte store with no normalization step of any kind, so the stored bytes are exactly the bytes the run wrote — scientific evidence — and a later read-back compares byte-identical.

#### Chart addressability

A captured PNG saved through matplotlib `Figure.savefig()`/`pyplot.savefig()`, ggplot2 `ggsave()`, or a single complete ggplot printed between `png()` and `dev.off()` can carry a `chart` projection. The kernel retains an export-time figure snapshot and export settings; previews and saved edits operate on fresh copies. R keeps the rendering device, DPI, dimensions, and font options. The artifact store owns the exact PNG bytes and ordinary metadata. Base graphics, viewport composition, multiple plots on one device, and paths excluded by capture remain ordinary raster artifacts.

Element extraction and hit-map extraction fail independently. Matplotlib records positions during the final export draw, including `bbox_inches='tight'` cropping; repeated annotation ids resolve to their own artist occurrence. R extracts automatic axis labels from the built plot and only emits hit-map ids present in the catalog. Unsupported geometry retains the catalog with `hitmapStatus: 'unavailable'`. Any chart timeout, protocol error, invalid result, adapter error, or missing registration leaves ordinary PNG capture intact; `chartUnavailablePaths` records affected paths for diagnostics without entering model output.

Each kernel keeps registrations for the newest `chartLiveRunsRetained` run ids and prunes older runs after extraction. Repeated saves to the same run-relative path replace that path's registration, so extraction describes the figure and export settings from the final save.

Element ids are unique within one catalog: the host codec rejects a chart carrying two elements with the same id, so each adapter appends a stable `#N` suffix to a colliding id (for example, two bar-value annotations whose rendered text matches) in first-occurrence order before hit-map extraction runs.

A series or annotation id embeds a sanitized, truncated snippet of the underlying figure text (a series label, an annotation's text): each adapter replaces control characters — including newlines in multi-line labels or annotations — with a space, collapses whitespace runs, and caps the result at 60 characters, keeping the wrapped id safely under the host codec's 200-character limit even with an axes prefix and a `#N` dedupe suffix. A snippet that sanitizes to nothing (for example, whitespace-only text) falls back to a positional placeholder such as `series[3]` or `annotation[2]`. The element's own `label` field is never sanitized or truncated — it keeps the exact original text for display.

The catalog retains all 13 element kinds for display and precise model references. The closed direct-operation set is `set_title`, `set_subtitle`, `set_axis_label`, `set_legend_position`, `toggle_grid`, and `set_font`; both adapters implement all six, and preview accepts the same codec. The `font` element's `current` value contains only `family` and `size`; it never enumerates installed families or carries truncation metadata. `set_font` checks the requested family through the plotting runtime and returns `font_not_found` without changing the figure when exact resolution fails. The matplotlib adapter applies the resolved family and size to the figure's existing `Text` objects without mutating global `rcParams`, and records that figure-wide value for post-export extraction; the ggplot2 adapter applies and re-extracts it through the plot theme.

`set_subtitle` changes the ggplot2 plot subtitle or the selected matplotlib axes titles (`axes: null` selects all axes), leaving the main title untouched. Main-title and subtitle edits remain separate operations even when both have a null axes target. An all-axes legend operation visits every selected axes, including those following an axes without a legend. Figure copies normalize the DPI transform to logical DPI before export, so display pixel ratios do not alter saved PNG dimensions.

A matplotlib figure extracts its axes title as `kind: 'title'` (not `'subtitle'`) when the figure has no `fig.suptitle()` and exactly one axes; a figure with a suptitle, or more than one axes, keeps the axes title as `kind: 'subtitle'`. ggplot2's own title is always `kind: 'title'` (ggplot2 has no equivalent to matplotlib's per-axes title on a single-axes figure), so the two runtimes agree on a single-axes chart's own title kind.

`set_legend_position` maps the shared position enum to each runtime's own placement mechanism. matplotlib passes every value straight to `Axes.legend(loc=...)`, its own native enum. ggplot2 4's `theme(legend.position = ...)` accepts only `"right"`/`"left"`/`"top"`/`"bottom"`/`"inside"`/`"none"` — passing an unrecognized string (a raw matplotlib corner/edge value) silently drops the legend rather than erroring, so the ggplot2 adapter maps deterministically instead of passing the enum through:

| `position` | ggplot2 `theme()` |
|---|---|
| `best`, `right` | `legend.position = "right"` (ggplot2 has no automatic-layout equivalent to `best`, so it takes the same outside placement as `right`) |
| `upper left`, `upper right`, `lower left`, `lower right`, `center left`, `center right`, `upper center`, `lower center`, `center` | `legend.position = "inside"` plus `legend.position.inside`/`legend.justification.inside` set to the matching normalized corner/edge/center coordinate (`x`, `y` each `0`, `0.5`, or `1`) |

Every other `position` value is a codec-level bug, not a legal runtime input, and fails the operation (`stop("unknown_legend_position")`) rather than silently dropping the legend. Extraction reads an inside legend's position back as `current: { position: 'inside', inside: [x, y], ... }`, so a direct edit's new placement round-trips into the panel's own display.

##### Direct edits

`applyChartEdit({ session, artifactId, version, ops, signal })` applies a non-empty bounded operation list to the exact current addressable PNG version. Its source is the nearest run-origin version of that artifact, not another run with the same filename. Every preview and save copies that source's saved figure, applies the committed operations followed by the requested operations, and exports with its saved settings. If the registration has expired, the Runtime re-executes that source with its exact materialized inputs in a disposable interpreter with its own home, state directory, and package-install tree. Recovery cannot mutate the analysis kernel's variables, mutable objects, modules, or process settings, and creates no scientific run or persistent kernel-state event. Source that depends on undeclared in-memory objects or kernel-local installs fails with `CHART_NOT_ADDRESSABLE`. A committed operation that cannot be reconstructed rejects with `CHART_NOT_ADDRESSABLE` rather than silently dropping part of the version.

The existing `timeoutMs` bounds the whole preview/save operation, including cold startup and source replay; `chartExtractTimeoutMs` also bounds each chart exchange. Operation cancellation or expiry of `timeoutMs` rejects with `OPERATION_CANCELLED` or `OPERATION_TIMED_OUT`, waits for recovery-process cleanup, and releases its session lease. A failed recovery leaves the analysis kernel intact; an interrupted warm chart exchange retires its own kernel. See [cold recovery isolation](https://github.com/SuperJJ007/papermachine/blob/44575f3bf0/.agents/notes/implemented/bug-fix/2026-08-31-science-cold-replay-isolation.md).

Every successful save appends an immutable `content_origin: 'human-edit'` PNG version to the project artifact store: `baseVersionId` names the requested version (`baseExplicit: true`), `environmentRevision`/`environmentFingerprint` are copied unchanged from that version's own store row (an assignment, not a re-validated fold check), and no producer run/tool-call fields are set beyond `producerTurn` — the session's last started turn, read once when `applyChartEdit` is called and not re-read afterward, so an edit applied during an idle gap between turns attributes to the turn that was current then, not to whichever turn is newest once the store write commits. The store's `figure_state` side table for the new version holds the prior successful operations followed by the successful new ones. A separate `annotateVersion` call (`actor: 'human'`) inherits the requested version's current title/caption onto the new one; the model never authorizes this metadata edit. A partially unresolved request commits its successful operations and reports indexed `failedOps`; a request with no resolved operation rejects with `CHART_ELEMENT_NOT_FOUND`, whose message lists each rejected op's 1-based index, op name, and resolution reason (for example `set_font`'s only reason, `font_not_found`) rather than a single generic summary. `previewChartEdit` publishes no version and leaves the saved figure unchanged, including when all pending operations fail. Discarding a preview therefore cannot affect a subsequent save. Title and axis-label edits retain existing text styling. Tight-cropped exports may change their outer bounds when edited text extents change; the crop policy itself is preserved. See the [editing isolation decision](https://github.com/SuperJJ007/papermachine/blob/44575f3bf0/.agents/notes/implemented/bug-fix/2026-08-31-chart-edit-baseline-isolation.md).

Exact-version and addressability failures reject as `CHART_STALE_VERSION` and `CHART_NOT_ADDRESSABLE`; malformed or over-limit operations reject as `CHART_OP_INVALID`. A source run whose retained scratch is unavailable cannot be recovered and is not guessed. The Consumer exposes direct edits to later model turns only as an operation name and element target plus `editCount`; title text, label text, legend position, and grid visibility stay out of sanitized state and receipt summaries.

Artifact identity is project-scoped, not session-scoped: the project artifact store's own `UNIQUE(owningProjectId, logicalName)` constraint is the sole authority for whether a logical name names a new or an existing artifact. A logical name this session's own fold has never recorded still continues an existing artifact when a lazy, once-per-walk `store.listArtifacts(projectId)` lookup finds one another session in the same project already created — a concurrent create race that same lookup missed is recovered by re-resolving the winner and appending onto it rather than failing the file. Cross-conversation relationships may also be made explicit through exact-version `artifact_inputs`; `edit_of` (`editBaselines`) still resolves only against this session's own live projection. Historical logs retain their recorded ordinals.

Each `editBaselines` key is a validated capture-relative output path whose value names an exact committed artifact version. If that path is captured, the new version's `baseVersionId` names it (`baseExplicit: true`): an existing logical name advances its own artifact as usual, a new logical name creates a new artifact whose first version has a cross-artifact base, and naming an older version records a visible branch instead of silently rebasing to latest. A missing baseline rejects before publication with `ARTIFACT_NOT_FOUND`. Outputs without a baseline retain ordinary capture behavior, and unchanged content remains skipped.

`captureMaxFileBytes` bounds one file's admitted size (an oversized file is skipped and counted, never a run failure). `captureMaxFilesPerRun` bounds eligible files attempted from one run; the excess are truncated (not attempted) and flagged in the returned accounting. `captureMaxArtifactVersionsPerSession` bounds artifact versions a session accumulates through auto-capture across every run; once reached, capture stops appending further versions for the rest of that run (and every later run) and flags it, until a future retention pass reclaims headroom. A capture failure — an oversized file, a truncated cap, or an unexpected exception — never fails the run whose terminal fact already committed.

`annotateArtifact({ session, logicalName, version, title, caption, toolCallId, requestHeaderSeq, signal })` resolves the named logical artifact's exact `version` (or its latest, when omitted) against the live Science projection and appends one new `version_annotations` row (`actor: 'model'`, this call's `sessionId`/`toolCallId`/`requestHeaderSeq`) naming the supplied `title`/`caption` — the store's content-addressed reference, producer fields, and `created_at` are untouched. Curation is metadata over content the session already holds, so it never advances the version a reader sees, and an omitted `caption` clears any prior one (every call is authoritative for both fields). It never reads or imports output bytes, never reads blob bytes from the project artifact store, and never publishes a Host path. When the logical name is absent, it checks the newest `annotateDiagnosticMaxRuns` retained runs, per run first for the exact eligible PNG under `SCIENCE_ARTIFACT_DIR` using the same safe walk as capture, then — only when that finds nothing — for the same PNG at the run's own scratch root outside it. Either match changes only the `ARTIFACT_NOT_FOUND` message: an undeclared `SCIENCE_ARTIFACT_DIR` match tells the caller to rerun the writing code with that path in `raster_artifacts`; a scratch-root match tells the caller to rerun the writing code, save the file under `SCIENCE_ARTIFACT_DIR`, and declare it in `raster_artifacts`. Either way the store and projection remain unchanged, and a later empty run cannot recover the file because output directories are per-run. Beyond the shared pre-publication failures it otherwise rejects with `ARTIFACT_NOT_FOUND` when `logicalName` or its named `version` does not exist in this session, `ARTIFACT_NOT_CURATABLE` when that version's store row is a direct human style edit (`content_origin: 'human-edit'`) — curating it would either erase the direct-edit discriminator or claim a model authorization the edit never carried, so the message points the caller at a new run or the viewer's style editor instead — and `ARTIFACT_ANNOTATE_TOOL_CALL_REUSED` when the project store's write transaction finds that the same `(sessionId, toolCallId, requestHeaderSeq)` already authorized any prior model annotation, including one a later metadata edit superseded.

`saveArtifactAs({ session, sourceVersionId, newLogicalName, signal })` duplicates one committed store version into a brand-new logical artifact in the same project: `createArtifact` with a fresh `artifactId`, ordinal 1, `baseVersionId` naming the source explicitly (`baseExplicit: true`), the source's own `contentOrigin`/`mediaType`/`environmentRevision`/`environmentFingerprint`/`figureState` (when the source is a PNG carrying one) carried over unchanged, and `producerSessionId`/`producerTurn` set to the calling session and its last started turn — a fresh producer fact, not a copy of the source's own. `producerTurn` is read once when `saveArtifactAs` is called and not re-read afterward, so a save-as during an idle gap between turns attributes to the turn that was current then. The source's bytes are re-admitted (never re-read from an existing blob path and re-written) through the store's own content-addressed `createArtifact` call, which is idempotent by digest, so no byte is ever duplicated on disk. A separate `actor: 'human'` annotation copies the source's current title/caption forward, mirroring `commitStyleEdit`'s own title-inheritance annotation. `sourceVersionId` may name any version the project's store holds, not only one this calling session's own projection already knows — the store, not session-local history, is the authority a viewer-driven duplication reads. A viewer operation: no `toolCallId`/`requestHeaderSeq`, and never exposed as a model tool. Beyond the shared pre-publication failures it rejects with `ARTIFACT_VERSION_NOT_FOUND` when `sourceVersionId` does not identify a committed version in the session's owning project, and `ARTIFACT_LOGICAL_NAME_CONFLICT` when `newLogicalName` already names an artifact in that project (the store's own `LOGICAL_NAME_CONFLICT` translated onto the Runtime's error vocabulary).

### Reconciliation

The Runtime triggers a bounded full-project store ↔ session reconciliation attempt — `dsh-science-artifact-store`'s `reconcile.ts` algorithm, comparing the store's version rows against this project's `science/artifact-saved` events — when `sessionProject` resolves a project id. It retains per-project session-collection and store-work cursors between eligible attempts, so each truncated call advances instead of repeating a fixed prefix. A complete event collection followed by a cursor-free, error-free store pass suppresses every later attempt for that project during the Host lifetime. Any collection failure, unreadable log, malformed target event, pending session or store work, store item error, or rejected store call leaves the project eligible when another session resolves it after `reconcileRetryDelayMs`; no background timer or retry loop is created. Every attempt runs fire-and-forget: it never blocks or delays the Science operation that triggered it, and every failure is logged through `ctx.logger.warn` and otherwise swallowed rather than propagated. A deployment with no `sessionPersistence` service mounted skips the attempt entirely rather than treating the missing service as an error.

`collectProjectArtifactEvents` (`reconcile-trigger.ts`) is the one place this Runtime reads a durable session log outside its own live Session: it lists every session whose header `cwd` resolves to the project's canonical workspace path, reads each through `SessionPersistence.inspect()` (raw, undecoded events — bypassing `dsh-science-session`'s codec, so a field the store's fallback reconstruction needs is not silently stripped by a codec built for a slimmer live shape), and folds their `science/artifact-saved` events per `versionId` in listing order (last write wins). Successful per-session results accumulate across calls; `reconcileMaxSessions` bounds each call, and an unreadable or malformed session rotates behind the unvisited tail so it cannot prevent later sessions from being read. A list failure or any pending session leaves the result incomplete, and only coverage of the full matching set permits absent-event orphan classification. The accumulated event set, completeness flag, and store cursor are handed to `ScienceArtifactStore.reconcileProject`, which never writes a session log. An incomplete set classifies a store row with no event as `unverified`, preserves its existing orphan flag, and still performs content-conflict checks, dangling-event reconstruction, metadata comparison, and `missingContent` refresh. Once collection becomes complete or changes, store work restarts over the accumulated set; subsequent bounded calls advance its version and dangling-event cursor until no work remains. See that package's README for the seven-case classification.

W2/W3 narrowing: a `science/artifact-saved` append the Session refuses after the store row (or annotation) already committed marks that version `orphan` on `version_health` immediately, rather than waiting for the next reconciliation pass to discover it. `capture.ts`'s auto-capture walk already does this for its own append site (described above); `annotateArtifact`, `performChartEdit`'s human-edit commit, and `saveArtifactAs` share one `appendArtifactSavedOrMarkOrphan` helper that does the same at their own append sites.

`installPackages({ session, language, packages, signal })` requires a configured `micromambaPath`/`installChannels` pair (`ScienceRuntimeError('INSTALLER_NOT_CONFIGURED', …)` otherwise) and an applied environment for `language` with no run in flight (`ENVIRONMENT_NOT_READY`/`RUNTIME_BUSY`, mirroring `startRun`'s own orphan check). It runs a direct, unconfined `micromamba install --yes --no-rc --prefix <canonicalPrefix> --override-channels --channel <one URL> <packages>` under a `workspace-write` sandbox policy rooted at the prefix itself — the one confinement site in this Runtime that grants the prefix write access rather than requiring it read-only, since installing is the one operation whose entire purpose is writing into it — bounded by `installTimeoutMs` rather than the generic `timeoutMs`. This confinement is required to report at least the same configured `minimumEnforcement` as an interpreter probe or persistent kernel spawn (`ScienceRuntimeError('CONFINEMENT_UNAVAILABLE', …)` otherwise, naming both the reported and required level); a win32 desktop deployment that lowers `minimumEnforcement` to `'partial'` therefore also runs `installPackages` under partial enforcement, described under Confinement and environment below. Each configured channel URL is tried in turn as one complete, independent invocation; only a `'failed'` attempt tries the next URL, and no invocation is ever given more than one channel (a conda channel list means "search all," not "fall back," and mixing sources into one solve could pull packages from different mirrors into one inconsistent install). A micromamba process that exits `0` classifies as `'success'` even when the deadline separately fired first — a solve that finishes inside the bounded SIGTERM grace after `installTimeoutMs` elapsed already wrote its target environment, so `'timed-out'` is reserved for a process that did not complete successfully. On success, and only on success, the Runtime re-observes the whole profile exactly as `bindEnvironment` does; a re-observation that differs from the session's current binding for either language appends a fresh whole-value `science/environment-bound` revision — an `invalid` revision if re-observation finds a capability failure, `applied` otherwise — while a re-observation that matches the current binding and its package inventory exactly (every requested package was already present) appends none and returns the existing environment with `environmentChanged: false`, so a redundant retry never advances the revision or restarts a kernel for no environment change. This call never itself restarts a kernel: an appended revision takes effect only on that language's next `startRun`, which finds the revision mismatch and ends the stale kernel (`environment-rebound`, described above) before starting a fresh one, so a caller must expect in-memory kernel state to be gone starting with that next run, not this one. A failed, cancelled, or timed-out install returns that classification with bounded output tails and appends no environment revision, leaving the durable projection and every live kernel exactly as they were. Another session bound to the same shared profile never sees this call's appended revision directly, but that session's own next `startRun` now catches the resulting prefix drift on its own and re-binds itself (see startRun's own drift-detection paragraph above).

The Runtime rejects pre-publication misuse or capability failures with `ScienceRuntimeError`. After a start event commits, the kernel's `ok`/`error`/`interrupted` reply, an uncommanded kernel death, cancellation, or timeout each append one matching terminal event, classified per the interrupt semantics above (`success`; `failed` with `failureCode: 'EXECUTION_FAILED'` for a driver-reported error or `KERNEL_DIED` for an uncommanded kernel death; `timed-out`; or `cancelled`), immediately followed by the auto-capture walk above. `done` also rejects when a still-live Session cannot commit the terminal fact or an unexpected detached Session makes a commit forbidden.

When the store's current head for a logical name is a direct human edit (`content_origin: 'human-edit'`), auto-capture also ignores an unclaimed file whose bytes still match the latest run-produced ancestor in that artifact's full store history. This prevents a stale pre-edit file in the private artifact directory from reverting the human version during an unrelated later run. Naming that output path in `editBaselines` makes the write intentional, so a model edit or explicit revert still commits normally. Human-edited versions themselves remain valid `artifactInputs` and `editBaselines` sources.

## Confinement and environment

Every probe, kernel spawn, and package install uses direct argv, an empty subprocess environment base, a fixed environment allowlist, owned cwd, and `workspace-write` confinement required to report at least the configured `minimumEnforcement` — the same confinement a one-shot process would need, held for the kernel's entire lifetime instead of freshly per run. `minimumEnforcement` defaults to `'full'`; a deployment lowers it to `'partial'` only where a supported sandbox backend cannot reach full enforcement, which today means win32's ACL restricted-token backend ([`dsh-sandbox-windows-acl`](../../sandbox/sandbox-windows-acl/README.md), "Verified boundaries") — accepting it does not widen what that backend actually enforces; Everyone-writable external objects and NTFS hard-link aliasing stay reachable exactly as that package documents. That same lowered minimum governs `installPackages` too: a win32 desktop deployment configuring `minimumEnforcement: 'partial'` accepts the ACL backend's write-target confinement for `micromamba install` on exactly the same terms it accepts it for a probe or a kernel. Whichever level a confinement call actually reports is recorded on the resulting environment binding as `sandboxEnforcement`, so provenance always shows what was accepted, never only what was required. `confineWithEnforcement` (`execution.ts`) is the one comparison point for probe and kernel-spawn confinement; `installPackages`' own `confineInstallArgv` (`install.ts`) cannot call it directly — installing must grant the target prefix write access, the opposite of what `confineWithEnforcement`'s own `assertPrefixReadOnly` requires — so it reuses the same `meetsMinimumEnforcement` comparison instead, and reports the identical `CONFINEMENT_UNAVAILABLE` message shape. The sandbox provider itself is never asked to relax anything at any of these sites — it keeps reporting the enforcement level it actually achieves. Python probes use `-I -B -X utf8` (isolated mode: a probe never installs anything). A Python kernel drops `-I`, keeping `-B -u -X utf8`, and runs the shipped `kernel_python.py` driver; its fixed environment allowlist adds `PYTHONUSERBASE=<kernel scratch dir>/pyuser`, created at spawn. Dropping isolated mode is what makes an inline `pip install` importable within the same kernel: under sandbox confinement the Conda prefix is read-only, so pip's install falls back to a user-site install, and `-I` would otherwise exclude user site-packages from `sys.path`; `PYTHONUSERBASE` gives that fallback a kernel-owned, writable target instead of the ambient default. R version discovery uses standalone `Rscript --version`; its UTF-8 probe uses `Rscript --vanilla --encoding=UTF-8`; an R kernel runs the shipped `kernel_r.R` driver under the same flags, with `R_LIBS_USER=<kernel scratch dir>/rlibs` added to its fixed environment allowlist and created at spawn — `install.packages()` only adds a directory to `.libPaths()` when it already exists, and only R_LIBS_USER, unlike a bare additional library path, is what a non-interactive `install.packages()` targets without further arguments. Python's package-inventory probe adds `-m pip list --format=json`, reporting what the interpreter itself sees; R's evaluates `installed.packages()` and prints `Package`/`Version` as TSV using only base R, since `jsonlite` is not guaranteed present. The Runtime refuses a Conda prefix that overlaps any writable root, and never grants the project directory as its workspace. On win32, the fixed environment allowlist additionally carries `SystemRoot`, `windir`, `SystemDrive`, `ComSpec`, `PATHEXT`, `TEMP`, `TMP`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `PROGRAMDATA`, `NUMBER_OF_PROCESSORS`, and `PROCESSOR_ARCHITECTURE`, carried through from the Host's own ambient environment: a win32 process started with none of them cannot initialize Winsock (`WinError 10106`), which the loopback TCP response channel and the interpreter's own standard library both depend on. `PATH` on win32 joins, in the order `conda activate` uses, `<prefix>`, `<prefix>\Library\mingw-w64\bin`, `<prefix>\Library\usr\bin`, `<prefix>\Library\bin`, `<prefix>\Scripts`, and `<prefix>\bin`, instead of POSIX's `<prefix>/bin:/usr/bin:/bin`.

Both `pyuser` and `rlibs` are scoped to their exact kernel instance, not the session or the environment: a fresh kernel — after an idle restart, a crash, an interrupt escalation, or an environment-rebound — gets a fresh, empty user-install base under its own kernel-epoch scratch directory, so an inline install never survives its kernel and never leaks into a later-bound environment revision.

Kernel execution runs on darwin, linux, and win32. The response-channel transport differs by platform (see above), and win32's cooperative-interrupt gap (`interrupt()` has no effect) means a cancelled or timed-out win32 run always loses its kernel's in-memory state where a POSIX run's kernel usually survives — see Known Limitations.

The private root is derived under `DSH_HOME/science/v1/` with an exclusive mode-0600 owner marker and mode-0700 directories, including a `kernels/` subtree holding each live kernel's own scratch (its response FIFO among it, on darwin and linux; win32 has no on-disk response-channel artifact — the loopback TCP listener and its one-time token exist only in Host process memory). On win32, Node's `lstat` mode bits on a directory or file are synthetic and never reflect a prior `chmod`, so privacy verification checks only directory/file/symlink kind there, not mode bits; the actual privacy guarantee comes from the user-profile ACL a Harness home inherits plus the ACL sandbox's own per-session SIDs (`dsh-sandbox-windows-acl`), not from POSIX permissions. Only the operation whose exclusive marker creation succeeds receives rollback ownership; a materialization failure removes that operation's exact marker and Session root after verifying the marker bytes, while concurrent or pre-existing ownership is retained. A live operation reserves the exact Session object; a same-ID successor remains quarantined until an older detached lifecycle proves all owned trees — including every kernel it owned — are quiescent. Accepted run directories remain for state and diagnostics, while unpublished probe directories are removed only after quiescence.

## Verification

Protocol fixtures run over TCP on every host and additionally over real FIFOs on POSIX. Portable ownership tests control subprocess exit evidence and filesystem failures without requiring native FIFO support; separate POSIX integration cases retain real FIFO and permission checks. Foreign-platform mode-policy tests supply recorded metadata rather than interpreting Windows synthetic mode bits as POSIX permissions.

Fake-prefix tests cover Python-only, R-only, shared and distinct prefixes; strict configuration, including the persistent-kernel idle and spawn-to-READY deadline bounds; stable and drifted observations; invalid UTF-8 probe bytes; package-inventory parsing, sorting, entry/byte-cap truncation, and probe-failure handling for both languages; scratch ownership; direct argv; empty environments; output bounds; terminal classifications; cancellation; timeout; detachment; same-ID quarantine; Loader composition; and live/cold replay. Kernel machinery has its own suites against a fake driver speaking the kernel wire protocol, composed through the real subprocess-local and sandbox-local providers: driver asset resolution for both source and built execution; kernel-process handshake, sequential runs, DONE routing, READY timeout, protocol garbage, uncommanded exit mid-run, interrupt-then-survive, interrupt-then-escalate, EXIT teardown, and response-channel cleanup; the loopback TCP transport has its own suite against a real `node:net` client (token acceptance; a wrong-token, premature-EOF, oversized-line, or erroring connection destroyed while the listener keeps accepting a later correctly-tokened one, including one queued before `connect()` was ever called; a pre-`connect()` listener fault observed immediately; a refused second connection once a valid one has landed; EOF classification; and listener teardown destroying any still-queued connection) plus a real-driver suite that forces the TCP transport (without mocking `process.platform`) and runs the shipped `kernel_python.py`/`kernel_r.R` through a full RUN/DONE/EXIT cycle against this machine's own bound or PATH-resolved interpreters, self-skipping per language when neither exists; and kernel-set epoch allocation and monotonicity across restarts, idle expiry and reset-on-activity, coexisting Python and R kernels, environment-rebound respawn, same-ID quarantine, and detach/dispose teardown. A dedicated auto-capture suite covers a new file, a changed file, an identical rerun (skipped), an oversized file, the per-run and per-session caps, dotfile/extension exclusion, capture on a failed run, a project artifact store write rejection, a non-fatal internal capture failure, independent same-named artifacts in separate sessions (distinct artifactIds, v1, and unchanged prior latest versions), and persistence across a Host restart. A dedicated test pins `bindingFingerprint` as independent of the package inventory: rebinding the same static identity with a different observed inventory changes `packagesSha256` but not `bindingFingerprint`. The lstat-only prefix manifest records relative path, type, symlink target, mode, size, mtime/ctime nanoseconds, and regular-file digest without using atime; an empty before/after diff is the prefix-unchanged result. `installPackages` has its own suite covering package-spec validation, argv construction (never more than one channel per invocation), the write-access confinement divergence, install-scratch lifecycle, and subprocess classification — including a zero-exit settlement that lands inside the deadline's SIGTERM grace classifying `'success'` rather than `'timed-out'` — plus orchestration coverage for every pre-publication rejection, single-channel success and failure, R-only re-observation, an invalid re-observed revision, scratch-cleanup-failure logging, whole-attempt channel fallback (a failed first channel trying the next, every channel failing, and a cancelled in-flight attempt trying no further channel), a successful install that actually changed the inventory appending a fresh revision, and a redundant successful install re-observing an identical inventory appending none and reporting `environmentChanged: false`. `installTimeoutMs`'s own config-resolution bound (default, min, max, and independence from `timeoutMs`'s own separate max) has dedicated coverage alongside the other resolved fields. `minimumEnforcement`'s config-resolution default and rejection of an invalid value, `confineWithEnforcement`'s full/partial acceptance matrix (including the `CONFINEMENT_UNAVAILABLE` message naming both the reported and required level), and a configured `'partial'` minimum accepting a `'partial'`-reporting sandbox end-to-end through `bindEnvironment` all have dedicated coverage; `KernelProcess.start`'s own confinement has the symmetric pair — a partial-reporting sandbox is rejected when the caller passes `minimumEnforcement: 'full'` and accepted when the caller passes `'partial'`. `KernelSet`'s own forwarding of its configured value into that parameter (the `acquire` spawn path and `startIsolated`) has dedicated coverage one layer up: each forwarding line has a dedicated test that fails when that line is missing. A further end-to-end case runs a real `startRun` kernel spawn against a `Config.minimumEnforcement: 'partial'` runtime and a partial-reporting sandbox, covering the same threading through `ScienceRuntime` itself, not only through a directly constructed `KernelSet`. `confineInstallArgv`'s own full/partial acceptance matrix has the same dedicated coverage, including the identical `CONFINEMENT_UNAVAILABLE` message shape; `installPackages`' own forwarding of `this.minimumEnforcement` into that call has an end-to-end pair one layer up — a configured `'partial'` minimum against a partial-reporting sandbox succeeds, and a sandbox reporting below the configured minimum rejects — the same forwarding-regression shape `KernelSet`'s own pair uses. A dedicated shared-prefix drift suite drives a real `startRun` through a real on-disk `conda-meta/history` mutation (not a manually appended durable event) for both Python and R: a drifted prefix re-binds and restarts the stale kernel; an unchanged prefix appends nothing and keeps the same kernel epoch; a drifted-and-now-unusable prefix rejects with `ENVIRONMENT_NOT_READY` and appends no revision, leaving the session able to run again once the prefix recovers; and history replaced with a directory routes through the same re-observe path rather than an unclassified exception.

## Known Limitations and Deferred Work

- **No environment management** — the Runtime consumes explicit existing prefixes; it does not discover, create, install into, update, repair, or delete Conda environments.
- **Existing local prefixes only** — observations are fingerprints, not reproducible-environment locks, and the Runtime never manages Conda packages or environments.
- **File-write confinement only** — full sandbox enforcement limits documented file writes but does not claim file-read, network, syscall, or scientific-validity isolation.
- **Host-local execution only** — a remote subprocess provider fails closed because this implementation owns private Host scratch. A sandbox reporting less than the configured `minimumEnforcement` (default `'full'`) also fails closed; a deployment accepts a `'partial'` backend only by explicitly configuring `minimumEnforcement: 'partial'`, and the actual accepted level is always recorded on the environment binding — see Confinement and environment above.
- **win32 interrupt loses kernel state** — `interrupt()` is a documented no-op on win32 (`dsh-subprocess-local`'s `spawn.ts`); there is no `CTRL_BREAK`-style escalation in this Runtime. A cancelled or timed-out win32 run therefore always falls through to `run-escalation`, ending the kernel and losing every variable the session had accumulated — the same outcome a POSIX kernel only reaches when it fails to reply to `SIGINT` within the grace window. Fixing this needs a distinct win32 cooperative-interrupt mechanism, deferred as v1 scope.
- **win32 kernel execution's real-hardware evidence is one manual verification, not a repeatable gate** — a real Windows Server 2022 run confirmed the loopback TCP transport, the win32 environment allowlist, and the `PATH` ordering end to end: `kernel-transport-real.spec.ts` runs both the shipped `kernel_python.py` and `kernel_r.R` through a full RUN/DONE/EXIT cycle against real Conda interpreters over a real TCP connection. R's `bindEnvironment` probe path is also confirmed on the same box, once `CHILD_LOCALES.win32` moved from `C.UTF-8` to `en_US.UTF-8` and the probe expressions moved from a literal non-ASCII argv to `\u`-escaped ASCII (see the [win32 locale and probe-argv Agent Note](https://github.com/SuperJJ007/papermachine/blob/44575f3bf0/.agents/notes/implemented/bug-fix/2026-09-06-win32-r-locale-and-ascii-probe-argv.md)): `bindEnvironment` reports R `capability: "available"`, a non-ASCII `startRun` round-trip (`cat(enc2utf8("dsh-科学-✓"))`) returned the exact expected UTF-8 bytes, and same-kernel state persistence (a value set in one run, read back correctly in a later run on the same `kernelEpoch`) held for both languages. Nothing in this repository's CI runs a real win32 kernel spawn.
- **The win32 loopback transport's per-kernel token is visible in the driver's own process argv** — a same-user process on the machine can read it (`Win32_Process.CommandLine`, `tasklist /v`), unlike a POSIX FIFO path, which names a filesystem object rather than a secret. This is accepted for v1: the listener on `127.0.0.1` stops accepting only once a connection presents the correct token, so the token defends against a stray or malicious *other* connection racing to connect first, not against a same-user process that could open the same loopback port directly anyway — the security boundary this Runtime actually holds is the operating system's own same-user trust boundary around the Host process, not the token's secrecy.
- **R output capture is sink-level only** — `sink()` attributes R-level `print`/`cat`/`message` output to the correct run, but C-level or child-process writes bypass it and land in the kernel's own long-lived, bounded stdout/stderr collectors instead, never attributed back to any run. `outputDegraded: true` on a run's terminal marks when the driver detected it could not fully restore or attribute that run's capture. Fd-level capture, matching Python's `os.dup2` redirection, is future work.
- **No reconciliation of a kernel's real process state across a Host crash** — replay derives `ScienceKernelInterrupted` for any kernel still `started` at `session/end-seed`, so the durable log and the model are always told a kernel from before a Host restart is not running; this Runtime does not additionally verify or reconcile what the language interpreter's real operating-system process actually did across that restart. A reconciliation pass is future work.
- **`installPackages` has no pre-flight size or disk-space check, and no sticky channel memory** — unlike the desktop provisioning track's `estimatedDownloadBytes`/`requiredFreeBytes` and per-source health metadata, this Runtime only classifies the completed micromamba invocation after the fact. A deployment whose first configured channel is currently unreachable pays that failed attempt's latency on every single call, since nothing remembers which channel last succeeded and each call retries `installChannels` from its first entry.
- **`kernel_python.py` must keep adding its own user site-packages directory to `sys.path` at startup** — Python's `site` module normally does this once, at interpreter startup, and only if the directory already exists at that instant; the nested `PYTHONUSERBASE/lib/pythonX.Y/site-packages` leaf pip actually installs into does not exist until a kernel's first inline install creates it, too late for that scan. The driver works around this with one `site.addsitedir(site.getusersitepackages())` call at its own startup (after `os.makedirs`), which is what actually makes an inline `pip install` importable within the same kernel — removing it would silently reopen this defect without changing any flag or environment variable.
- **A truncated package inventory cannot be replayed into an environment** — the digest still covers the complete inventory, so truncation is detectable, but a capped retained list is name/version pairs, not an installable specification. `bindingFingerprint` never folds in the package digest, so raising or lowering either cap does not change drift detection.
- **Prefix-drift detection covers conda transactions only, checked per run rather than per import** — `startRun`'s digest comparison (described above) reads `conda-meta/history`, so it catches a package `install_science_packages`/micromamba wrote to the shared prefix, but not a package a user installed into that same prefix by hand outside the product (a raw `pip install` writes `site-packages` directly, never `conda-meta/history`). This product's own pip / `install.packages()` paths never touch the shared prefix either way: an inline kernel install lands in that kernel's private `PYTHONUSERBASE`/`R_LIBS_USER`, not the shared prefix, so it was never a source of this gap. Detection also runs once per `startRun` call, not on every kernel-level import inside a run: a shared-prefix mutation mid-run is caught by that run's own next `startRun`, not the run in progress.
- **A crash between a run's terminal commit and its auto-capture walk leaves that run's files uncaptured** — with no automatic retry. This mirrors the existing pre-/post-`science/run-started` scratch-cleanup asymmetry and is accepted for v1; a future retention or reconciliation pass is the seam that would close it.
- **An auto-capture failure during the walk (not before it) also has no automatic retry** — an environmental fault (the artifact directory disappeared, a permission or disk error) or a defect in this Runtime's own capture logic both stop that run's walk with no run failure; the run's own terminal fact and result stand, and the failure is logged (`warn` for the environmental class, `error` for anything else) rather than silently absorbed, but the remaining eligible files in that run stay uncaptured until a future retention or reconciliation pass closes this gap the same way as the crash case above.
- **`editBaselines` stays resolved against this session's own live projection only** — unlike `artifactInputs` above, naming a version another session in the same project produced as an edit baseline still rejects with `ARTIFACT_NOT_FOUND`. Lifting this needs `dsh-science-session`'s strict fold to also accept an unresolved cross-session `parent` reference on replay, which requires a separate lineage decision.
- **R composite and base graphics are raster-only** — only one complete ggplot on a PNG device is addressable; viewport composition, multiple plots, and base `plot()` retain region editing.
- **Repeated saves retain only terminal state** — multiple matplotlib or ggplot2 saves to the same path during one run leave only the final exported snapshot and settings registered for extraction.
- **Uncopyable custom figures remain ordinary PNGs** — a snapshot failure preserves the successful save but makes the image unavailable for direct editing. Cold recovery still requires reproducible source inputs and plotting dependencies; runtime objects are not persisted.
