# @deepseek-ai/dsh-science-session

English | [中文](README.zh.md)

The Science Session domain: durable required-on-read Session events, strict deterministic Host replay, a pre-commit invariant, and the optional client-safe `science` Session projection. This package exposes no mutation service, starts no process, observes no interpreter, registers no model-facing tool or prompt, and renders no client UI. The owning project's artifact store (`@deepseek-ai/dsh-science-artifact-store`) is the sole authority for an artifact version's provenance — content origin, producer, base version, and creation time all live there only; this package's own `science/artifact-saved` durable event carries only the store's version reference plus the title/caption presentation the model or user saw when the event committed. `@deepseek-ai/dsh-science-runtime` appends environment, run, and artifact events; `@deepseek-ai/dsh-tool-science` binds mode and publishes Outcomes.

## Durable vocabulary

Seven `science/*` Session events, each `version: 1`, lossless JSON, carrying a complete domain value rather than a patch, and required on read (never `ignorable`): `science/mode-bound`, `science/environment-bound`, `science/run-started`, `science/run-finished`, `science/artifact-saved`, `science/outcome-published`, `science/kernel-state`. `science/mode-bound` is legal once, only for a Session whose resolved agent preset (creation header, overridden by the last `agent-preset/selected` event — the same resolution `@deepseek-ai/dsh-agent-presets`' `resolveSessionPreset` uses) is `science`, and before the first Science-preset `step/start`, `request/header`, or `tool/call` fact. `science/artifact-saved` carries an artifact version's store reference (`artifactId`, `versionId`, `version`, `projectId`, `sha256`) and a presentation snapshot (`title`, an optional `caption`) — nothing else: content origin, producer identity, base version, and creation time are the owning project store's facts alone, never duplicated onto this event. `sha256` pins the exact bytes the model or user saw independent of trusting the store; `title`/`caption` are the value displayed when this event committed, not necessarily the store's current value after a later metadata edit. `seenAt` is this event's own commit time — when this presentation was seen, distinct from the store's own content-commit timestamp. `logicalName` is a forward-slash path (each segment the same safe grammar as every other durable id), kept because it appears in model requests (tool receipts, `get_science_state`); no other field does. Outcomes retain non-empty references to prior successful runs, exact artifact versions, and/or message facts. `science/kernel-state` is a whole-value fact for one persistent kernel's lifecycle transition, reusing the same shape for both directions instead of a started/terminal event pair: `state: 'started'` opens a kernel instance identified by its `language` and `kernelEpoch` (session-local, strictly monotonic across both languages); a later `state: 'exited'` fact for the same `language`/`kernelEpoch` closes it and carries a closed-union `reason` and a `startedAt` (the closed kernel's own `started` fact `at`, keeping its lifetime whole-value in the closing fact), both present if and only if `state === 'exited'`. At most one kernel per language may be open (started, not yet exited) at a time. `science/run-started`/`science/run-finished` fix a run's `kernelEpoch`, the persistent kernel instance that executed it, so two runs sharing an epoch prove they shared in-memory state. They may also repeat a start-owned `inputs` array whose entries pin an exact previously committed artifact version and its unique canonical path below the run's reserved `inputs/` directory. Omission preserves replay of events written before this field existed; an empty array records that a producer supplied no artifact version. `science/run-finished` optionally carries `outputDegraded: true` when the kernel driver could not fully attribute this run's captured output.

A log written before this event was slimmed still replays: the decoder is deliberately not strict about `science/artifact-saved`'s payload, so it silently drops any field it no longer declares (`producerSessionId`, `runId`, `toolCallId`, `requestHeaderSeq`, `environmentRevision`, `environmentFingerprint`, `parent`, `origin`, `byteCount`, `mediaType`, `chart`, `createdAt`), and falls back to the legacy `createdAt` field for `seenAt` when a value has no `seenAt` of its own. This is a read-compatibility fallback, not a promise the two fields mean the same thing; see [the slimming Agent Note](../../../.agents/notes/implemented/architecture/2026-09-02-science-artifact-event-slimming.md) for why this did not need a `SESSION_FORMAT_VERSION` bump.

## Strict fold and invariant

`replayScience(events)` deterministically replays a complete contiguous log into the complete Host-side `ScienceProjection`, or `null` before a valid mode binding. A caller that appends many Science events in one pass (`@deepseek-ai/dsh-science-runtime`'s auto-capture walk, for example) advances the same fold incrementally instead of re-replaying the complete log on every append: `foldScience(events)` once for the accumulator, `applyScienceEvent(state, event)` per newly appended event (the event's `seq` must equal the accumulator's own next expected sequence), and `projectScienceFold(state)` on demand for the public value — the exact three-step composition `replayScience` itself runs in one shot. The fold rejects discontinuous sequences, malformed values, invalid transitions, forward provenance (a `requestHeaderSeq`/`toolCallId` must identify the required prior committed fact in this session's own log), reused or settled tool calls, non-monotonic revisions or times, and foreign evidence. A run input is the one reference this rule does not fully apply to: it must exactly match a prior committed fact only when its version is at or below this session's own locally-recorded maximum for the same artifactId; a version strictly ahead of that local maximum (including when this session's log has never recorded the artifactId at all) is accepted untraced, trusting the live Runtime's pre-commit validation against the artifact's owning project store (a second session in the same project reading or interleaving writes against a first session's artifact — see Known Limitations).

`science/artifact-saved` folds under the store-is-authority rule: since content origin, producer, base version, and creation time live only in the owning project's artifact store, this fold neither re-derives nor cross-checks any of them — every check that once did moved to the store write transaction that commits before this event does (the complete list and each check's new home are in [the slimming Agent Note](../../../.agents/notes/implemented/architecture/2026-09-02-science-artifact-event-slimming.md)). What this fold still enforces from the log alone: one session's artifacts share one `projectId`; a `versionId` cannot back two committed versions in this session; `version` must exceed this session's own locally-known maximum for that `artifactId`, or equal an already-recorded one; and `sha256` distinguishes a content event from a metadata-only re-record — identical to the target's `sha256` (and `versionId`) replaces that entry in place (its `title`/`caption` snapshot advances; content stays pinned), a different `sha256` at an already-recorded ordinal is rejected, since a genuine new version always opens a fresh ordinal instead. The fold applies no content-hash dedup of its own; a caller that wants to skip an unchanged file compares content hashes itself before appending. Both an opened version and a re-record stay in the durable log — only the projected version list collapses on a re-record — and the version's retained fact follows the later event, so evidence cited against a version is dated by whichever save produced what it currently holds.

A kernel-state fact adds its own pre-commit rules to the same fold: its `kernelEpoch` must strictly exceed every epoch the session has already admitted; a `started` fact is rejected while its language already has an open kernel, and must name the session's latest applied environment revision with a fingerprint matching that revision's own available binding for its language — the same relation `science/run-started` asserts, deliberately not required of the `exited` direction, whose revision is pinned instead by the identity match below; an `exited` fact is rejected unless it names its language's currently open epoch exactly, repeats that fact's own `environmentRevision`/`environmentFingerprint` unchanged, and carries `startedAt` equal to the started fact's `at`. Every kernel-state fact's own `at` must not exceed its committing event's time, and an `exited` fact's `at` cannot precede its started fact's `at`. A `science/run-started` fact's `kernelEpoch` must name a currently open kernel for the run's own language whose `environmentRevision`/`environmentFingerprint` match the run's own — no run may name a kernel that was never started or has already exited. An applied environment revision may supersede an earlier one after runs already exist (the provisioning track's environment-rebound path), rejected only while a run is still `running`. `science/outcome-published`'s `environmentRevisions` are used by cited run evidence only — chart evidence never contributes one, since an artifact version's environment provenance is no longer on the event. `session/end-seed` alone derives `interrupted` for an unmatched running run or an unmatched open kernel; no synthetic Science terminal event is appended. The package-owned invariant (`./invariant`) applies the same applicability rule and strict fold before every commit, so a rejected candidate appends nothing to the durable log.

## Projection

Registers the optional `science` key on `ctx.sessionProjections` only when that registry is composed (`ctx.inject(['sessionProjections'], …)`); a host without the registry, or a Standard (non-Science) session, never carries the key. The public `ScienceClientProjection` keeps mode, path-free environment capability/version/package-inventory summaries, run status/history with exact artifact inputs when recorded, kernel lifecycle history, artifact version references with their presentation snapshot, the latest Outcome, metrics, and a browser-safe trajectory index. The index records every post-binding `tool/call` identity with its turn and step plus every turn lifetime, independently of the paged conversation projection. Run entries repeat their authorizing call's turn and step; a newly committed artifact version takes the currently open run or annotation call's coordinates as its trace anchor, and a later metadata-only re-record of that same version keeps those original producing-call coordinates rather than moving to whichever call is open when the re-record happens. These Session-log coordinates let a cold client restore the complete process timeline while loaded conversation nodes supply only optional request text, arguments, and results. A kernel record carries the same `language`/`kernelEpoch`/`state` fields as its durable `ScienceKernelState`/`ScienceKernelInterrupted` counterpart — both arms share the `state` discriminant (`'started' | 'exited' | 'interrupted'`), so a reader switches on one tag — including an exited or interrupted fact's `startedAt`, with the full environment fingerprint reduced to the same twelve-character preview runs use; it carries no Host path, so no other field needs redaction. A run record also retains its `kernelEpoch`, its authorizing `toolCallId` and `requestHeaderSeq`, and, when present, `outputDegraded`. A run record also retains its whole `codeSha256`, unlike the environment fingerprint: it is a digest over source text the same transcript call already restates verbatim once resolved, so it carries no Host-infrastructure fact, and provenance needs the durable anchor exact rather than previewed. It omits configured/canonical prefixes, executable paths and identity, full environment and package-inventory fingerprints (twelve-character previews only), source/scratch facts, and free-text Runtime failures. The persisted private state is plain JSON at `stateVersion: 18`: an observed-event watermark, the encoded strict fold, and a sparse redacted witness. `checkpointStateSchema` admits a persisted row only when replaying its witness reproduces the encoded fold and the row's outer `seq`; `checkpointStateSeq` binds every state to that same watermark so a valid-but-stale state can never be spliced under a newer one; `viewChanged` publishes Science facts and trajectory-index changes while ignoring supporting events that change neither.

An artifact version's client projection carries its durable event fields plus optional projection-derived turn and step coordinates. It carries no producer identity, run id, tool-call id, base-version, environment fields, or `projectId`; provenance and addressable chart-edit state remain the owning project artifact store's facts. A version whose commit found no open run or annotation call has no coordinates and remains explicitly unassigned unless its store content origin proves it was a direct edit or import, which the UI places by store creation time. The independent `scienceArtifactNotes` projection folds ignorable user-only add/remove events by store `ScienceArtifactId`; it is durable UI state and never contributes a model message.

## Session attachment registry

This package registers no extractor with `ctx.sessionAttachments`: `science/artifact-saved` is classified `attachment-free` in `dsh-session-attachment-index`'s static policy table, since the event carries no session-scoped attachment reference at all. Session export therefore never collects Science artifact bytes from the session log; the owning project's artifact store is the sole byte authority, and it outlives session deletion.

## Model Experience

None, as this package validates and projects already-logged Session facts and touches no prompt, message, schema, stream, or tool result; the Science tool Consumer is a separate package.

#### KV Cache effect

None; this package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- **The sparse projection witness retains provenance, not a bounded window.** It grows with retained Science facts; no constant-time or bounded-history claim is made, matching the accepted trade-off in the generic `session-projection` registry's own checkpoint contract.
- **Run inputs beyond this session's own locally-recorded maximum are trusted untraced; artifact provenance is not this package's concern at all.** A run input naming a version strictly ahead of this session's own locally-recorded maximum for an artifactId is accepted without a local match — the live `dsh-science-runtime` already validated it against the owning project's artifact store before the referencing event committed, and pure replay trusts that already-validated fact rather than re-deriving it. This covers both an artifactId this session's fold has never recorded at all (a second session in the same project reading a first session's artifact) and one it has recorded only up to a lower version (two sessions interleaving writes against the same artifact, where a concurrent session's own append may hold an intermediate ordinal this session never locally observed). A version at or below that local maximum which does not exactly match a local record is still rejected — the log alone can catch that same-session inconsistency. Base-version lineage (edit baselines, direct-edit ancestry) is no longer a fold concern at any range: `baseVersionId`/`baseExplicit` are declared facts the owning project artifact store's write transaction fixes once, resolved and validated there, never re-derived or cross-checked from this session's own log.
- **No settings or current-state Details UI.** `@deepseek-ai/dsh-client-ui-science` renders chart and Outcome transcript occurrences; settings and a current-state Details entry remain later product work.
