# @deepseek-ai/dsh-science-session

English | [中文](README.zh.md)

The Science Session domain: durable required-on-read Session events, strict deterministic Host replay, a pre-commit invariant, the optional client-safe `science` Session projection, and the `science/artifact-saved` attachment extractor. This package exposes no mutation service, starts no process, observes no interpreter, registers no model-facing tool or prompt, and renders no client UI. `@deepseek-ai/dsh-science-runtime` appends environment, run, and artifact events; `@deepseek-ai/dsh-tool-science` binds mode and publishes Outcomes.

## Durable vocabulary

Seven `science/*` Session events, each `version: 1`, lossless JSON, carrying a complete domain value rather than a patch, and required on read (never `ignorable`): `science/mode-bound`, `science/environment-bound`, `science/run-started`, `science/run-finished`, `science/artifact-saved`, `science/outcome-published`, `science/kernel-state`. `science/mode-bound` is legal once, only for a Session whose resolved agent preset (creation header, overridden by the last `agent-preset/selected` event — the same resolution `@deepseek-ai/dsh-agent-presets`' `resolveSessionPreset` uses) is `science`, and before the first Science-preset `step/start`, `request/header`, or `tool/call` fact. `science/artifact-saved` generalizes the durable model beyond charts: an artifact version carries an always-populated `title`, an optional `caption`, an `origin` of `'auto'` (unattended capture) or `'model'` (curated), and its complete `ImageAttachmentRef | TextAttachmentRef`; `logicalName` is a forward-slash path (each segment the same safe grammar as every other durable id) so a captured file's path relative to its run's artifact directory is a legal logical name directly. It may reference any run that reached a terminal status — success, failed, timed-out, or cancelled — not only a successful one, since a failed run's partial output is still eligible for capture. Its optional `parent: { artifactId, version }` names the exact previously committed baseline from which its content descends; self-reference and missing versions are invalid, and a superseding save must retain the version's existing parent. Outcomes retain non-empty references to prior successful runs, exact artifact versions, and/or message facts. `science/kernel-state` is a whole-value fact for one persistent kernel's lifecycle transition, reusing the same shape for both directions instead of a started/terminal event pair: `state: 'started'` opens a kernel instance identified by its `language` and `kernelEpoch` (session-local, strictly monotonic across both languages); a later `state: 'exited'` fact for the same `language`/`kernelEpoch` closes it and carries a closed-union `reason` and a `startedAt` (the closed kernel's own `started` fact `at`, keeping its lifetime whole-value in the closing fact), both present if and only if `state === 'exited'`. At most one kernel per language may be open (started, not yet exited) at a time. `science/run-started`/`science/run-finished` fix a run's `kernelEpoch`, the persistent kernel instance that executed it, so two runs sharing an epoch prove they shared in-memory state. They may also repeat a start-owned `inputs` array whose entries pin an exact previously committed artifact version and its unique canonical path below the run's reserved `inputs/` directory. Omission preserves replay of events written before this field existed; an empty array records that a producer supplied no artifact version. `science/run-finished` optionally carries `outputDegraded: true` when the kernel driver could not fully attribute this run's captured output.

### Direct human-edit versions

In addition to the two run-produced origins above, `origin: 'human-edit'` is a third strict branch rather than a run with missing fields. It requires an exact parent and a Vega-Lite text attachment, copies the parent's environment revision and fingerprint, and carries no `runId`, `toolCallId`, or `requestHeaderSeq`. The fold admits it only as the next contiguous version of the same artifact over that artifact's current committed Vega-Lite parent, after the parent fact and before its own save event; it cannot open version 1 or supersede a version in place.

## Strict fold and invariant

`replayScience(events)` deterministically replays a complete contiguous log into the complete Host-side `ScienceProjection`, or `null` before a valid mode binding. A caller that appends many Science events in one pass (`@deepseek-ai/dsh-science-runtime`'s auto-capture walk, for example) advances the same fold incrementally instead of re-replaying the complete log on every append: `foldScience(events)` once for the accumulator, `applyScienceEvent(state, event)` per newly appended event (the event's `seq` must equal the accumulator's own next expected sequence), and `projectScienceFold(state)` on demand for the public value — the exact three-step composition `replayScience` itself runs in one shot. The fold rejects discontinuous sequences, malformed values, invalid transitions, forward provenance (a `requestHeaderSeq`/`toolCallId`, artifact parent, or run input must identify the required prior committed fact), reused or settled tool calls, non-monotonic revisions or times, and foreign evidence. A version is the content one request turn produced, so a re-save either opens the next contiguous version or supersedes an existing one in place. An `origin: 'auto'` save may supersede changed bytes only when its source run shares the target version's `tool/call.turn`; an `origin: 'model'` curation must repeat the target's `attachment` byte-for-byte. Either origin may supersede an unchanged attachment in any turn. `requestHeaderSeq` remains authorization and provenance, not version identity: one request header can authorize calls in different turns. An auto save that changes content in a new turn must open the next version; reusing a version number there is rejected. Both saves stay in the durable log — only the projected version list collapses — and the version's retained fact follows the superseding event, so evidence cited against a version is dated by the save that produced what it holds. The fold applies no content-hash dedup of its own; a caller that wants to skip an unchanged file compares content hashes itself before appending. An `origin: 'auto'` artifact version's `toolCallId`/`requestHeaderSeq` must equal its source run's own (already proven when that run started), since unattended capture is not a distinct model-issued call and never re-consumes one — many files captured from one run share that run's call. An `origin: 'model'` version consumes a fresh, distinct tool call exactly once, as `annotate_artifact` always has. A kernel-state fact adds its own pre-commit rules to the same fold: its `kernelEpoch` must strictly exceed every epoch the session has already admitted; a `started` fact is rejected while its language already has an open kernel, and must name the session's latest applied environment revision with a fingerprint matching that revision's own available binding for its language — the same relation `science/run-started` asserts, deliberately not required of the `exited` direction, whose revision is pinned instead by the identity match below; an `exited` fact is rejected unless it names its language's currently open epoch exactly, repeats that fact's own `environmentRevision`/`environmentFingerprint` unchanged, and carries `startedAt` equal to the started fact's `at`. Every kernel-state fact's own `at` must not exceed its committing event's time, and an `exited` fact's `at` cannot precede its started fact's `at`. A `science/run-started` fact's `kernelEpoch` must name a currently open kernel for the run's own language whose `environmentRevision`/`environmentFingerprint` match the run's own — no run may name a kernel that was never started or has already exited. An applied environment revision may supersede an earlier one after runs already exist (the provisioning track's environment-rebound path), rejected only while a run is still `running`. `session/end-seed` alone derives `interrupted` for an unmatched running run or an unmatched open kernel; no synthetic Science terminal event is appended. The package-owned invariant (`./invariant`) applies the same applicability rule and strict fold before every commit, so a rejected candidate appends nothing to the durable log.

## Projection

Registers the optional `science` key on `ctx.sessionProjections` only when that registry is composed (`ctx.inject(['sessionProjections'], …)`); a host without the registry, or a Standard (non-Science) session, never carries the key. The public `ScienceClientProjection` keeps mode, path-free environment capability/version/package-inventory summaries, run status/history with exact artifact inputs when recorded, kernel lifecycle history, artifact attachment references and optional parent identities, the latest Outcome, and metrics (including `kernelCount`, the number of kernel instances ever started). A kernel record carries the same `language`/`kernelEpoch`/`state` fields as its durable `ScienceKernelState`/`ScienceKernelInterrupted` counterpart — both arms share the `state` discriminant (`'started' | 'exited' | 'interrupted'`), so a reader switches on one tag — including an exited or interrupted fact's `startedAt`, with the full environment fingerprint reduced to the same twelve-character preview runs and artifacts use; it carries no Host path, so no other field needs redaction. A run record also retains its `kernelEpoch` and, when present, `outputDegraded`. Run and artifact records retain their authorizing `toolCallId` and `requestHeaderSeq` — session-log identities the browser already holds — so the client can join a run or artifact version to its transcript tool call with no additional Host route. A run record also retains its whole `codeSha256`, unlike the environment fingerprint: it is a digest over source text the same transcript call already restates verbatim once resolved, so it carries no Host-infrastructure fact, and provenance needs the durable anchor exact rather than previewed. It omits configured/canonical prefixes, executable paths and identity, full environment and package-inventory fingerprints (twelve-character previews only), source/scratch facts, and free-text Runtime failures. The persisted private state is plain JSON at `stateVersion: 9`: an observed-event watermark, the encoded strict fold, and a sparse redacted witness. `checkpointStateSchema` admits a persisted row only when replaying its witness reproduces the encoded fold and the row's outer `seq`; `checkpointStateSeq` binds every state to that same watermark so a valid-but-stale state can never be spliced under a newer one; `viewChanged` narrows public-change notification to transitions that actually moved `lastScienceEventSeq`, since supporting events can advance the private watermark without changing the public value.

Run-produced artifact projections retain their authorizing run, tool-call, and request-header identities. A projected human-edit version instead retains its exact parent and direct-edit origin with no synthetic run link; every exact artifact version remains eligible as run input, edit parent, and Outcome chart evidence.

## Attachment authorization

When `ctx.sessionAttachments` is composed, this package registers the sole extractor for `science/artifact-saved`. It strictly decodes the event and returns its complete artifact attachment reference. A missing owner or malformed event fails authorization and Session export instead of authorizing an empty set.

## Model Experience

None, as this package validates and projects already-logged Session facts and touches no prompt, message, schema, stream, or tool result; the Science tool Consumer is a separate package.

#### KV Cache effect

None; this package never assembles or sends provider requests.

## Known Limitations and Deferred Work

- **The sparse projection witness retains provenance, not a bounded window.** It grows with retained Science facts; no constant-time or bounded-history claim is made, matching the accepted trade-off in the generic `session-projection` registry's own checkpoint contract.
- **The Runtime does not yet materialize artifact inputs.** `ScienceRuntime.startRun` does not emit the optional `inputs` field; this package validates and projects non-empty input facts from a conforming producer, but it neither reads attachment bytes nor writes the reserved `inputs/` directory.
- **No settings or current-state Details UI.** `@deepseek-ai/dsh-client-ui-science` renders chart and Outcome transcript occurrences; settings and a current-state Details entry remain later product work.
